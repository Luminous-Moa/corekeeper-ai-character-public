# 채팅 약절반 크기 표시 조사

2026-11-06. 사용자 최신 요구는 ‘채팅창 글자’를 더 작게 하는 것이다. 패널 가독성25db8ed는 유지하며, 사용자가 게임을 직접 조작하는 동안 설치·입력·종료·Unity를 하지 않는다.

## 판단

가능한 경로가 있다. 권장은 **기본 ChatWindow/PugText를 그대로 사용하고, 그들이 만든 글리프의 최종 표시만 실화면 해상도로 옮기는 것**이다. 채팅 입력기·메시지 큐·AI 발언 경로·알림·Tab·IME·fade를 새로 만들지 않는다. 목표 초기값은 원래 채팅의 약0.5배이며, 화면 픽셀 정수배와 한글 획 보존 때문에 해상도에 따라 정확한0.500 대신 가까운 선명한 크기를 택한다.

처음 참고한12px→동봉10px 로그는 FontKorean이 아니라 Font8B의 첫 라틴/시스템 줄이었다. 따라서 한글이 정확히17% 축소됐다고 확정할 근거가 아니며 이 해석을 정정한다. 사용자가 본 채팅이 여전히 크다는 실제 보고를 기준으로 한다. 같은 저해상도 UI 렌더 경로에서 transform0.7만 다시 적용하거나 한글 비트맵을5~6px로 강제로 줄이는 것은 추천하지 않는다. 전자는 이미 픽셀 격자/획 손실 실패가 있었고, 후자는 복잡한 받침을 표현할 정보 자체가 줄어든다.

## 실제 코드 근거

- `PugText.Render(bool,bool)`는 문자열/서식·언어·욕설 필터를 처리하고 `OnProfanityChecked`에서 `PugFont.Render`를 호출한다. `PugText.glyphs`에는 **이미 처리된** SpriteRenderer가 있고 실제 sprite,transform,color,maskInteraction을 읽을 수 있다. 이 결과를 쓰면 원문을 다시 파싱해 색 태그·아이콘·알림을 누락시키는 별도 채팅 구현을 피할 수 있다.
- `PugFont.Render`는 pixelsPerUnit과 charDims/lineSpacing으로 줄바꿈·글리프 위치·dimensions를 계산한다. `ChatWindow.AddPugText`는 `text.dimensions.height`를 `AddMessageHeight`에 넘겨 기존 줄을 밀고 큐/높이 한도를 유지한다. **표시만 작게 그리면 기존 빈 줄높이가 남으므로 메트릭도 함께 맞춰야 한다.**
- `PugText.ManagedLateUpdate`의 effects와 `PugTextEffectMaxFade.PugTextEffectLateUpdate`는 원본 글리프 색/alpha를 갱신한다. 기존 `AIChatWindow`는 fadeEffects 큐의 곡선만 조절한다. 최종 글리프 색을 읽으면 기존7초 선명→1초 소멸/입력시 재표시 흐름을 그대로 따른다.
- `ChatWindow.SetInputText/AppendString`, `MenuManager`의 IME 버퍼, `AIChatHint`의 Tab완성은 기존 입력 PugText를 사용한다. 표시층 변경이 이 API를 대체할 필요는 없다.
- `PugText.Clear`는 glyphPool에 렌더러를 반환하고, `OnDisable`도 freeResourcesOnDisable일 때 반환 대기 목록으로 넘긴다. 글리프의 원본 표시를 잠깐 감추려면 **풀 반환 전에 반드시 복원**해야 다른 게임 UI 글자가 사라지지 않는다.
- `ChatWindow`에 inputMask/outputMask가 있고 글리프마다 maskInteraction이 다르다. 새 화면 표시층이 마스크를 무시하면 채팅창 밖 문자/입력 긴 문자열이 새어 나오므로 동일 클리핑을 적용해야 한다.
- UI 카메라는 `CameraManager.uiCamera`와 별도의 PugCamera를 쓴다. 과거 실게임2는2800×1752에서 N측정이 정수±0.02 조건에 들지 않아 실제 줄배율1에 머물렀다. 카메라 내부 렌더픽셀을 곧바로 실제 창 픽셀로 간주하면 안 된다. 정규화 viewport 좌표를 실제 Screen 해상도로 옮기는 대응을 실제 화면과 검증해야 한다.

## 후보 비교

| 경로 | 판단 |
|---|---|
| 동봉10px를5~6px로 추가 축소 | 한글 획/받침 손실이 커서 제외 |
| 원본 저해상도 카메라에서 transform0.5/0.7만 적용 | 과거 실패 반복 가능, 단독 해법에서 제외 |
| 채팅문장을 새 IMGUI 문자열 목록으로 재구성 | 색·아이콘·줄바꿈·알림·입력·fade를 복제해야 하므로 범위가 너무 큼 |
| 기존 PugText 글리프를 실화면 픽셀 표시층에서 그림 | 권장. 기존 동작을 이용하되 표시·메트릭·클리핑·풀 수명을 한정 수정 |
| 전역 UI 카메라/렌더파이프라인 해상도 변경 | 다른 게임 UI에 영향을 주므로 제외 |

## 최소 구현 경계

1. 현재 채팅/입력/프롬프트/AI멘션 힌트만 대상으로 제한한다. 다른 게임 PugText/폰트/UI 카메라는 바꾸지 않는다.
2. 표시용 글리프 비트맵의 원래 획은 유지한다. 목표 실화면 글자높이를 기존 원본의 약절반으로 정하고 가까운 정수 픽셀배율을 골라 같은 비율로 PugFont 메트릭과 생성 sprite의 ppu를 맞춘다. 줄높이·줄바꿈폭·입력 스크롤 계산을 기존 PugText가 수행하게 한다.
3. OnGUI의 실화면 표시층은 원본 glyph sprite/위치/색/alpha를 읽는다. 해당 채팅 glyph의 렌더만 일시 차단하고 같은 화면 위치에 픽셀 경계로 그린다. 별도 메시지 저장/수신/전송은 없다.
4. output/input 마스크의 실제 화면 경계를 반영하고, 프롬프트·힌트와 색/아이콘·외곽선을 보존한다. 동적 글꼴/지원하지 않는 마스크나 sprite 형식에서 조용히 글자를 누락시키지 말고 그 텍스트는 원래 표시로 되돌린다.
5. Clear/OnDisable/씬종료/실패에서 원래 렌더 플래그와 글꼴을 복구한다. glyph풀을 다른 UI에 다시 쓰더라도 차단 상태가 새지 않게 한다.

## 위험과 합격 기준

가장 큰 위험은 위치 대응과 마스크다. ‘폰트 숫자가 절반’ 로그만으로 성공 판정하지 않는다. 같은 해상도에서 원본대비 실제 글자높이/줄간격과 한 화면 줄수를 측정하고, ‘광/활/훟/힣’ 등 복잡한 한글·라틴/숫자·색 알림·아이콘을 확인한다. 긴 입력/IME 조합/멘션Tab/Enter·취소, 7초fade, 마스크 경계, 재입장, 다른 게임UI 글자 유지까지 실제 화면에서 봐야 한다. glyph 수에 비례한 표시 비용도 관측한다.

이것은 기술적으로 가능한 구현 제안이며 아직 성공한 실게임 결과가 아니다. HEAD가 기존 채팅 동작을 유지하는 표시층 기술 선택으로 진행을 허용했다. 사용자 직접 조작 종료와 점유 조율 전에는 설치/실게임 검증하지 않는다. 현재 패널25db8ed와 새 장비 표시 결함 조사 범위는 별도로 보존한다.
