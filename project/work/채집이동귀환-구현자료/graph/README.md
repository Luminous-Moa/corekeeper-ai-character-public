# 채집·이동·귀환 개발 그래프 준비

현재 상태는 [최종 반영](final.md)을 따른다. 아래 준비 기록은 당시의 staging 이력이다. 공식 소스7af8f91에 대한 코드층/제품 그래프 재생성과 사용자 “조명 시야는 후속으로 분리” 결정을 반영했으며, 조명 동일성은 해결로 승격하지 않는다.

현재는 구현 freeze 전 준비 단계다. 확정 합의를 기존 최상위 모드 목적에서 연결하는 기획 delta를 staging에 만들었다. 현재 정본과 제품 코드는 변경하지 않았으며 코드 추출·설치·게임·외부 모델 실행도 하지 않았다.

현재 coherent 후보 `e1cedcf9033f5ec72f43555a27b3f59a9b565db1`는 재검수 중이다. 최초 독립검수 R1에서 빛·어둠을 고려하지 않는 일반 시야가 발견됐으며 [원본 조사](../vision-authority-investigation.md)의 GPU/호스트렌더/ThinClient 경계에 따라 사용자 제품선택 대기다. 따라서 전체 구현 수용·사람 동일 시야 완료로 표시하지 않는다. R2~R7 보완도 독립 재검수 결과 이후에만 수용 근거를 연결한다.

## 입력과 경계

- 합의 원문: `work/2026-11/2026-11-07-채집이동귀환-확정합의.md`, 역할판단.md. 곁일은 판단모델에 위임하며 임의 한도를 추가하지 않는다.
- 현재 공식 소스 기준: `5cc5a43ff8df91634c04b44bac9f15f849bdb611`. 임의 수량·행동 제한 해제를 보존한다.
- 게임 행동 그래프는 개발 규칙 근거로 조회한다. 이 작업에서 해당 그래프나 런타임 known 공개 정책을 바꾸지 않는다.
- 기존 그래프 재생성 절차는 `work/2026-11/2026-11-07-제약해제/graph.md`를 따른다. 생성 JSON을 직접 편집하지 않는다.

## 기획 delta

P.execution/P.original-request → P.expedition → 직접/트리 선택, 곁일 위임, 묶음 실행, 귀환·누적량, 이동 의도, 방향 선행 질문, 막힘, 자동 상위보고를 연결한다. 기존 P.unrestricted-work, P.valid-action, P.field-choice와의 관계를 이어 쓴다. 개발용 게임 그래프는 참고 노드로만 연결하며 합의나 런타임 실행 성공의 권위로 승격하지 않는다.

`prepare.mjs`는 기존 기획 선언을 읽고 합의 delta·기존/신규 근거 고정 사본·정본 입력 해시를 이 폴더 안에만 저장한다. `planning/graph.mjs build/check`는 staging 기획 산출만 만든다. 정본 적용이나 전체 Roslyn 추출은 하지 않는다.

## freeze 뒤 이어갈 순서

1. HEAD가 독립검수 수용 코드의 정확 커밋과 경로를 전달한다. 구현자의 graph-handoff.md에서 실제 코드 앵커·게임 그래프 조회·시험 근거·미실게임 경계를 확인한다.
2. 새 기능/정책과 코드 대응을 기존 원본에 추가할 delta를 구성한다. 현재 정본 입력이 준비 시점과 달라졌으면 최신 상태에 rebase한다.
3. HEAD의 반영 지시 후 기존 고정 snapshot/runtime-package pin → Roslyn/Acorn 코드층 → 기획·기존 근거 → C/실화면 대응 → 제품 그래프 순서로 갱신한다. 과거 화면·실게임 증거를 새 코드판의 성공으로 승계하지 않는다.
4. 원본/앵커/참조·실제 대표 조회·결정성·공식 HEAD 일치를 확인하고 독립 검수에 넘긴다. 반복 전체 추출은 새 코드 변경이 있을 때만 한다.

현재 준비 자료는 구현 완료·독립 수용·본 반영의 증거가 아니다.
