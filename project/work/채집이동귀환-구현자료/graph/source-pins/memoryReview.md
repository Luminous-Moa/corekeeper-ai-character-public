# 현재 기억 시스템 평가

사용자 요청은 현재 기억 시스템을 그대로 적용할지 개선할지에 대한 평가다. 구현 변경·게임 실행·실제 LLM 호출은 하지 않았다. 현재 본 저장소 ai-character를 대상으로 하며 별도 base-4a 개발 브랜치의 효과를 본 구현에 포함하지 않는다.

## 판단

자동 기록과 공간 상태·사건 이력·게임 지식의 구분은 유지할 만하다. 현행 플레이의 기억 기반으로 계속 사용할 수 있다. 다만 필요한 과거 정보를 실제 판단에서 찾아 쓰고 행동을 바꾸는 능력까지 완성됐다고 보기는 어렵다. 전면 재작성이나 저장소 통합보다 판단에 필요한 정보 전달과 조회의 성공 조건을 보완하는 것이 우선이다.

## 확인한 구조와 장점

- AIMemory는 광석·제작대 등 마지막 관측 상태를 월드/캐릭터별 memory.json에 보존하고 관측으로 갱신한다. 행동 후보 코드가 이를 직접 사용한다.
- AIExperience/AIExpCore는 사건 원본 events*.jsonl과 목표별 결과를 남긴다. memgraph는 원본에서 대상·장소·목표별 색인을 만들며 near 조회 때 공간 기억도 읽는다. 원본과 파생 검색 구조를 구분하므로 동일 세계를 별도로 추측해 유지하는 두 시스템으로 볼 필요가 없다.
- 조건 변화에 따라 실패 재도전 가능성을 구분하는 ExpRules.Measured/Judge가 이미 있다. 실패 횟수만 세는 시스템이 아니며, 새로 만들 필요가 없다.
- 관측과 모델의 말, 현재 관측과 과거 위치, 캐릭터별 접근 범위를 구분한다. 자동 기록은 관측을 안정적으로 보존한다는 장점이 있다.

## 보완 우선순위

1. 조회가 필요한 장면에서 실제 조회가 일어나도록 한다. 이미 experience·최근 전투·목차가 자동 공급되므로 모든 판단에 과거 기록을 더 붙이는 방식은 피한다. 제작법 때문에 거절됐거나 특정 과거 시점/사건을 질문받아 현재 보고만으로 답할 수 없는 장면처럼 정보 공백이 명확한 경우를 대상으로, 필요한 소수의 사실을 먼저 조회하거나 모델이 조회 후 답하도록 흐름을 보완한다. 기존 프롬프트의 game how 안내만으로 현재 효과를 보장하지 않는다.
2. 판단과 실행의 연결을 평가한다. 기억에서 준비가 필요함을 알아도 해당 준비·이동·장비 행동을 표현/실행할 수 없으면 결과가 달라지지 않는다. 철광석 채집 연결 누락은 기억 저장 결함과 별개다. 현재 goto/place 등의 지원을 활용하되 경로 회피 등 일반 제약이 다 구현됐다고 확대하지 않는다.
3. 효과 검증을 기억이 필요한 대표 사례로 좁힌다. 기억한 제작대로 돌아가 완료하기, 같은 실패 조건에서는 준비를 바꾸고 조건 개선 뒤 재도전하기, 현재 요약에 없는 과거 질문을 검색해서 답하기. 원본→조회/보고→판단→실제 결과를 연결해 판정한다. 검색 횟수 증가는 성과가 아니다.

자유로운 교훈 저장은 후순위의 선택지다. 반복 경험에서 적용 조건과 근거 사건을 가진 짧은 해석이 실제로 필요할 때만 추가한다. LLM 말이 관측 사실을 덮거나 같은 사건 재해석으로 신뢰가 올라가는 구조는 피한다. 현재 자동 기록을 교훈용 LLM 쓰기로 대체할 근거는 없다.

## 검증과 한계

현재 코드의 memgraph 검사 80개 및 recall-loop 검사 41개 통과. 실제 ai2 저장 기록 네 캐릭터를 real-data.mjs로 읽어 사건 색인→목차→대상/장소/목표/기간/제작법 조회 결과를 확인했다. 합성 100시간 자료 검사도 통과했으나 실제 100시간 플레이 품질 검증을 뜻하지 않는다. 현재 사용자의 실게임·추가 LLM 시험 보류를 유지했다.

과거 [실게임](2026-11-04-기억-그래프-검색/7-실게임.md)에서 42판단의 recall은 0이었다. 그것만으로 결함은 아니다. [질문 시험](2026-11-04-기억-그래프-검색/8-질문시험.md)에서는 35판단의 recall이 0이고 필요한 정보가 요약에 없을 때도 일부 부정확한 답이 있었다. 시험에는 보고/기록 시점 차이와 당시 모델·프롬프트라는 한계가 있다. 이를 현재 모든 모델의 동일 재현으로 단정하지 않는다.

현재 plan.mjs/recall-loop.mjs도 추가 검색은 모델의 recall 응답 또는 이전 prefetch에 의존한다. 검색 구현의 정상 동작과 모델이 필요한 때 검색하는 능력은 별도로 판정한다. 과거 [재생 판정](2026-11-04-기억-그래프-검색/6-목표판정.md)은 목차 유무의 명확한 개선을 입증하지 못했고 일부 스냅숏 결함도 명시했다. 따라서 기존 수치로 기억 효과를 확정하지 않는다.
