# 공통 실행 계약

기반은 common-execution-20261107, 11eb461이다.

공통 실행은 685dde4d27dd91a782a14d8ae33fb576160fa578로 구현되어 C:/Dev/CoreKeeperModSDK의 ai-character에 통합됐다. 다른 행동 작업은 이 커밋을 기반으로 연결한다.

- 기존 AICandidate의 kind, key, value와 대상 필드, AISkill.Start/Tick/Status/Reason/Facts를 사용한다. 후보는 실제 대상에 바인딩하고 결과는 몸이 관측한 변화로 기록한다.
- stop_action은 현재 몸 동작만 AI가 중단한다. 목표와 원래 부탁은 유지한다.
- stop_action은 관측한 실행 회차에 바인딩된다. 관측 뒤 새 실행이 시작됐으면 이전 중단 응답은 새 실행을 멈추지 않는다. 문닫기 정리 동작까지 포함한 현재 회차를 종료하며 열린 문 사실은 남긴다.
- finish_goal은 현재 작업 단계를 AI가 완료 처리한다. 다음 계획 단계가 있으면 이어지고, 마지막 단계면 상위 LLM에게 보고한다. 원래 사용자 부탁의 완료는 상위 응답 order=done이 결정한다.
- request_plan은 현재 관측과 실행 이유를 상위 LLM에게 전달한다. 응답을 기다리는 동안 유효한 몸 동작과 현재 목표를 유지한다. 이미 요청 중이면 현재 사실을 후속 보고에 합쳐 요청을 중복하지 않는다.
- 위쪽 LLM의 hold는 목표 유무와 관계없이 명시 중단으로 처리한다. 목표·자기방어 상태를 갱신하고 현재 몸 동작을 끝낸다.
- 수량 충족·목적지 도착·시설 조건 충족, 진행할 후보 없음은 AIGoals의 관측 상태로 현장 입력과 상위 보고에 제공한다. 코드가 현재 작업을 자동 완료하거나 취소하지 않는다.
- 실행 제한시간·진척 없음은 AISkill의 실행 관측으로 기록하고 현장 재판단을 요청한다. 실제 대상 소실이나 입력 대상 변경은 실제 실행 결과로 종료할 수 있다.
- 실행 관측은 AISkill.ExecutionObservations와 AIBrain.ExecutionObservation에서 읽는다. 관측 수정번호를 마지막 요청과 대조해 요청 중 발생한 사실을 후속 판단에 전달한다. 현장 입력과 상위 보고가 이 상태를 소비한다.
- AI가 새로 고른 중단·전환과 사용자 직접 중지는 실행한다. 과거 응답은 대상·실행 회차·현재 목표에 실제로 맞는지 확인한다.
- 호출 실패, 호출예산·월간 비용 제한은 새 호출을 제어한다. 이미 선택한 실행 가능한 행동은 유지한다.

위 kind 세 개는 공통 실행이 처리한다. 다른 작업의 후보 생산자는 장비·대상·위치 등을 지정한 기존 동작 후보를 추가하며, 공통 제어 동작을 별도 구현하지 않는다.
