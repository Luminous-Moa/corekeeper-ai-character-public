## 연결 구조

- 기존 후보 생산자·AIActions·AISkill을 유지한다. 가시 채집 후보를 고정 묶음으로 선택하는 AIGathering 실행을 추가하고 단일 후보도 유지한다.
- AITravel은 통로 탐색/알려진 목적지 이동을 구분한다. 관측·기억 경로를 사용하고 다음 갈림길 방향 선행 선택만 허용한다. 기존 몸 입력·정상 경로·막힘 관측을 재사용한다.
- AIExpedition은 개별 캐릭터의 원정 관측과 곁일/원작업 맥락, 직접 선택과 얕은 분류 탐색을 담당한다. 현재 목표를 메뉴 조작이나 곁일 때문에 교체하지 않는다.
- 기존 AIPlanner 계획 단계·host orders·RequestReplan을 사용하여 자동 보고 두 사건의 중복을 억제하고, 귀환 목적과 다음 작업을 상위/현장 입력에 연결한다. 코드가 곁일이나 귀환의 정답을 고르지 않는다.
- 기존 공통 실행의 중단/단계 완료/원래 부탁 완료 의미를 유지하며 목표 수량과 현장 묶음은 분리한다. 수량 제한 해제 코드는 재사용한다.

## 검증

생산 C# 경로를 호출하는 오프라인 대표 흐름: 가시 광맥 묶음 선택→새 대상 제외→회수 실제량 기록→길가 곁일 전환·원작업 재개→통로 분기 선행 선택/늦은 응답 정지→막힘 재판단→귀환·다음 계획 단계. 위험 전환·오래된 응답·자동 보고 중복·목표 보존을 함께 확인한다. 전체 C# 게임 어셈블리 컴파일과 관련 기존 회귀를 실행한다. 실제 게임/모델 호출·설치는 기존 보류 조건을 따른다.

## 실행 소유권
