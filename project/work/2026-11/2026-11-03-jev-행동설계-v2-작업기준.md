# Jev 행동설계 v2 작업 기준

요청일: 2026-11-03. 사용자 요청: “여태까지 수집한 자료를 바탕으로 설계를 다시 보완해줘”.

## 목적과 범위

AI 단톡방 캐릭터의 Core Keeper 플레이를 위한 검토용 설계를 보완한다. 소비자는 설계를 검토하는 사용자와 이후 몸 조작 시험·구현을 맡을 작업자다. 이번 산출물은 연결된 설계 문서이며 구현·설치·게임 실행·유료 API 실행은 포함하지 않는다. context.md와 단톡방 자체 구조는 변경하지 않는다.

## 유지할 방향과 구분

- 사용자 구상: LLM 큰 목표, Jev 상황별 행동 선택, 프로그램 관찰·행동 후보 구성·조작. 변화 없는 지속 행동은 호출을 줄이고 전투에서는 현장 판단을 갱신한다. LLM은 전투 중에도 목표를 재판단할 수 있어야 한다.
- 사용자 문제 제기: LLM이 Jev의 모든 행동을 일일이 보는 것은 의미가 적다. 직전 답변에서 제안한 단계·결과·예외 중심 점검을 이번 보완안으로 구체화하되, 세부 운영값까지 사용자 확정 사항으로 기록하지 않는다.
- 전투 판단을 Jev에 맡기는 구상을 유지한다. 조사 사례의 자동 조준·도주·긴급 반사를 기본 허용으로 받아들이지 않는다.
- 10/21 프로그램 점수 방식 우선의 잠정 기록, 11/3 Jev 설계 초안, 이번 보완안의 관계를 명시한다. 이번 결과만으로 구현 방식을 확정하지 않는다.
- 몸·관찰·입력 가능한 범위는 실제 월드 시험 전이다. 설치 미완료라는 오래된 context 문구보다 최근 모드 로드 확인/월드 시험 대기 기록을 따른다.

## 판단 기준

1. 사용자 목표에서 실제 관찰 결과와 다음 LLM 계획까지 흐름이 이어져야 한다.
2. 당장 가능한 후보와 준비 후 가능한 목표/선행조건을 구분하되 미구현 능력을 수행 가능하다고 전달하지 않는다.
3. 모델의 선택, 실행기의 명령 수락, 게임에서 확인된 효과를 구분한다.
4. Jev와 LLM은 비동기이며 게임 입력 소유자는 하나다. 과거 목표·대상·중요 전제가 사라진 응답이 현재 행동을 덮어쓰지 않는다.
5. 호출 억제가 무한 정체·오래된 기억으로 이어지지 않게 진행·유효성을 관찰한다. LLM은 의미 있는 변화/정체를 보고, 평소 세부 기록은 필요시 조회한다.
6. 지식 전달은 매 Jev 호출마다 LLM을 기다리지 않는다. 현재 사실과 장기 지식을 구분하고 판단에 필요한 내용을 실제 요청에 포함한다.
7. 다양성·자연스러운 무빙·성공률·지연·비용은 서로 다른 측정이다. Jev 효과를 주장하려면 같은 후보/실행기/지식/목표 아래 프로그램 판단기와 비교한다. 오프라인 판단 비교와 실제 플레이 비교를 구분한다.
8. 조사 수치는 저자 보고·정지 추론·프로그램 개입·조건 제한을 보존한다. API 0.1초나 안정적 전투 성공을 확정하지 않는다.
9. 대표 사건 추적으로 설계의 연결을 확인하되 실제 E2E 실행 검증이라고 표현하지 않는다. 실게임 검증이 필요한 조건을 별도로 남긴다.
