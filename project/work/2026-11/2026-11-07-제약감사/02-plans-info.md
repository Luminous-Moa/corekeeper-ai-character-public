## 범위와 남은 사각

계획 입력→StepForm/CheckGoal→현재 목표, 모델 보고 구성, bridge shape·검색·시간/구독 검사까지 정적 추적했다. P01~P08/I01~I10/C01~C12는 **30개 식별 항목**이며 성격별 묶음이다. 추가로 공간·권한·지원범위 정책 세 항목을 별도 기재했다. 동일 상한의 중복 구현은 별개 문제로 세지 않았다. 보고 제한은 다른 전체 상태 필드·현장 트리·검색으로 우회 가능한 경우가 있으므로 즉시 ‘기능 불가’라고 일반화하지 않는다. 게임 본체의 실제 스택·레시피·행동 제한과 모든 설정의 런타임값은 전수 실행 검증하지 않았다. 후보/스킬별 범위·종료 제한은 01-choices.md 담당이다. 이번 감사는 수정 승인이 아닌 보고이며 예산·권한을 임의로 바꾸지 않았다.

## 연결된 CLI 어댑터 확인

03-cross-choices.md의 독립 검수에 따라 I01의 별도 전체 main bag 슬롯 전달 경로와 P04의 절단 사건 알림을 본문에 반영했다. 두 항목은 정보·계획을 단순 최신순으로 줄이는 다른 제한과 강도를 구분한다.

브리지가 실제 가져오는 `C:/Dev/ai-chatroom/lib/agents/adapters.mjs`의 chat 경로와 CLI별 chat 함수를 읽었다. `maxPromptChars()=120000`(:84)은 chatroom의 `lib/server/turn.mjs:69`에서만 사용되며 Core Keeper bridge는 그 호출자를 경유하지 않으므로 **이 브리지의 활성 입력 잘라내기 상한으로 보고하면 안 된다.** CLI chat 출력에 별도 max_tokens 숫자를 주는 경로는 읽은 Codex/Claude/agy/Grok chat 함수에서 찾지 못했다. `lib/agents/run.mjs:39~64`는 수신 stdout/stderr 버퍼를 합치고 시간 초과에 프로세스를 종료하며 출력 문자열을 숫자로 자르지 않는다. 이미지 설명의600자 tidy는 별도 describe 경로이므로 이번 텍스트 계획 호출과 다르다. agy는 chat에서 print-timeout을 전달하고 외부 실행 타이머에10초를 추가한다(`lib/agents/cli/agy.mjs:80~83`). 사용량·서버·모델 내부의 비공개 한도는 이 감사 범위 밖이다.
