## 요약

시도 ID, 중복 방지, 결과 코드 구분은 실제 연결 경로에서도 기준대로 돈다. 쓰러짐·호스트 명령·재시작·오래된 답이 이에 해당한다. 게임 루프 보호(모든 연결 지점의 try/catch)와 100시간 규모의 크기·속도도 문제없다.

문제는 **"지금과 같은 조건" 판정**이다. 보고와 brief가 모두 이 판정에 기대는데, 이 판정이 막힌 원인과 맞지 않는다. 그 결과 두 방향으로 다 틀린다.
- 탐험이나 재료 준비로 풀리는 막힘(모을 곳 없음·만들 방법 없음·할 행동 없음)은 장비가 바뀔 때까지 시간 제한 없이 "같은 조건에서 막힘"으로 남는다. 그동안 brief는 "되풀이하지 않는다"고 지시한다. 그래서 준비를 마친 뒤의 재도전이 막힌다.
- 목표 안에서 장비가 바뀐 뒤 막혔거나, 상관없는 값만 바뀐 경우에는 "조건이 달랐음"으로 나온다. 그래서 지금 실패가 가려진다.

가짜 기록 시험은 두 경우를 모두 만들지 않아서 통과한다.

## 가짜 기록 시험이 실제 경로를 대표하는가

통과는 재현했다. 다만 다음 차이 때문에 위 발견들이 시험에서 드러나지 않는다.

1. **목표 안의 조건 변화가 없다.** 시험의 c0는 시작 때 값이고, c1은 끝 때 무작위 지역뿐이다. 실제로는 준비 단계에서 곡괭이·칼이 바뀐다(F1).
2. **"맞는 경험" 검사는 tool_weak 두 사례뿐이다.** 그것도 run 사이에 장비가 바뀌는 사례다. no_source·cannot_craft·only_wait 막힘 뒤 장비 변화 없이 시간이 지나는 경우, explore 막힘은 검사하지 않는다(B1).
3. **지역 모형이 다르다.** 시험의 지역은 보고마다 무작위다(15%는 Slime). 실제 지역은 캐릭터가 선 곳이고, back_up 보고는 늘 코어다(F2).
4. **gather 품목이 다르다.** 시험은 광석 6종과 필요 레벨 1~6을 쓴다. 실제 `can_do.gather`와 답 검사는 흙벽·구리·주석·나무 4개로 고정이다(`AIPlanner.cs:176, 364`). 그 밖의 gather 키는 호스트 목표에서만 생긴다.
5. **AIExperience.cs(Unity 쪽)는 전혀 돌지 않는다.**
   - 조건 읽기(레벨·방어구·바이옴)
   - `AIVitals.Downs` 차이로 쓰러짐 감지
   - ResetState→OnReset→unknown 경로(시험의 재시작은 `Load`만 부름)
   - 월드 전환(`Rec`)
   - 불러오기 실패 처리(F3)
   - got 계산
   - 이 부분은 실게임 흐름 시험에서만 확인된다.
6. **S4의 "다른 캐릭터" 검사**는 폴더가 다르면 안 섞인다는 것만 본다. 실제 위험은 `AIAgent.Cur` 범위인데, 그쪽은 코드 읽기로 확인했다(위).
7. **보고 시점이 다르다.** 시험은 매 목표 앞에서 보고 조각을 만든다. 실제 보고는 완료·막힘·탐험 끝·back_up·hold 재확인 때만 나가고, back_up은 진행 중인 run이 있을 때다(R2).
