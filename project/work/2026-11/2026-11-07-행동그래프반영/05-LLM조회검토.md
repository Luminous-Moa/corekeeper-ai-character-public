# 게임 내 LLM의 행동 그래프 조회 검토

## 확인한 목적

사용자는 AI 조회용 게임 지식그래프의 목적이 게임 내 LLM이 목표를 달성하기 위해 필요한 게임 사실·규칙을 찾아 판단하도록 하는 것임을 확인했다. 공간 기억(어디에서 봤는가), 경험 기억(무엇을 겪었는가), 게임 지식(어떤 규칙과 방법이 있는가)은 서로 다른 입력이다. 대상·행위·조건·결과도 이 목적에 필요한 지식이다. 연구 추출과 현행 조회 그래프는 저장 해상도와 소비 경로가 다르며 목적까지 별개라고 보아서는 안 된다.

현행 근거: C:/Dev/CoreKeeperModSDK/Tools/ai-bridge/brief.md의 기억 찾아보기 및 C:/Dev/CoreKeeperModSDK/Tools/ai-bridge/memgraph.mjs의 game 질의/캐릭터별 view, 기존 게임 지식그래프 설계2.

## HEAD의 권고 — 연결 구현 결정 아님

상세 근거를 보존한 그래프를 게임 지식의 근거로 사용하되, LLM에는 현재 대상·의도에 관련된 행동 설명을 반환하는 조회를 권고한다. 모든 추출 payload를 그대로 보여주면 코드 구현 세부·중복 보강·검수 내역과 게임 판단 정보가 섞인다.

기본 응답에 필요한 것은 대상·행위, 요구 도구/재료/상태, 소모와 산출/상태 변화, 실패 조건, 아직 모르는 조건/결과다. sourceKey·prefab주소·해시·Converter/System·버퍼·코드줄·추출/검수이력은 근거 추적용으로 남기고 일반 행동 설명에서 숨길 수 있다. 기술적 표기라도 실제 결과를 바꾸는 조건은 의미를 풀어 보존해야 한다.

전기 전파·선행 충전·UI 내부 소비 같은 단계는 모두 독립적인 AI 행동으로 노출하지 않고 관련 행위의 조건/결과에 연결해야 한다. 같은 원본의 여러 보강행도 지식의 복수 근거이지 별개의 행동 수가 아니다.

세 가지 판정을 구분한다.

1. 게임에서 가능한가: 정적 게임 규칙과 조건.
2. 현재 가능한가: 위치·가방·대상 상태 등 현재 관측과 조건을 비교.
3. AI 모드가 실행할 수 있는가: 실제 제공되는 실행 도구와의 대응.

캐릭터에게 열린 지식 범위를 지키고, 필요한 현재 상태가 미확인일 때 가능으로 단정하지 않는다. 현행 can_do·실행 도구 범위와 게임 지식의 범위를 혼동하지 않는다.

## 이번 작업의 경계

### 별도 그래프 유지와 조회 분리의 비교

사용자는 기존 게임 지식그래프를 별도로 두고 보완할지, 이번 그래프에 조회 조건을 둘지 물었다. HEAD는 게임 사실을 독립적으로 수작업 관리하는 두 정본보다 같은 게임 근거에 개발자용·LLM용 조회를 나누는 방향을 권고했다. 단순 노드 노출 필터만이 아니라 내부 단계/보강을 행동 설명으로 묶고 캐릭터별 공개 범위를 적용하는 조회가 필요하다. 성능을 위한 작은 자동 생성 조회용 사본은 허용 가능한 구현 방식이며 별도 정본은 아니다.

이번 행동 자료가 현행 게임 지식의 제작·드롭·스폰·효과·타일 관계를 모두 대체한다고 검증한 적은 없다. 기존 지식을 보존해 대조·연결한 뒤 소비 경로를 바꾸는 순서가 필요하다. 이는 HEAD의 권고이며 사용자의 아키텍처 선택이나 후속 구현 승인으로 기록하지 않는다.

사용자는 적합성과 불필요 정보 여부를 질문했으며, 이 질문 자체로 게임 내 조회 API·캐릭터 공개 정책 변경을 요청한 것은 아니다. 이번 구현은 합의된 대상·행위·조건·결과 파생 그래프와 개발 조회까지다. 실제 LLM 소비 연결·응답 스키마·공개 조건은 후속 결정이 필요하다.
