# 검수 상호작용 반영 후 완전성 독립 평가

평가일: 2026-11-07. 기존 자료를 읽기만 하여 평가했다. 게임·모드·기존 추출본·그래프를 실행하거나 수정하지 않았고 세션 연결/저장 도구를 사용하지 않았다. 이 문서는 그래프 구현 검수가 아니라 **반영할 근거가 무엇을 보장하는가**의 평가다.

## 답변

**검수된 자료를 그래프에 모두 반영하더라도 “이제 빈 곳이 없다”고 말할 수 없다.** 고정 원본의 source와 이미 알려진 미결을 빠짐없이 연결하는 것은 가능하다. 그러나 행동 계열 전수 발견, 모든 대상×행위의 조건·결과 완결, 실게임 성공, 모드 능력 비교는 서로 다른 범위이며 아직 모두 완료되지 않았다. 그래프 반영은 이미 확인한 사실과 미결을 함께 조회 가능하게 만드는 일이지, 미결을 자동 해소하는 일이 아니다.

## 수집 단위와 집계의 한계

- 원본은 3,235 source이며 ID×variation key는 3,021개다. 하나의 key에 여러 프리팹 source가 있을 수 있어 병합하면 안 된다. 이전 수집 3,031 key와 분모도 다르다. 원본 coverage는 이전에만 있는 12 key와 새로 있는 2 key를 보존한다. 이전 ID 등록 전용 11개도 현재 원본에 억지로 추가하지 않았다. 따라서 숫자 증가를 대상 종류의 전면 확장으로 해석할 수 없다.
- baseline 1,432행은 967 source에 연결되며 code_linked 1,345행과 asset_link 레시피 설정 87행을 구별한다. 요리 6,561 순서쌍은 별도 관계표다.
- 보강 949행은 681 source에 연결된다. 기존 source×action 문자열과 같은 427행(B425+C2)은 보강이다. 나머지 522행도 전기 사실 단계·선행 활성화·UI 입구·경계 설명을 포함하므로 모두 신규 플레이어 행동이 아니다. 고유 게임 행동 총수는 `null`로 유지한다.
- `final/coverage.json`의 `unresolvedRecords=3235`는 원본 시점의 미결 보유 source 집계다. 보강 후 남은 미결의 총수로 재사용해서는 안 된다. 반대로 보강의 `current_disposition_present=1671`도 잔여 미결 0이라는 뜻이 아니다.

## object / coordinate / liquid / abstract 범위

이 네 범주는 현재 추출본에 확정된 네 가지 schema type이라는 뜻으로 사용하지 않는다. 질문의 대상 범위를 나누어 평가한 것이다.

| 대상 범위 | 자료로 확인되는 것 | 확인되지 않은 완전성 |
|---|---|---|
| object | 고정 bundle의 EntityMonoBehaviourData에서 objectInfo와 ID/variation을 읽어 3,235 source를 생성. 네 분석이 전수 분담 | 다른 번들·추가 catalog·실행 중 loader·동적 모드까지의 모든 객체 |
| coordinate | 삽·괭이·물뿌리개·씨뿌리개 등의 슬롯 경로, 배 하선 후보 타일/위치 검사 등 위치 조건 일부 존재 | 좌표/타일을 독립 모집단으로 정한 모든 대상과 행위의 census |
| liquid | 양동이 채우기·붓기, 물뿌리개, 낚시 시작 등의 도구 경로 존재 | 액체 종류·위치·상태별 가능한 모든 행동과 조건·결과의 census |
| abstract | UI, 잠금/활성화/전력/인벤토리/타이머 등 상태 전이가 일부 정적 연결됨 | 모든 추상 상태와 가능한 전이의 census |

구 수집 [README](../2026-11-06-게임상호작용자료/README.md)는 “좌표·액체·추상 상태 전체를 포괄하지 않는다”고 명시한다. 이후 원본 수집은 신뢰도를 원문 프리팹/동일 설치판 코드로 개선했지만, [extract.py](../../게임원본-상호작용/extract.py)의 107~114행에서 census 진입점이 EntityMonoBehaviourData임을 확인했다. [재현 안내](../../게임원본-상호작용/README-추출.md)도 기본 bundle 등 manifest 입력만 고정하며 설치 폴더의 다른 bundle 추가/변경은 감시하지 않는다고 명시한다. 따라서 **비객체 범주가 전혀 없다는 결론도, 그 범주까지 전수로 확장했다는 결론도 성립하지 않는다.**

## 표본 확대 밖의 계열과 실제 미완료 지점

baseline의 A는 앉기·침대·문·레버·배, B는 먹이·안장·목줄·우리·수리, C는 잠금·압력판·포털·강화·자판기, D는 포획·투입·제작·요리·지도다. 이 규칙을 전체 source에 적용했다고 해서 전체 게임 행위를 발견한 것은 아니라는 제한이 [작업 기준](../2026-11-07-행동전체추출/00-작업기준.md)에 명시되어 있다.

독립적으로 원본 equipment `records.interactions.verb`를 집계하면 `beam_attack`, `catch_critter_request`, `dig_shovel`, `equip_gear_swap`, `fill_bucket`, `melee_attack`, `paint_entity`, `plant_seed`, `play_instrument`, `pour_bucket`, `range_attack`, `start_fishing`, `summon_minion`, `toggle_roof`, `use_hoe`, `water_ground`가 이미 존재한다. 그러므로 낚시·전투·농사·액체 사용 등을 통째로 “미수집 행동 계열”이라고 표현하면 틀리다.

다만 원본 JSON에서 다음 미완료 지점은 직접 확인된다.

| 사례 | 이미 수집한 단계 | 남은 내용과 판정 |
|---|---|---|
| 삽 1:0 `dig_shovel` | 조건을 통과하면 `digStateStarted=true` | 대상별 최종 파기 결과는 이 행에 없음. 개별 보조 행동·조건부 효과·대상별 결과 추가 조사를 명시 |
| 광선 91:0 `beam_attack` | `projectileTriggerEnabled=true` | 광선 투사체 프리팹과 실제 명중 결과 미확인을 명시 |
| 소환 9176:0 `summon_minion` | `spawnMinionCalled=true` | 소환체 프리팹의 실제 생성 가능성과 최대 차지 분기 미확인을 명시 |
| 상인/특수 UI | 원본 NPC 상점 열기, 보강 D의 `special_ui_entry` | 보강 보고서도 UI 열림까지라고 제한하며 구매·대화 전체 완료로 확대하지 않음 |

근거: [장비 원본 JSON](../../게임원본-상호작용/analysis/equipment/results.json), [장비 보고서](../../게임원본-상호작용/analysis/equipment/report.md), [생물 보고서](../../게임원본-상호작용/analysis/creatures/report.md), [보강 D 보고서](../2026-11-07-상호작용미결보강/D-outcomes/report.md).

baseline 및 보강의 여덟 `extraction.json`에서 고유 action 목록을 읽어 대조했다. 위 장비 계열 전체를 대상별 조건·결과까지 완결했다고 주장하는 후속 범위는 확인되지 않는다. 자동 낚시·농사 팔·전기 공격 보강이 있다는 사실을 플레이어 낚싯대·수동 농사·광선 무기의 모든 후속 처리 완료로 대체해서는 안 된다. 이 대조는 **이미 부분 수집된 계열의 미완료 근거**이며, 게임의 모든 코드 경로를 새로 전수 감사해 “완전히 미수집된 계열”을 확정한 결과는 아니다.

생물 원본의 오래된 “먹이 전체 ID 미완료”를 현재 미결로 그대로 재사용하면 안 된다. B가 catalog/먹이/variation 선택을 보강했다. 압력판의 기본 플레이어 충돌 필터도 C 보강에서 정적으로 해결됐으므로 여전히 필터 자체가 미결이라고 쓰면 틀리다. 원본 unresolved는 최신 보강 관계를 따라 해석해야 한다.

## 최신 자료에서 확정된 잔여와 검증 필요

### 정적 근거 자체의 확정 미결

1. **회로 6506 variation 0~3**: 원본 circuitType=3과 같은 빌드 DLL enum 0/1/2의 불일치. 원본/DLL 재조회까지 했으나 특수 의미는 unresolved다. 전력 전파의 다른 확인된 경로와 분리한다.
2. **제품 4600**: 4006 제작 설정에 참조가 있지만 고정 3,235 source 및 현재 ObjectID enum에 해당 원본이 없다. 전체 raw component 정확 참조도 해당 레시피 하나뿐이다. 실제 DB/추가 catalog의 부재까지 증명한 것이 아니므로 정상 제품도 불가능 제품도 단정할 수 없다.

### 조건부 해석은 확인했고 실행 증거가 더 필요한 경계

- 실제 월드 회로 배치·물리 hit·타일·권한·슬롯·타이머·네트워크/ECB 반영·엔티티 생성/삭제.
- 추가 loader/모드의 실제 활성 상태와 실행 중 DB/variation 선택.
- 낚시/벌레덫의 실제 위치·난수·loot database·월드 캐시 선택. 소비자와 입력 규칙을 모른다는 뜻은 아니다.
- 포획의 한 InventoryUpdateSystem 실행 안 중복 방지와 삭제 후 차단은 확인됐다. 삭제 전 다음 실행 요청이 임의 미래 tick에서 항상 막힌다는 보장은 없다. 실제 중복 발생을 관측했다는 뜻도 아니다.

근거: [gap-index.json](../2026-11-07-상호작용미결보강/package/gap-index.json)의 `A.enumBoundary`, `D.remaining`, `originalGapStatus`와 [보강 통합 독립검수](../2026-11-07-상호작용미결보강/review/package-review.md). `originalGapStatus`는 B-2406/B-selection/C-filter/D-map1513/D-none을 resolved로, A-circuit6506/D-4600을 unresolved로, 여러 경로를 conditional로 구분한다. runtimeStatus는 모두 runtime-not-observed다.

지도 unknown 1,513개는 고정 graphicalRef→onUseActions→CartographyTable.Use 경로의 비적용으로 해결됐다. 이를 미수집 1,513 행동으로 다시 세거나 일반 지도 UI/동적 prefab/모드 지도 행동 모두의 불가능 판정으로 넓히면 안 된다.

## 그래프 반영 시 보존할 평가 기준

그래프는 source 전수 대응, 기존 행과 보강행 관계, rule별 적용/비적용/unknown 및 판정 범위, 원본 수준의 partial 결과, 최신 미결을 함께 조회할 수 있어야 한다. 행 수나 검수 pass만으로 행동 완전성 또는 실게임 성공을 표시하지 않아야 한다. 원본 장비의 시작 단계가 보강되지 않았다면 그 경계도 남겨야 한다.

사용자에게는 다음처럼 답할 수 있다: **“알려진 자료와 미결의 연결 누락은 막을 수 있지만, 빈 곳이 모두 없어지는 것은 아닙니다. 원본 3,235개와 기존 미결 1,671건은 전부 대조했고, 아직 회로 6506·제품 4600의 근거, 시작 단계만 확인된 일부 행동의 후속 조건·결과, 실게임 검증과 모드 능력 비교가 남습니다. 전체 게임 행동을 빠짐없이 발견했다는 검증도 별도로 필요합니다.”**
