# 행동 판단 프로젝트 연계 독립 검수

판정: 수용 적합. 최종 구현에서 수정이 필요한 코드 결함을 발견하지 않았다. 합의의 정상 조회 진입점, 최대 관련 범위 연결, 원문 도달, 기존 지위 보존을 충족한다. 생산 코드·생성 JSON은 검수자가 수정하지 않았다.

검수 대상은 `지식그래프/tools/product.mjs`를 통한 조회와 `topics.mjs`, `link.mjs`, 실화면 D의 integrate/query 및 생성물이다. 최종판은 27,015노드·49,591관계, 게임 정본은 251,417노드·350,275관계다. 고정한 파일 해시와 57개 조회 항목은 [review-evidence.json](review-evidence.json)에 있다. 최종 검수 구간에서 graph/link/topics/게임 정본의 해시 변경은 없었다.

## 핵심 대조

- 정본의 19,122개 참조 전부에서 정확 ID·origin·sourceKey·variation을 대조했다. 중복 ID, 선택한 종류의 누락, 미분류 행위, 존재하지 않는 label은 0건이다. 원본 대상·주장·완결·공통 소비·미결 등을 참조하는 색인이며 원문 조건·결과 전체를 프로젝트에 복사하지 않는다. 상세 필드와 관계는 기존 게임 CLI로 위임한다.
- 22개 주제 각각 정상 프로젝트 CLI의 `behavior`에서 대상 ID를 선택하고 `source`를 실제 실행했다. 이후 CLI 구현을 사용하지 않는 Python으로 실제 JSON 파일의 pointer를 직접 읽고 정규화 SHA256과 반환 내용을 재검산했다. 22건 모두 일치했다. 상세는 [review-raw.json](review-raw.json), 실행 응답은 [review-evidence](review-evidence/)에 있다.
- 문·곡괭이·요리 쌍·스프링클러의 `show`를 추가 실행해 조건·결과·실패·흐름과 관련 근거를 확인했다. 과거 곡괭이/문/다리의 정확 참조 3개와 채굴·이동 주제 보완도 확인했다.
- origin이 없는 `game:verb:cooking`의 `show`에서 incoming `uses_label`을 따라 `base:D::CAB-2ebcba97367158c9b08f790c25d642c9:-2106314794829400105#cooking`으로 이동하고 그 주장 원문을 조회했다. 라벨 자체에 임의 원문을 부여하지 않는다.
- ObjectID 4776의 sourceKey 4개와 variation 0·1·2·3을 별도 ID로 유지했다. `game target 4776`과 `--variation 0`을 실제 조회했다. 같은 ObjectID를 같은 원본으로 합치지 않는다.
- `legacy show F.action-select`, `source P.original-request`, `feature slash:ai`가 정상 동작했다. 기능 코드 트리의 기존 출력은 유지되며 관련 게임 주제 안내가 덧붙는다.
- 현재 integrate에서 `addBehavior` 호출만 비활성화한 검수용 사본과 비교했다. 기존 7,870노드의 모든 필드·30,388관계·다른 그래프 영역·validation이 유지된다. [review-preservation.json](review-preservation.json). 이는 변경 전 생성물의 역사 스냅샷을 대조한 시험은 아니며, 생산자가 변경 직전 graph를 별도로 보관하지 않았다는 제한이 있다.
- `product-build.mjs --check`는 `regeneration byte-identical`, 최종 `product.mjs check`는 `ok:true`, 구조 오류와 stale 모두 빈 배열이다. stale 함수에 합성한 잘못된 해시·없는 파일을 넣어 각 감지가 동작하는 것도 확인했다. 검수 과정에서 실제 원본을 변조하지 않았다.

분류는 정본의 label/action을 기준으로 하며 현재 각 주장에 다중 uses_label은 없다. 129개 verb·5,880개 claim·2,539개 action_completion·6,561개 cooking_pair를 모두 참조한다. 주제 없는 source와 보완 규칙·미결은 정본 입구에 연결하며 전체 상세는 `game`으로 조회한다. 주제별 수는 기록 단위이며 일부 교차 참조가 있으므로 고유 게임 행동 수로 합산하지 않는다.

코드 연결은 정확한 함수 signature를 찾은 관련 검토 위치다. 동물·낚시·차량·거래·전기·디버그 등의 주제는 기획 참고에서 연결하고 코드 지원을 새로 만들지 않는다. 모든 추가 간선은 reference이며 runtimeTrace:false, 참조 노드는 runtimeTested:false다. 주제 설명도 지원 여부 별도 확인을 명시한다. 넓은 주제의 전 행동이 해당 함수에서 구현되거나 실게임에서 성공했다는 의미로 읽히지 않는다. 기획의 합의/제안/승인 범위 및 과거 관측의 코드 기준도 보존했다.

게임 행동 대응이 없는 모드의 모델 통신·기억·토큰 비용 등에 억지 실행 관계를 추가하지 않은 범위 설정은 타당하다. 개발자 조회 연결의 최대 범위이며 AI에게 노출하는 행동·known.json·게임·세이브·모드는 변경 범위가 아니다. 실제 게임 성공이나 게임 규칙 자체의 전수 완전성은 이번 검수의 결론이 아니다.

## 검수 중 보완

EV-1: 생산 `evidence.json`의 초기 productEdges가 49,589로 최종 49,591보다 앞섰다. 생산자에게 알렸고, 최종 check/mining/move 재조회와 집계 갱신을 확인해 해결했다. [evidence.json](evidence.json)의 `queryRunProductEdges`와 `finalChecks`가 이전 조회 시점과 추가 2간선 확인 시점을 구분한다. 검수자의 22개 주제 behavior 결과는 모두 최종판에서 다시 조회했고, 원문은 게시본 불변과 origin 재대조 및 직접 해시 검증에 따라 앞선 실제 응답을 재사용했다.

초기 생산 중에는 입력 3개 stale, 이후 검수 중 최종 2간선 추가로 pin 변화를 감지했다. 해당 시점 결과를 최종 수용 근거로 사용하지 않고 파일 고정 이후 check/주제 조회/보존 대조/바이트 재생성을 다시 확인했다. 현재 미해결 finding은 없다.
