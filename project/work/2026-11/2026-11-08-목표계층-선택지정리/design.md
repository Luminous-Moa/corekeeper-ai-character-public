## 1단계 — 위쪽 LLM 목표 조정
답 형식(브리지 brief·protocol·게임 파서)에 추가:
- `step`(선택): 현재 단계 조정. `{"count": N}` 현재 gather/craft 단계의 수량을 바꾼다(늘리면 파밍 지속, 이미 확보량 이상이어야 함) / `{"stop": true}` 현재 단계를 지금 끝내고 다음 계획 단계로(측정 없는 단계를 끝내는 유일한 길, 측정 단계는 '파밍 멈춤'). keep과 함께 쓸 수 있다.
- `extra`(선택): 보조 목표 목록 전체를 바꾼다. 각 `{"item": ID, "count": N, "why": "짧게"}`. `[]`는 모두 지움. 생략하면 그대로.
- 사용자 결정: 보조 목표 개수와 주요·보조 목표 수량에 별도 상한을 두지 않는다. 위쪽 LLM이 보고 판단한다(형식 검사는 양의 정수·알려진 품목 정도만).
- 보고에 넣을 것: 현재 단계의 확보량/수량, 보조 목표별 확보량/수량(가방 기준), 기존 chests·base·가방. 수량 도달이 가까우면(예: 남은 양 ≤ 20% 또는 ≤2개) 그 사실.
- 보조 목표는 현재 단계를 끝내지 않는다. 확보량이 수량에 닿으면 그 보조 목표는 '채움'으로 표시되고 꼬리표가 떨어진다(목록에선 위쪽 LLM이 지울 때까지 남음).
- brief 기준(지침이지 상한이 아님): 보조 목표는 지금 계획을 진행하며 챙길 가치가 있는 것(계획 다음 단계 재료, 기지에 모자란 것, 성장 다음 단계 준비). 상자·가방에 이미 충분하면 정하지 않는다. 더 캐게 하려면 step.count를 늘린다.
- 원래 부탁의 완료는 지금처럼 order=done.

## 2단계 — 하위 선택지 정리
분류(갇힘 #60 기준 27개 → 약 10개 안팎 예상):
| 분류 | 처리 |
|---|---|
| 생존: 공격·짧은 이동·물러나기(적), 먹기(배고픔 낮음·체력 깎임) | 늘 남김 |
| 제어: 지금 동작 중단, 재계획 요청 | 남김(finish_goal 없음) |
| 의미 있는 계속하기: 공격 이어 가기, 걷는 중 탐색, 진행 중 채집 | 남김 |
| 효과 없는 계속하기: 멈춘 탐색의 '제자리에 서 있기', 답 전에 끝나는 짧은 행동의 계속하기 | 뺌 |
| 주요·보조 목표 품목이 나오는 캐기·부수기·묶음 채집, 기억한 목표 광석 쪽 이동, 목표 제작·건네기 | 남김 + 꼬리표 `(주요 목표 X 나옴)` / `(보조 목표 X 나옴, a/b)` |
| 기억한 주요·보조 목표 광석 | 채집·이동 목록 안이 아니라 가까운 몇 곳을 직접 선택지로 |
| 목표 찾기 이동(통로 탐색·출구) | 남김. 목표 품목이 화면에 없으면 설명에 '목표 X 탐색을 위한 이동' |
| 목표와 무관한 채집(버섯·흙벽 등) | 뺌(주요·보조 목표나 생존 필요—배고픔 시 음식—이면 남김) |
| 기다리기 | 목표가 있으면 뺌 |
| 메뉴(생활·인벤토리·채집·이동 목록) | 그 목표 종류가 메뉴를 쓰는 경우에만(생활 목표→생활, 가방 목표→인벤토리, 채집 목표인데 화면·직접 선택지에 목표가 없을 때→채집·이동 목록) |
- 근거: 조사 [판단모델 입력 최적화 조사](../2026-11-08-판단모델-입력최적화-조사.md) — 무효·무관 선택지 줄이기, 숨은 하위 목록 대신 직접 선택지, 라벨은 고르면 일어나는 일. 오늘 재생 결과(계속하기 139→0, 완료 확인 132→0).
- 확인: 오늘 기록 재생(서 있기·완료 확인 갇힘·공격 이어 가기 세트)과 100건 상황 세트에서 '목표 외가 정답'(위험·배고픔) 묶음을 따로 집계해 생존 선택이 줄지 않았는지 본다.
