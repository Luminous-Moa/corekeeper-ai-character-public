### B1. count 없는 place가 모두 거절됨 — 심각도: 막음 [관찰]
- 위치
  - `Core/AIPlanProtocol.cs:73`, `:87`: count가 없으면 `Int()`가 -1을 돌려준다(`:109`).
  - `AIPlanner.cs:561`, `:822`: 그 -1이 그대로 `CheckGoal` → `AIPlaceGoal.CheckPlace`로 간다.
  - `AIPlaces.cs:219`: `if (!r.IsShape && (count < 1 || count > 30)) return "개수 범위 밖(-1)"`.
  - count<1을 1로 바꾸는 곳은 `AIPlanner.cs:728` SetGoalFrom뿐이다. 이 줄은 검사를 통과한 뒤에만 돈다.
- 실패 장면
  - 위쪽 LLM 답 `{"do":"place","item":"CopperAnvil","where":"base"}`는 brief.md:59의 예시와 똑같고, brief가 "count 없으면 1"이라고 말한다.
  - 이 답은 '개수 범위 밖(-1)'으로 거절된다.
  - 계획 `[place CopperAnvil base, craft CopperSword 1]`도 1단계 검사에서 같은 까닭으로 막힌다.
  - 계획 2단계 이후의 place는 StepForm은 통과한다. 그러나 StartNextStep의 CheckGoal에서 '시작 못 함'이 되어 계획이 멈춘다(plan_step_failed).
  - CraftFact 문장("먼저 place CopperAnvil(장소)로 놓은 뒤")도 count를 말하지 않는다. 그래서 모델은 count 없이 쓸 가능성이 높다.
  - 결과: 계기 사례가 '같은 시도 되풀이'에서 '다른 거절 되풀이'로 바뀔 뿐이다.
- 브리지 쪽은 count 없는 place를 받는다(protocol.mjs goalShape, protocol.test 사례).
- 시험이 이 경로를 덮지 않는다.
  - PG 9a는 바로 이 계획(count 없음)을 읽기만 하고 CheckGoal에는 넣지 않는다.
  - CheckPlace는 Unity 쪽이라 core-tests 밖이다.
- 고칠 길
  - CheckGoal의 place 갈래(또는 CheckPlace 첫머리)에서 count<1을 1로 본다.
  - 이 정규화를 Core 함수로 두고 PG에 'count 없는 place 답 → 받음' 사례를 넣는다.

- **문 지나가기**: 회귀 없음. IsOwnDoorTile → IsWalkDoorTile은 둘레 문을 포함하는 상위 집합이다. [관찰]
- **위협 판정**: GuardGridAround는 바뀌지 않았다. [관찰]
- **문 닫기 후보**: 둘레 계획이 없어도 내 문이 있으면 모든 후보 묶음에 나온다(§6 (c)대로). [관찰]
- **솥·상자 놓기, store·cook**: 기지 판정(AtBase 10)이 그대로라 영향이 없다. [관찰]
- **home**: F1의 회귀가 있다.
- **보고 길이**: craft 16 → 40에 재료 문장이 붙고, places 12줄과 can_do.place가 더해진다. [추정] 지금보다 +1,000~1,500자다(설계 추정 +600~700보다 크다). 상한 장치는 없다. 실게임 보고에서 잰다.

## 실게임에서 꼭 볼 것
1. **모루 → 구리 검(B1을 고친 뒤)**
   - 가방에 CopperAnvil이 있을 때 craft CopperSword가 CraftFact 문장으로 거절되는지 본다.
   - 모델이 count 없이 `place CopperAnvil base`를 쓰면 받아지는지 본다.
   - 놓은 뒤 계획 2단계 craft가 시작되는지 본다.
   - 놓기 성공 판정은 '같은 id의 제작대가 3칸 안에 보임'이다. 그래서 이미 모루가 옆에 있으면 거짓 성공이 될 수 있다. 판정 자리(anchor)도 함께 본다.
2. **도착 판정(F1)**
   - 2×1·2×2 제작대로 `goto station:…`을 건다.
   - 기지 3칸 안을 본 적 없는 캐릭터로 `goto base`와 home을 건다.
3. **다리 line·here**: 물 건너 다리. here·count로 놓을 때 선택지 문장에 모순이 없는지 본다(F2).
4. **rect 바닥**: 선 칸 비켜 서기, 칸 하나가 막혔을 때의 끝 문장(F4), 가방 부족(F3).
5. **내 문**: 놓기 → `is my door` 로그 → 지나가기(열기→지나기→닫기) → 재접속 뒤 기억 → 화면 밖에서 닫혀 있을 때의 위협 사실(S6). 정확한 칸에는 `rect:x,y,x,y`로 놓는다(S1).
6. **2칸 이상 물체의 놓은 판정과 places 좌표.**
7. **보고 길이와 모델이 craft 묶음·places를 읽는지**, 새 로그 줄의 logshape 허용 목록.
8. **합치기 전에 Unity 관문**(`gates.sh --unity`). 구현자도 검수자도 돌리지 않았다.
