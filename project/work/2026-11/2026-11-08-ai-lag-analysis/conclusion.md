# AI 통신과 게임 전체 순간 멈춤 — 분석 결론

2026-11-08. 요청 범위는 원인 분석 및 해결책 제안이다. 사용자는 AI 통신 시 화면 전체와 본인 캐릭터까지 순간 멈춘다고 확인했다. 코드·게임·서비스·설치는 변경하지 않았다.

## 결론과 확실성

최우선 원인은 AI 요청 직전 게임 메인 스레드에서 수행하는 보고서·후보·길찾기 계산의 집중이다. HTTP 요청은 전송 후 완료를 다음 Tick에서 확인하므로, LLM 응답 대기 전체를 동기적으로 붙잡고 있는 구조는 아니다. 현재 관찰은 모든 순간 멈춤의 단일 원인까지 확정하지는 않는다.

- 기존 11월 6일 조사: 이전 실게임에서 판단 준비 100~320ms, 길 계획 50~179ms가 관측됐다. [기존 진단](../2026-11-06-stutter-diagnosis.md)을 재사용했다.
- 이번 추가 확인: 11월 7일 Gemini 실행 로그의 report #2에서 ReportJson 생성 구간 buildMs=434.5ms가 기록됐다. 같은 30초 통계창에 AI Tick 최대773.4ms 및 프레임 최대1683.4ms가 있다. 각 최대가 같은 프레임이라는 뜻은 아니다. 434.5ms는 HTTP 전송과 SEND 로그 작성 이전의 로컬 보고서 생성 경과시간이며, 개별 함수 CPU시간과 OS 스케줄링/GC 기여는 분리되지 않았다.
- 11월 8일 현재 브리지와 11월 7일 게임 로그는 서로 다른 실행이다. 조사 중 Player.log가 새 게임 시작으로 교체되어 이전 실행과 현재 실행을 구별한다. 현재 사용자 증상 당시의 로드 바이너리와 프레임별 인과는 미확정이다.
- 현행 설치 준비 자료의7af8f91 소스에도 동기 준비/보고서/경로계획 구조가 남아 있다. 제작법마다 재료 가능 여부를 반복 평가하고 생활 보고서를 여러 번 조회하는 경로는 추가 최적화 지점이다. 실측435ms 중 각 하위 단계의 기여율은 아직 모른다.
- 응답 처리의 동기 저장·JSON 할당, ECS 동기화, GC 및 다른 PC 작업은 부차 후보이다. 현재 자료만으로 각각의 주원인 여부를 판정하지 않는다.

## 권장 해결 순서

1. 실제 증상 장면에 최소한의 구간별 계측을 붙인다. 프레임 번호, AI 전체 시간, 관측/보고서/후보/길찾기/응답적용/저장 시간을 연결한다. 평균 FPS 대신 긴 프레임 횟수와 p95/p99, 최대를 비교한다.
2. 모든 AI를 합산한 프레임 작업 예산을 두고 보고서·후보·길찾기를 중단 후 이어갈 수 있도록 나눈다. 개별 함수가 한 번에 수백ms 실행되는 상태에서 바깥 루프만 나누면 효과가 제한되므로, 무거운 내부 반복까지 분할한다. AI 여러 명의 준비도 분산한다. 초기 예산값은 실기 측정 후 정한다.
3. 한 보고서 작성 중 같은 관측·인벤토리·상자·제작대 정보를 재사용하고, 변경된 입력만 다시 계산한다. 캐시는 입력 변경과 월드/명령 변경을 반영해야 한다. 보고서의 선택지·기억·행동 의미는 보존한다.
4. 위 조치 후에도 큰 순수 계산이 남으면 불변 데이터 스냅샷으로 워커/Job 분리를 검토한다. 현재 길찾기 비용 계산은 Unity EntityManager·TileReader에 접근하므로 함수 전체를 Task.Run으로 감싸는 방식은 적합하지 않다. 캡처 비용도 프레임 예산에 넣고, 완료 결과는 월드·명령·관측 버전이 여전히 맞는지 확인한 뒤 적용한다.
5. 동기 저장과 임시 할당은 계측상 기여가 확인되는 순서대로 개선한다. 저장을 분리할 때는 최신 데이터와 종료 시 보존을 유지한다.

여러 프레임 분할은 적용 범위가 비교적 직접적이며 계산 총량은 그대로 남을 수 있다. 워커 분리는 메인 스레드 부하를 더 줄일 수 있지만 관측 복사와 상태 일관성 설계가 필요하다. 먼저 중복 조회 제거와 프레임 분할을 결합하는 것을 권장한다. 판단 빈도·선택지 수를 줄이는 방안은 게임 행동의 변경이므로 이번 해결책으로 확정하지 않았다.

## 개선 판정

같은 설치판·월드·카메라·명령으로 AI 켬/끔 및 개선 전후의 대표 흐름을 비교한다. 사용자 명령→보고서 준비→실제 모델 응답→게임 행동까지 연결된 한 흐름에서 화면 끊김 감소와 원래 판단/행동의 보존을 함께 확인해야 한다. 현 시점은 분석 완료이며 수정 및 개선 검증 완료가 아니다.
