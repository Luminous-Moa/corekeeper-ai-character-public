# 게임 행동 판단: LLM 에이전트 선례 독립 조사

조사일: 2026-11-03. 원저자 논문·공식 저장소·소스만 근거로 사용했다. 게임 실행, 설치, 유료 모델 API 호출은 하지 않았다. 아래 성과는 저자 보고이며 이번 조사에서 재현하지 않았다. 논문의 실험 버전과 현재 저장소 구현을 구분한다.

## 핵심 비교

| 사례 | 판단과 몸 조작의 구조 | 확인된 성과·조건 | 재사용 가치와 한계 |
|---|---|---|---|
| Voyager | GPT-4가 목표를 정하고 JavaScript 행동 코드를 생성·수정한다. 성공한 코드를 스킬 라이브러리에 저장·검색·조합하고 Mineflayer API로 실행한다. 고정 명령만 선택하는 구조가 아니다. | 160회 prompting iteration 안에 고유 아이템 63종, 비교군 대비 아이템 3.3배·이동거리 2.3배, 목재 기술 단계 도달 15.3배 빠름을 보고한다. 마지막 수치는 실제 시간이나 반응속도가 아닌 prompting iteration 기준이다. 비교군은 연구자가 Minecraft에 맞게 구현한 ReAct·Reflexion·AutoGPT 등이다. | 장기 목표·경험 축적·실패 피드백의 선례. 논문은 고수준 API를 사용하므로 픽셀→저수준 제어 연구와 직접 비교하지 않는다고 명시한다. 빠른 판단 모델의 실시간 회피나 인간다운 몸짓을 입증한 것은 아니다. |
| Mindcraft / MindServer | 현재 구현은 LLM이 파라미터 있는 명령을 선택하고 Mineflayer 스킬이 실행한다. 코드 생성 `!newAction`은 선택 기능이며 기본 비활성화. 자기보존·도주·방어 등은 프로그램 자동 모드로 개입한다. MindServer는 통신·외부 제어·웹 UI의 허브다. | 관련 MineCollab 논문은 요리·제작·건축 협업을 평가한다. 예컨대 제작 표의 Claude 3.5 성공률은 80%, GPT-4o는 32%이며, 요리는 각각 80%, 63.33%다. 이는 지정된 과제·자원·협업 조건의 결과이지 일반 생존 성공률이 아니다. | 준비된 풍부한 행동 API, 명령 인자, 실행 중단, 자동 반응층의 실질적 소스 참고 가치가 크다. 별도 신경망이 고빈도 후보를 순위화하는 구조라는 근거는 없다. 최신 코드에 과거 논문의 성과를 그대로 귀속하면 안 된다. |
| STEVE-1 | 텍스트를 MineCLIP 목표 표현으로 바꾸고, 학습된 VPT 계열 정책이 화면 픽셀에서 키·마우스 행동을 예측한다. LLM 코드 생성이나 고정 함수 선택기가 아니다. | NeurIPS 2023 논문은 초기 게임 평가 13개 과제 중 12개를 수행했다고 보고한다. 프로그램 지표 실험은 조건별 10개 seed, 3,000 timestep(게임 시간 2.5분) 등을 사용한다. 긴 과제에는 prompt chaining이 도움되지만 집 짓기·다이아몬드 획득 등은 한계로 명시한다. | 언어 목표와 실제 운동 정책을 분리하는 선례. Minecraft 전용 VPT·MineCLIP 선행 학습에 의존하므로 Core Keeper에 가중치를 그대로 옮길 수 있다는 근거는 없다. 상위 LLM과의 자동 연결은 논문의 향후 연구 방향이다. |

Voyager 출처: [공식 논문 §2–3, 부록](https://arxiv.org/html/2305.16291v2), [원저자 프로젝트](https://voyager.minedojo.org/), [공식 코드](https://github.com/MineDojo/Voyager).

Mindcraft 성과 출처: [Collaborating Action by Action, §4–5 및 표 4–7](https://arxiv.org/html/2504.17950v1), [공식 저장소](https://github.com/mindcraft-bots/mindcraft). 건축 표의 수치를 단순한 과제 성공률로 읽으면 안 된다. 구현 설명상 건축 보상은 설계도 블록 완성 비율이고 제작·요리는 0/1 판정이다. 위 표에는 혼동을 피하기 위해 제작·요리 수치만 실었다.

STEVE-1 출처: [NeurIPS 최종 논문 §3–5, 부록 B/E](https://papers.nips.cc/paper_files/paper/2023/file/dd03f856fc7f2efeec8b1c796284561d-Paper-Conference.pdf), [원저자 코드](https://github.com/Shalev-Lifshitz/STEVE-1), [공식 프로젝트](https://sites.google.com/view/steve-1). 저자의 60달러 학습비는 기존 대규모 VPT·MineCLIP 사전학습 비용까지 포함한 총개발비가 아니다.

## Mindcraft 소스로 확인한 역할 분리

GitHub 연결 도구로 확인한 develop tree SHA: `e1c1fc3ffa481506c2445fc639e16dba504b5920`. 다음 링크는 해당 시점에 고정했다.

- [commands/actions.js](https://github.com/mindcraft-bots/mindcraft/blob/e1c1fc3ffa481506c2445fc639e16dba504b5920/src/agent/commands/actions.js): `goToCoordinates`, `followPlayer`, `searchForBlock`, `collectBlocks`, `craftRecipe`, `equip`, `attack` 등 명령과 인자 정의가 있다. `newAction`은 설정 검사 후 코드 생성 경로로 연결된다.
- [modes.js](https://github.com/mindcraft-bots/mindcraft/blob/e1c1fc3ffa481506c2445fc639e16dba504b5920/src/agent/modes.js): `self_preservation`, `cowardice`, `self_defense`는 기존 행동에 개입할 수 있다. `idle_staring`은 주변 엔티티를 보는 대기 동작이다. 이 기능의 존재는 자연스러움에 대한 사용자 평가 결과와 다르다.
- [library/skills.js](https://github.com/mindcraft-bots/mindcraft/blob/e1c1fc3ffa481506c2445fc639e16dba504b5920/src/agent/library/skills.js): `attackEntity`와 `defendSelf`는 `bot.pvp.attack(...)`을 호출한다. 방어 반복문의 500ms 대기 값은 LLM 추론 지연 측정값이나 전체 시스템 반응시간 보장이 아니다.
- [mindcraft/mindserver.js](https://github.com/mindcraft-bots/mindcraft/blob/e1c1fc3ffa481506c2445fc639e16dba504b5920/src/mindcraft/mindserver.js): Socket.IO/Express 기반 통신 허브·외부 제어 API·웹 앱 호스트다. MindServer 자체를 별도의 빠른 판단 AI로 부르면 부정확하다.

## 사용자 구상과의 연결 — 조사자의 해석

세 사례를 합치면 **언어 모델의 목표·기억 관리, 실행 가능한 행동 인터페이스, 저수준 제어를 분리하는 설계에는 선례가 있다.** 특히 Mindcraft는 LLM 판단을 기다리지 않고 프로그램 반응층이 개입하는 예이고, STEVE-1은 별도 학습 정책이 실제 입력을 만드는 예다. Voyager는 성공한 행동 절차를 축적하고 재사용하는 예다.

그러나 **“LLM이 목표와 지식을 정리 → Jev 같은 빠른 모델이 현재 가능한 풍부한 후보 중에서 실시간 세부 행동 선택 → 프로그램이 몸 조작”이라는 정확한 3단 구성이 이 자료들에서 그대로 검증된 것은 아니다.** 현재 가능한 후보를 상태마다 생성·필터링하는 방법, 빠른 모델의 선택 품질, 판단 주기, 오래된 판단의 폐기, 행동 취소·재시도 계약은 별도로 설계하고 검증해야 한다. 이는 조사 결과에서 도출한 구현 과제이며 원논문의 검증 결과가 아니다.

## 과장하면 안 되는 점

1. 공격 API·좀비 전투 예시의 존재와 복잡한 실시간 전투 성능 검증은 다르다. 이 조사에서 회피 타이밍, 보스전, 동시 위협 대응의 비교 평가를 확인하지 못했다.
2. 키·마우스 출력이나 대기 시 시선 이동이 있다고 사람처럼 자연스럽게 보인다는 결론은 나오지 않는다. 세 자료에서 그 목적의 사람 대상 자연스러움 평가를 확인하지 못했다.
3. Minecraft의 구조화 상태·경로 탐색·제작 API가 제공하는 능력과 LLM 자체 능력을 분리해야 한다. API 기반 아이템 성과를 픽셀 입력 에이전트와 직접 비교하면 안 된다.
4. 세 사례는 Core Keeper 호환성, 사용자의 Jev 모델 지연·정확도, 새 게임의 학습비를 입증하지 않는다. STEVE-1은 직접적인 LLM 에이전트라기보다 연결 가능한 저수준 정책의 비교 사례다.
5. 현재 저장소 기능과 2023/2025년 논문 실험 조건은 같은 버전이라고 가정하지 않았다. 본 조사에서는 실행이나 재현 검증을 하지 않았다.
