## 목표와 완료 의미

**모델이 적의 보이는 공격 전조와 실제 장비 상태를 읽고, 짧은 공격·이동·이탈을 선택하여 실행하고, 전투가 끝나면 목표를 이어 가게 한다.** 첫 검증 대상은 버섯 야수와 근접전이다. 원거리 무기, 여러 적·동료, 반복 부활과 준비 부족까지 단계적으로 확장한다.

성공은 무사망이나 공격 횟수 증가가 아니다. 상황에 맞지 않는 선택·번복이 줄고, 고른 행동이 정확히 실행되며, 싸울 수 있는 상황에서 공격 기회를 이용하고 불리하면 모델이 실제 이탈을 선택할 수 있는지가 기준이다. 피해·처치·생존은 함께 보는 결과 지표다.

현재 사용자가 정한 **기억 검색 등 열린 작업 마무리 → 리팩토링 → 다음 기능 작업** 순서를 유지한다. 이번에는 계획 문서만 만든다. 전투 구현 시점의 기준 버전은 리팩토링 완료 뒤 다시 고정한다.

## 단계 0 — 기준과 관측 가능성을 먼저 확인

**결과:** 구현에 쓸 적 상태·입력·측정 지점이 실제로 존재하는지 확인한 표와 비교 시험 기준.

- 리팩토링 이후 코드·설치본·설정·캐릭터와 장비를 고정한다. 이전 진단에서 해결된 stale 계속하기 검사와 무기 기본 피해 읽기를 보존한다.
- 버섯 야수의 준비→발동→회복 동작을 실제 화면과 게임 상태에 대조한다. 참고본 ChargeAttackStateCD는 조사 시작점이며 실제 해당 적에 부착됐다는 가정으로 구현하지 않는다.
- 첫 근접 비교는 정상 무기·일정한 기술/배고픔으로 시작해 조작 능력과 장비 부족을 분리한다. 부서진 무기 조건은 별도 시험으로 둔다.
- 사람 화면에서 알 수 있는 공격 방향·전조·공격 범위를 관측할 수 있는지 확인한다. 정확한 남은 시간은 관측 또는 검증된 표시로 추정 가능한 경우에만 근거·오차와 함께 준다. 비공개 AI 목표·미래 공격·화면 밖 적을 읽어 넣지 않는다.
- 전조 발견→관측 준비→모델 응답→행동 적용→실제 이동/타격까지 총 지연을 잰다. 기존 0.26초는 API 응답 중앙값일 뿐 전체 반응 시간이 아니다. 적의 공격 시작까지 남은 시간과 p95 총 지연을 비교한다.
- 기존 전투 로그에 필요한 연결만 더할 위치를 정한다: 관측 시각, 후보/행동 식별자, 응답·선택, 적용/폐기 이유, 실제 손무기·내구, 타격/피해/사망. 직접 DOWN을 전투 종료 집계에 포함해 downs 0 누락을 막고, 사망 직전 행동도 보존한다. 현재 로그 스위치와 분할 방식을 재사용한다.

**통과 기준:** 해당 적의 가시적인 전조와 상태 대응, 동작 입력과 완료 신호, 총 지연을 확인한다. 전조를 못 읽거나 반응 시간이 부족하면 그 한계를 먼저 보고하고, 관측 가능한 거리·방향과 사전 거리 유지로 시험 범위를 조정한다. 정밀 회피가 가능한 것처럼 꾸미거나 자동 회피로 바꾸지 않는다.

## 단계 1 — 판단에 주는 사실과 피해 추정을 맞추기

**결과:** 모델이 지금의 무장·위험·추정 신뢰도를 오해하지 않는 공통 전투 관측.

- 실제 손에 든 무기, 가방의 대체 무기, 내구·파손, 무기 레벨, 현재 사용 가능 상태를 분리한다. 상위 보고의 wpn도 소지 무기와 사용 중 무기를 구분한다.
- 파손·무기 교체 시 공격 사실과 관찰 통계를 갱신한다. 실제 공격자·대상·무기를 게임 피해 사건에서 연결할 수 있는지 조사한다. 연결할 수 없는 다수전 HP 변화는 출처 불명으로 두고 내 타격 평균에 넣지 않는다.
- 받은 피해도 확정 공격자와 근처에 있던 적을 구분한다. 단일 적 근접 추론은 추론이라고 표시하고, 여러 적·환경 피해가 섞인 값을 특정 적 공격력으로 확정하지 않는다.
- 회복이 섞인 순체력 감소를 총 피격량으로, 여러 타격이 합쳐지거나 막타에서 잘린 체력 감소를 한 번의 무기 피해로 확정하지 않는다. 체력 변화 관측 간격과 무기의 실제 발동 간격도 구분한다. 사건을 분리할 수 없으면 순변화/모름으로 보고한다.
- 이전 오염 가능 통계는 일괄 사실로 승계하지 않는다. 출처·장비 상태가 검증된 표본과 분리하고, 검증할 수 없으면 새 조건별 관측이 쌓일 때까지 낮은 신뢰 또는 모름으로 둔다. 원본 기억은 보존한다.
- 무기 레벨을 기본 피해 조회에 넘긴다. 배고픔·버프·적 방어 등을 반영하지 않은 값은 기본값으로 표시한다. 관측값도 다른 상태의 값을 현재 실제 피해처럼 말하지 않는다. 불확실한 처치 시간은 범위/근거/모름을 표시한다.
- 새 공격 후보와 계속하기에 같은 최신 위험·무기 사실을 준다. ‘쓸 무기 없음’은 ‘현재 지원하는 정상 근접 무기 없음’처럼 실제 능력 범위에 맞춘다.

**통과 기준:** 무기 파손·교체 직후 후보와 실행 장비가 일치한다. 동료의 타격이 내 무기 피해로 쌓이지 않고, 불명 피해를 확정 공격력으로 보고하지 않는다. 같은 적/무기 조건에서 표시 추정과 실제 결과를 대조한다.

## 단계 2 — 버섯 야수 한 종류에서 짧은 근접 컨트롤 완성

**결과:** 관측→모델 선택→짧은 실행→다음 관측이 연결된 첫 전투 흐름.

관측에는 적의 보이는 준비/발동/회복 상태, 공격 방향·위험 구역, 내 위치가 그 안인지, 무기 사거리·현재 동작 상태, 주변의 이동 가능한 칸을 추가한다. 확인되지 않은 상태는 모름이며, 예전 방향은 예전 관측임을 표시한다.

처음 추가할 후보는 다음과 같다. 이동 거리·지속 시간은 고정 확정값이 아니라 단계 0에서 실제 속도와 전조 길이를 보고 정한다.

| 후보 | 실행 약속 | 모델에 보여 줄 사실 |
|---|---|---|
| 한 번 휘두르기 | 지정 적을 겨누고 게임이 한 번의 공격으로 수용한 동작만 실행. 몰래 추격·반복 공격하지 않음 | 사거리, 공격 가능 여부, 현재 적 상태, 소요/취소 가능한 시점 |
| 짧게 옆/뒤로 이동 | 명시한 칸/구간까지만 이동. 지형으로 불가능하면 이유를 반환 | 실제 목적지·이동 길이·각 적과 거리 변화·알려진 공격 구역 교차 |
| 사거리까지 접근 | 명시된 짧은 접근 구간까지만 실행 | 도착 거리, 이동 중 보이는 위험, 공격은 별도 선택이라는 사실 |
| 유지/짧게 관찰 | 현재 유효 동작을 이어 가거나 명시된 짧은 대기 | 진행 정도, 실제 끝 조건, 새로 생긴 위험 |

‘한 번 공격’은 명중 여부로만 끝을 판단하지 않는다. 빗나가도 실제 한 번의 휘두르기가 끝나면 반환하며, 입력을 계속 눌러 두 번 때리지 않도록 실제 게임 입력·쿨다운과 대조한다.

짧은 동작은 실제 게임의 취소 가능한 시점에 전환한다. 긴 기술에서 쓰던 대기 규칙을 그대로 이중 적용하지 않고, 공격 준비·발동·회복 중 어떤 부분을 게임이 끊을 수 있는지 확인한다. **한 번 공격 뒤 자동으로 피하는 복합 행동은 만들지 않는다.** 다음 회피도 모델이 선택한다.

동작 속도는 캐릭터의 현재 게임 타이머를 우선한다. 읽지 못하면 해당 캐릭터의 최근 실제 휘두르기 간격을 쓰며, 둘 다 없으면 동작 상태·속도를 모름으로 표시해 관측부터 확보한다. 장비·음식 보너스를 별도로 추산해 확정 타이머로 만들지 않는다. 기존의 ‘경계를 2초 기다리면 강제 적용’ 경로는 짧은 동작에 그대로 승계하지 않는다. 정상 경계·취소 가능 시점·입력 해제·실행 실패 반환을 구분해, 오래 기다렸다는 이유로 불가능한 취소나 추가 공격이 발생하지 않게 한다. 정확한 대기 한계는 단계 0의 실제 동작 측정 뒤 정한다.

기존의 단순 지속 공격은 약한 적 등 기존 유효 상황에 유지한다. 새 짧은 후보는 먼저 강한 적 근접전처럼 필요가 있는 문맥에 노출한다. 노출 기준은 기능 도입 범위이며 강한 적의 고정 블랙리스트가 아니다. 동일 행동의 키·순서를 안정적으로 유지하고, 신규/계속 후보의 의미가 같게 한다.

요청 중 적이 움직인 것만으로 응답을 모두 버리지는 않는다. 적용 시 대상 존재·사용 무기·행동 식별·물리적 실행 가능성을 검사하고, 정말 무효인 동작만 이유와 함께 재판단한다. 유효한 모델 선택을 더 안전한 다른 행동으로 바꿔 실행하지 않는다. 짧은 행동이 완료된 뒤 도착한 계속하기는 종료된 행동을 다시 시작시키지 않는다.

비동기 처리의 약속도 함께 구현한다. 요청에는 관측 시각·실행 중 행동의 고유 실행 번호·대상·무기·후보가 뜻하는 목적지를 연결한다. 같은 적에게 같은 공격 키로 다시 휘둘러도 이전 실행과 새 실행을 구분한다. 계속하기는 요청 당시의 실행 하나에만 적용하고, 새 한 번 공격은 모델이 새 공격 후보를 고른 경우에만 시작한다. 같은 응답을 두 번 적용하지 않는다. 경계를 기다리는 선택과 그사이 도착한 새 선택은 하나의 입력 소유자에서 처리하고, 실제 적용·무효·대체된 대기 요청을 기록한다. 그 사이 실행이 바뀌어 더는 유효하지 않은 계속하기는 사유와 함께 재판단하며, 과거 선택을 새 행동의 유지로 바꾸지 않는다.

| 비동기 시험 조건 | 기대 결과 |
|---|---|
| 응답 전에 한 번 공격/이동이 종료됨 | 늦은 계속하기가 같은 행동을 재시작하지 않음 |
| 같은 대상·같은 키로 새 실행이 시작됨 | 이전 실행의 계속하기가 새 실행을 계속시키거나 대기 중인 새 전환을 취소하지 않음 |
| 대기 중 선택이 적용된 직후 이전 관측의 답이 도착함 | 실행 번호·전제 대조 후 실제 유효한 선택만 적용, 이유 기록 |
| 적 소멸·무기 파손/교체·이동 경로 막힘 | 실행 불가능 조건을 사실대로 반환, 임의의 다른 전술로 교체하지 않음 |
| 응답 지연·중복 처리·동작 타이머 읽기 실패 | 추가 타격/발사와 불가능한 강제 취소 없음, 기존 늦음 반사와 재판단 경로 유지 |

**통과 기준:** 모델이 공격 기회를 보고 한 번 공격하고, 다음 선택으로 공격 방향 밖에 이동하는 연결을 실제로 관측한다. 각 동작은 선택한 횟수·목적지대로 끝난다. 총 지연이 짧은 행동의 효과를 지우지 않는지 확인한다. 한 번의 성공은 기능 연결 증거로만 쓰고 전투 개선은 반복 비교로 판정한다.

## 단계 3 — 후퇴를 실제 방향·목적지 선택으로 바꾸기

**결과:** 코어가 위험한 상황에서도 모델이 다른 이탈 방향을 선택할 수 있다.

- 기존 고정 복귀는 정확히 ‘코어로 이동’으로 이름을 바꾸고 목적지를 표시한다. 코어가 안전하다고 보장하는 설명을 없앤다. 사용자 지정 기지와 코어도 구분한다.
- 화면 안의 열린 경로 중 방향이 다른 몇 개의 짧은 이탈 후보를 구성한다. 각 후보에 목적지·경로 길이·보이는 모든 관련 적과 가까워지는지·공격 구역을 지나는지·막다른 길 여부·확인 가능한 범위를 준다. 가장 가까운 적 하나만 보고 안전하다고 평가하지 않는다.
- 이동 가능한 후보를 전술적으로 위험하다는 이유만으로 자동 제거하거나 실행기로 몰래 교체하지 않는다. 물리적 불가능은 후보 구성에서 제외하고, 위험 차이는 모델의 선택 근거로 준다. 전역 안전 지도나 미래 적 위치는 가정하지 않는다.
- 짧은 거리 벌리기 이후에도 이탈을 이어 갈 의미 있는 후보가 남게 한다. 기존 4.5칸 문턱을 벗어났다는 이유만으로 회피가 사라지고 공격/코어 복귀만 남는 전환을 없앤다.
- 상위 LLM에는 코어 주변 위협, 반복 쓰러짐 위치, 실제 장비 부족, 방금 이탈 결과를 요약한다. 상위 응답을 기다리는 동안에도 하위 전투 판단은 계속한다. 상위 목표가 채집이라도 전투마다 적 쪽으로 복귀를 강제하지 않으며, 이탈·전투 뒤 이어 갈 원래 목표는 보존한다.

**통과 기준:** 기존 ‘적 쪽 코어 복귀’ 입력을 다시 평가해 경고·실제 이동이 일치한다. 코어가 적 뒤에 있는 실제 시험에서 모델이 옆/반대 방향 이탈을 선택할 수 있고 이후 목표 재개까지 이어진다. 여전히 위험한 복귀를 고르면 입력 충분성·후보 의미·모델 선택을 따로 기록하고 같은 조건으로 개선한다. 선택을 사후 강제로 고치는 것으로 통과시키지 않는다.

단계 2와 3은 첫 실전 개선 묶음이다. 짧은 회피를 만들고도 곧 위험한 코어 복귀로 돌아가면 첫 묶음 완료로 보지 않는다.

## 단계 4 — 원거리 무기와 장비 회복 연결

**결과:** 소지한 무기를 실제로 활용하고 파손 상태를 벗어날 선택을 제공한다.

- 첫 원거리 대상은 현재 시험에서 소지가 확인된 목제 석궁으로 좁힌다. 실제 사거리, 발사 입력, 발사 간격, 투사체·벽 차단, 탄/자원 필요 여부, 내구 감소를 게임에서 확인한다. 기존 근접 실행을 그대로 공유하지 않는다.
- ‘지정 무기로 한 번 발사’, ‘사거리 유지 위치로 짧게 이동’, ‘무기 교체’를 구별해 제시한다. 조준은 모델이 선택한 대상/방향을 입력으로 옮기는 실행이며, 다른 적 선택이나 자동 추격·자동 연속 회피를 수행하지 않는다.
- 정상 무기·부서진 무기·근접/원거리 선택의 장단점을 보여 준다. 선택한 무기를 손에 옮기는 과정과 소요 시간도 행동에 포함하고, 공격 중 파손 시 후보와 실행 상태를 즉시 갱신한다.
- 대체 장비가 없을 때는 상위 LLM이 제작·재료 준비를 고를 수 있도록 실제 부족 조건을 보고한다. 수리는 게임에서 접근 가능한 수리 방식·재료·시설·기존 구현을 확인한 뒤 지원 계획을 확정한다. 수리가 아직 미지원이면 가능한 것처럼 말하지 않고 교체/제작 경로를 사용한다.
- 석궁으로 원거리 흐름이 통과한 뒤 활 등 다른 소지 무기를 같은 입력 방식별로 확장한다. 마법·소환 등 별도 자원/조작이 필요한 군은 추가 범위를 명시해 따로 결정한다. 모든 무기 지원을 이번 첫 버전의 완료 조건으로 삼지 않는다.

**통과 기준:** 실제 석궁을 손에 들고 사거리 밖으로 불필요하게 붙지 않으며 발사→명중 또는 빗나감→다음 판단을 확인한다. 파손 검+정상 석궁 조건에서 두 선택의 능력·상태가 정확히 보이고 석궁을 실제 선택·실행할 수 있다. 무기 부족→교체/제작 준비→전투 또는 원래 목표 복귀가 한 번 연결된다.

## 단계 5 — 무리전·동료와 반복 비교 후 적용 판단

- 적 한 마리로 연결 검증을 끝낸 뒤 강한 적+약한 적, 벽·좁은 길, 코어 주변 위협, 동료 동시 공격, AI 네 명 동시 상황 순으로 넓힌다. 정보량·후보 수 증가가 준비 비용과 응답 지연을 늘리는지도 본다.
- 비교는 같은 월드 사본·위치·적 구성·캐릭터 기술·HP·배고픔·무기 레벨/내구·모델/설정으로 기존 버전과 개선 버전을 실행한다. 플레이 중 세계가 달라진 경우 그 차이를 기록하고 같은 조건 비교라고 말하지 않는다.
- 대표 조건마다 우선 같은 횟수로 반복한다(초기 제안: 버전별 5회). 효과가 불명확하면 불명확으로 남기고, 비용·게임 시간 안에서 추가 확인 범위를 정한다. 무사망이나 임의 승률 수치를 성공 기준으로 선결정하지 않는다.
- 핵심 평가는 입력→선택→실행을 읽어 그 상황에서 부적절한 번복, 위험 정보 무시, 선택과 실제 동작 불일치를 구분하는 것이다. 단순 전환 횟수나 deaths만 줄인 결과를 개선으로 인정하지 않는다.

| 검증 축 | 확인할 결과 |
|---|---|
| 실행 정확성 | 한 번 공격/발사 횟수, 선택 목적지, 실제 무기, 종료된 행동 계속 응답의 정상 처리 |
| 판단 적합성 | 전조에 맞는 이동, 가능한 공격 기회 활용, 새 사실 없는 번복, 적 쪽 복귀 이유와 입력 충분성 |
| 전투 결과 | 처치/이탈, 받은 피해·회복 자원·장비 소모, 쓰러짐, 목표 진행량 |
| 시간·비용 | 총 반응 p50/p95, 관측 준비 비용, 네 AI 동시 처리, 호출/토큰 비용과 기존 상한 |
| 회귀 | 약한 적 지속 공격, 목표 없는 자기방어, 먹기, 채집·이동 재개, 동료 피해 학습 분리 |

검증은 작성자 기능 확인 뒤 독립 검수자가 합의 기준과 실제 결과를 대조한다. 결함 수정 뒤에는 해당 실패 조건과 연결된 대표 흐름을 다시 실행한다. 사용자에게 비교 결과와 남은 한계를 제시한 다음 적용 여부를 결정한다. 이번 계획 작성에서는 시험·수정·배포를 실행하지 않는다.

## 작업 경계와 의존성

구현 역할은 기존 코드를 활용해 관측·후보/응답·몸 실행·경험/상위 보고 네 책임으로 나눈다. 현재 AIBodySkills의 관측/공격, AIDecisions의 후보/응답, AICombat의 상태/이동, AIExperience·AIPlanner의 기록/보고가 관련되지만 리팩토링 후 위치를 다시 확인한다. 별도 범용 전투 엔진이나 대형 전략 시스템을 만드는 계획은 아니다.

추천 순서는 **기준·관측 확인 → 사실/추정 정합성 → 짧은 근접 제어+실제 이탈 → 석궁/장비 회복 → 무리전 비교**다. 각 단계가 다음 단계의 검증 가능한 입력을 만든다. 첫 핵심 성과는 '버섯 야수 앞에서 전조를 보고 한 번 공격·이동을 모델이 선택하고, 이탈 후 목표를 이어 가는 실제 흐름'이다.

현재 확정할 수 없는 것은 전조 필드와 화면의 대응, 한 번 입력의 정확한 끝, 반응 시간의 여유, 피해 사건의 공격자 식별, 석궁의 실제 사용 조건, 수리 지원 범위다. 이들은 조사·실기 결과로 정할 구현 조건이며 사용자 결정처럼 기록하지 않는다. 자동 전술 도입, 모델/비용 정책 변경, 정보 공개 범위 확대는 이 계획 밖의 사용자 선택이다.
