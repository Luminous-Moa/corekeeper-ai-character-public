# 코어키퍼 전투 개선에 참고할 내용

TerraBlind에서 참고할 핵심은 **게임 상태를 모델의 비교 판단에 맞게 가공하고, 선택된 행동이 실제로 실행되는 과정을 분명히 연결하는 것**이다. 다음 내용은 기존 전투 개선 계획을 바탕으로 한 비교이며, 새 구현 결정이나 자동 전술 도입 승인이 아니다.

기준: [2026-11-04 전투 개선 계획](../2026-11-04-전투-개선-계획/2-개선계획.md), [전투 현황 진단](../2026-11-04-전투-현황-진단/2-상세진단.md), [TerraBlind 전투 상세](01-전투.md).

## 이미 정한 방향과 만나는 부분

기존 코어키퍼 계획은 보이는 전조·실제 장비 상태를 제공하고, 한 번 공격·짧은 이동·이탈·원거리 발사를 모델이 선택하는 방향이다. TerraBlind의 입력과 후보 설계는 이 방향을 구체화하는 참고가 된다. 자동 공격·회복·안전 방향 강제와 같은 다른 정책까지 함께 가져올 필요는 없다.

| 개선 항목 | TerraBlind에서 참고할 구현 | 코어키퍼에 맞춰 확인할 내용 |
|---|---|---|
| 상대 움직임 | 속도 벡터와 최근 최고 속도를 함께 제공 | 보이는 이동 방향·접근 속도와 실제 공격 전조를 구분. 화면과 상태 필드가 대응하는지 먼저 확인 |
| 공격 위험 | 충돌 예상 시간과 상대 피해 규모 | 접촉 피해·근접 범위·돌진·투사체를 나눔. 버섯 야수의 실제 준비·발동·회복 구간 확인 |
| 여러 위협 | 보스·부위·투사체를 함께 고려 | 가장 가까운 적뿐 아니라 행동 경로에 영향을 주는 적과 공격 구역을 포함 |
| 이동 후보 | 방향별 변위·거리 변화·통로 위험 설명 | 짧은 이동의 실제 목적지, 경로, 도착까지 시간, 위험 구역 통과 여부를 연결 |
| 공격 후보 | PvP의 무기·조준·발사 결합 선택 | 첫 대상 석궁의 사거리·탄속·막힘·재사용 시간·내구·자원 조건을 실제 실행과 맞춤 |
| 응답 유효성 | 요청별 후보 사전·시퀀스·기한 | 요청을 보낸 당시의 행동과 응답 적용 시점의 행동을 구별. 다른 대상으로 바뀐 뒤 옛 continue를 적용하지 않음 |
| 실행 결과 | 선택과 실제 적용, 변경 이유 기록 | 물리적 실패·공격 종료·경로 막힘·늦은 응답·모델 선택 문제를 나눠 기록 |

## 정보 세 묶음을 분리해서 설계하기

**관측 사실**은 실제로 보거나 확인한 것이다. 위치·체력·장비·보이는 공격 전조·투사체 위치처럼 사실의 시각과 출처를 붙일 수 있어야 한다.

**근사 예측**은 관측을 바탕으로 계산한 것이다. 예를 들어 현재 속도가 유지되면 어느 시점에 접근하는지, 특정 경로를 택하면 공격 범위를 지나는지다. 갑작스러운 방향 전환이나 아직 시작되지 않은 공격까지 확정된 미래처럼 말하지 않는다.

**선택지 설명**은 실제 행동 실행기의 약속이다. 한 번 공격인지 지속 공격인지, 어디까지 이동하는지, 도중에 중단할 수 있는지, 선택할 때와 실행할 때 어떤 조건을 다시 확인하는지가 일치해야 한다.

이 구분은 정보량을 늘리기 위한 분류가 아니다. 예측이 틀렸는지, 설명이 잘못됐는지, 모델이 위험을 알고도 선택했는지, 실행기가 다른 행동을 했는지를 판별하기 위해 필요하다.

## 후보 하나를 읽고 판단할 수 있게 만들기

다음은 **코어키퍼에서 검토할 수 있는 설명 형식의 예시**다. 현재 구현된 요청 스키마나 실게임 수치가 아니며, 필드명을 그대로 채택하자는 결정도 아니다.

| 정보 | 짧은 이동 후보에서 답해야 할 질문 |
|---|---|
| 행동의 정체 | 어느 방향의 어느 지점으로 이동하는가 |
| 실행 범위 | 한 걸음·정해진 거리·정해진 시간 중 무엇으로 끝나는가 |
| 실제 가능성 | 경로를 걸을 수 있는가, 장애물이나 다른 몸이 막는가 |
| 소요 시간 | 지금 속도로 끝내는 데 얼마나 걸리는가 |
| 주요 위협과 관계 | 어떤 적에게 가까워지며 어떤 적에게서 멀어지는가 |
| 공격 구역과 관계 | 지금 보이는 공격 범위나 투사체 경로를 통과하는가 |
| 다음 행동의 여유 | 도착지가 막다른 곳인가, 이어서 움직일 공간이 보이는가 |
| 예측 조건 | 현재 속도·현재 공격 상태가 유지된다는 가정인가 |
| 유효 기간 | 응답이 늦어졌을 때 재확인해야 할 조건은 무엇인가 |

현재 거리만 보고 ‘멀어지기’를 설명하면 그 길 중간을 적이 가로지르거나 다른 적 앞으로 들어가는 문제를 놓칠 수 있다. TerraBlind의 후보별 위험 설명은 이 차이를 드러내지만, 그 근사 계산식을 그대로 쓰면 같은 한계도 옮겨 온다.

## 근사 위험 계산을 읽을 때의 주의점

TerraBlind 보스 경로의 충돌시간은 현재 상대 속도를 이용한 단순 근사다. 각 축에 동시에 겹치는 시간 구간을 완전하게 검사하는 정밀 충돌 예측과 다르다. 후보의 0.6초 이동 변위 역시 매번 실제 물리를 시뮬레이션한 도착점이 아니다. 특정 방향의 투사체가 많다는 표현도 실제 명중 횟수와 동의어가 아니다.

코어키퍼에서는 우선 보이는 공격 범위와 짧은 실제 경로의 겹침처럼 확인 가능한 계산부터 시작하는 편이 기존 계획과 맞는다. 이후 추정값을 추가할 때에는 예측한 결과와 실제 실행 결과를 비교해야 한다. 자세한 식과 단순화는 [전투 문서](01-전투.md)에 있다.

## 기존 계획에 연결해 볼 확인 순서

1. 버섯 야수의 보이는 전조·공격 방향·범위·끝나는 시점이 어떤 실제 데이터로 확인되는지 조사한다.
2. 같은 장면에서 짧은 이동과 한 번 공격이 각각 무엇을 의미하는지 실행 기준을 고정한다.
3. 그 후보에 필요한 정보만 모으고, 확인된 사실과 추정치를 구분한다.
4. 관측→후보 구성→요청→응답→실행→행동 종료의 시간을 이어서 기록한다.
5. 모델 선택과 실제 적용이 일치하는지 먼저 확인하고, 같은 조건 반복 전투에서 피해·처치·이탈·목표 재개를 비교한다.

이 순서는 이미 작성된 개선 계획의 관측 확인·짧은 근접 제어·실제 이탈·석궁·무리전 검증을 읽는 보조 기준이다. 리팩토링 이후 구현 시점에 실제 파일 구조와 기준 버전을 다시 확인한다.
