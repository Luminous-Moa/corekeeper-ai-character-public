# TerraBlind 분석 문서 독립 검토

2026-11-04. 검토 대상은 00~04 문서이며, TerraBlind 기준 커밋은 `0859ca29aedea7bb48324c68eaece35b629c6d37`이다. 소스 사본의 HEAD를 직접 확인했다. 코어키퍼 적용 해석은 기존 `2026-11-04-전투-개선-계획/2-개선계획.md`와 대조했다. 이번 검토에서 제품 코드·원본 참고 저장소·기존 개선 계획은 수정하지 않았다.

## 판정

**최종 판정: 통과. 중대 오류는 발견하지 않았고, 경계 배율 설명 1건과 사소한 보완 2건은 모두 반영된 것을 재확인했다. 미해결 수정 요청은 없다.** 아래 지적은 검토 이력으로 남긴다. 위치는 최초 검토본 기준이다.

문서는 실제 활성 호출과 옛 질문 정의를 분리하며, 수집한 데이터와 실제 전송한 데이터를 구분한다. 보스·일반 몬스터·PvP·광맥 채굴·벌목의 의사결정 주체를 하나로 묶지 않는다. 예시 요청은 실측 캡처로 주장하지 않으며, 제작자 시연과 제삼자의 직접 설치 후기를 구분한다. 사용자 프로젝트의 전술 판단 권한과 보이는 정보 원칙을 변경하기로 결정한 문서로도 읽히지 않는다.

이는 고정 커밋과 문서의 정합성 판정이다. 게임 실행, 실제 API 요청, 성능 측정, 영상 전편 시청에 의한 동작 검증은 수행하지 않았다.

## 중대

발견하지 못했다. 분석의 중심 결론을 뒤집는 호출 경로 혼동, 단위 혼동, 실사용 성능의 과장, 사용자 정책의 무단 변경은 확인되지 않았다.

### R1. PvP의 `.075` 배율에는 월드 경계 예외가 있다

- 위치: `01-전투.md:176`, `01-전투.md:406`.
- 현재 설명: PvP가 `.075` 배율로 훨씬 작은 경계 여유를 사용한다고 요약한다.
- 근거: [GameMovement.cs:25](https://github.com/Reisenbug/TerraBlind/blob/0859ca29aedea7bb48324c68eaece35b629c6d37/Jev/Port/GameMovement.cs#L25-L40). 수평·상단 reserve에 배율을 적용하고, 아래쪽 실체 거리의 `4*16`에도 배율을 적용한다. 그러나 월드 가장자리의 추가 `40*16`은 고정이다. 특히 아래 월드 경계는 `world.Down <= (4+40)*16`이므로 `.075`를 적용하지 않는다.
- 영향: PvP의 모든 경계 제한이 보스의 7.5%라고 오독하면, 실제 후보 제거 조건을 잘못 옮길 수 있다.
- 정정 제안: “PvP는 수평·상단 여유와 아래 실체 여유를 `.075`로 줄인다. 월드 가장자리의 40타일 여유는 유지되며, 아래 월드 경계는 총 44타일로 고정된다”를 추가한다. 기존 보스 `reserveScale=1` 수식은 맞다.

### S1. 보스 종료 뒤 이전 무기 슬롯 복원은 조건부다

- 위치: `01-전투.md:314`.
- 근거: [ProjectileAim.cs:13](https://github.com/Reisenbug/TerraBlind/blob/0859ca29aedea7bb48324c68eaece35b629c6d37/Jev/Port/ProjectileAim.cs#L13-L41). 자동 선택 뒤 현재 슬롯이 바뀌면 `_autoSlot=-1`로 만든다. `RestoreWeapon()`도 자동 슬롯이 유효하고 현재 슬롯과 같으며 이전 슬롯이 있어야 복원한다.
- 정정 제안: “자동 선택한 슬롯이 유지되는 경우 종료 후 이전 슬롯을 복원한다. 중간에 슬롯을 바꾼 경우에는 복원을 생략한다.”
- 영향: 일반적인 자동 선택 흐름의 설명은 맞지만, 사용자가 바꾼 슬롯도 무조건 되돌린다는 인상을 줄일 수 있다.

### S2. 사례 모음·프로젝트 디렉터리 행에 직접 출처가 없다

- 위치: `03-전투성능과후기.md:15`.
- 근거: 해당 행은 등재 사실을 언급하지만 아래 출처 목록은 영상·README·LINUX DO·GitHub 이슈만 제공한다.
- 정정 제안: 조사자가 실제 확인한 사례 모음의 직접 링크를 행에 추가하거나, 성능 판단에 추가 증거를 주지 않는 이 행을 제거한다.
- 영향: 결론은 바뀌지 않지만 독자가 등재 사실을 재확인하기 어렵다.
- 반영 확인: [Jev 사례 모음](https://anandi1989.github.io/awesome-jev-usecases/)과 [프로젝트 디렉터리](https://jevhunt.com/tasks/workflow-automation/)에 TerraBlind가 등재되어 있다. 두 곳의 소개는 독립적인 직접 설치·반복 전투 성능 검증의 근거로 확대하지 않았다.

## 수치·입력 검토

- 보스 원자료의 픽셀/프레임과 직렬화된 타일·타일/초, Y 부호 반전, 정수 절삭을 대조했다.
- 이름별 최근접 1개→200타일 제한, 투사체 30타일/96픽셀·접근 방향 필터→최대12개와 후보 설명에 쓰는 전체 투사체의 차이가 정확하다.
- 충돌 예상 시간의 축별 진입시간 최댓값, 600프레임 상한, 축 이탈시간 미검사 한계를 확인했다.
- `.6초` 고정 변위, 70타일 이내 적의 36프레임 외삽, ±5타일 거리 변화 분류, 탄막 10타일 근접 반경·4~36프레임 시간 제한을 대조했다. 이를 실제 물리 시뮬레이션·명중 확률로 과장하지 않는다.
- PvP 탄도 해의 2~90프레임·.5 간격·2.5% 속도 허용차, 1프레임 사선 검사와 400픽셀 조준점 설명을 대조했다.
- 벌목의 맨해튼 거리, 일반 Trees 한정, 가구 타일 최대16개, 나무당 최대2회 시도, 16회차·루프 시작 기준180초와 gather의 취소 토큰 deadline 구분을 확인했다.
- 벌목 Observe는 항상 wood/trees/player_cell/hp를 만든 뒤 error를 추가한다. 초기 wood 접근과 매 회차 gained 계산이 error 검사보다 앞이지만, 오류 장면을 Jev에 보내지 않는다는 문서 설명은 맞다. 목표 충족 시 enough가 error보다 먼저 판정되는 세부는 핵심 결론을 바꾸지 않는다.

## 후기·코어키퍼 적용 검토

[LINUX DO 9월20일 댓글](https://linux.do/t/topic/2916571?page=3)과 [9월21일 글](https://linux.do/t/topic/2931223)을 독립적으로 열람했다. 전자는 영상에 대한 움직임 평가·반응 지연 언급이고, 후자는 실시간 동작 응용의 기대와 영상 링크다. 두 자료에서 직접 설치·반복 전투 실험의 근거는 확인되지 않았다. 이를 영상 반응으로 분류한 03의 서술은 적절하다.

README의 Jev 보스 영상과 코드 전용 Wall of Flesh 진행은 다른 시연이다. 14분15초·3배속·DragonLens 전제와 무적 조건을 서로 옮겨 붙이지 않은 점을 확인했다. 03은 독립 설치 후기가 없다고 단정하지 않고 이번 검색에서 찾지 못했다고 제한한다. 영상 전체와 댓글 전체를 확인하지 못한 한계도 명시한다. GitHub API 전수 조회 및 광범위 검색 결과는 주 조사자가 수행한 확인 범위이며, 이 검토에서는 같은 검색을 전부 반복하지 않았다.

04의 관측 사실·근사 예측·선택지 설명 구분과 모델의 전술 선택 권한은 기존 개선 계획에 부합한다. 자동 사격·회복, 위험 방향의 사전 제거, 전체 게임 메모리 관측을 채택된 코어키퍼 정책으로 취급하지 않는다. 보이는 전조와 실제 실행을 먼저 검증한다는 적용 순서도 기존 계획을 바꾸지 않는다.

## 링크 점검과 검토 범위

주 조사자의 자동 점검은 소스 링크 84개와 로컬 링크 9개를 확인했다. 소스 끝줄을 넘어선 범위 링크 4건은 Intercept 끝43→41, PvpHistory 끝84→83, PvpTerrain 끝166→155, PvpDuel 끝431→418로 정정되었으며 이 검토에서도 해당 링크 정의를 다시 읽어 반영을 확인했다. 정정 후 주 조사자의 자동 재검사는 소스 파일 존재·앵커 끝줄, 로컬 링크, 코드 펜스 균형 모두 문제 0건이었다. 자동 검사 수치는 주 조사자가 전달한 별도 점검 결과이며 이 검토에서 자동 검사를 다시 돌린 결과로 주장하지 않는다.

본 검토의 소스 대조는 대표 흐름과 핵심 수식·상수·필터·입력/실행 경계에 집중했다. 모드 전체의 버그 탐색, 숨은 모든 실행 조합 증명, 서비스의 현재 API 계약 검증은 범위에 포함하지 않았다.

## 추가 검토 — 설정 부담과 후기 부족의 관계

사용자 추가 질문에 따라 작성된 `03-전투성능과후기.md:43`의 “설정 부담이 후기를 줄였을 가능성” 절만 원본과 추가 대조했다. **추가 절도 통과하며 새 수정 요청은 없다.**

- [Agent/README.md:1](https://github.com/Reisenbug/TerraBlind/blob/0859ca29aedea7bb48324c68eaece35b629c6d37/Agent/README.md#L1-L17)은 기본 Codex CLI·로그인 경로, 기존 로컬 인증 재사용, ChatGPT 로그인과 API 인증의 구분, Codex 비활성 시 OpenAI 호환 API 경로와 별도 TypeSafe 키를 명시한다. 문서는 이를 특정 구독 계정의 의무 가입으로 바꾸어 설명하지 않는다.
- 구현도 `Config.AgentUseCodex=true`, `NativeAgent`의 Codex/API 분기, `CodexAgent`의 `app-server --listen stdio://` 프로세스 실행과 일치한다. Claude Code는 확인한 기본 실행 경로의 필수 요소로 등장하지 않는다. 근거: [Config.cs:41](https://github.com/Reisenbug/TerraBlind/blob/0859ca29aedea7bb48324c68eaece35b629c6d37/Infra/Config.cs#L41-L53), [NativeAgent.cs:186](https://github.com/Reisenbug/TerraBlind/blob/0859ca29aedea7bb48324c68eaece35b629c6d37/Agent/NativeAgent.cs#L186-L199), [CodexAgent.cs:148](https://github.com/Reisenbug/TerraBlind/blob/0859ca29aedea7bb48324c68eaece35b629c6d37/Agent/CodexAgent.cs#L148).
- Jev 보스 제어의 별도 키·허가 경로와 벌목의 모드 설정 TypeSafe 키 검사는 앞서 추적한 실제 호출과 일치한다. 자연어 Agent를 쓰는 조건과 보스 제어 자체의 조건을 혼동하지 않는다.
- 설정 요소가 많아 잠재 사용자를 줄였을 수 있다는 부분은 명시적으로 가설·해석으로 제한했다. 단계별 이용 통계나 실제 이탈 사용자 조사 없이 후기 부족의 주원인, 사용자 구성, 전투 품질을 확정하지 않는다.

위 인증 설명은 고정 커밋이 문서화하고 구현한 통합 방식의 검토다. 현재 Codex 요금제별 권한이나 외부 서비스의 현재 제공 조건을 별도 확인했다는 의미는 아니다. 최종 통과 판정은 유지한다.
