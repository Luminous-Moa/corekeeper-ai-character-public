## 대표 문제·정상 흐름 5개

### 1. 모델의 ‘거리 벌리기 계속’이 실제로는 공격을 지속함 — 실행·응답 시차 문제

**10764~10792행, t=692.0~693.3, #826~#830.** HP102, 버섯HP105, 주변 슬라임도 보인다. #826이 공격을 골라 경계를 기다리는 동안 #827은 아직 실행 중인 거리 벌리기를 입력으로 받았다(버섯3.1칸, 거리 벌리기2.7초 남음). #827을 보낸 직후 #826이 적용되어 공격으로 바뀐다.

0.27초 뒤 #827은 **away_near ‘거리 벌리기 계속’**을 선택했지만 로그는 APPLY만 기록하고 실제 거리 벌리기 START는 없다. 바로 뒤 #828 SEND는 ‘공격 계속하기’를 제시하며, 693.3초에는 실제 버섯HP105→93 공격도 남는다. 모델 답에 적힌 행동과 실행이 어긋난 것이다.

설치 소스 `StaleReason`(1295행 이후)은 continue에서 ‘현재 실행 중인 기술이 존재하는가’만 검사하고 요청 당시 key와 현재 key를 비교하지 않는다. `Apply`(1352행 이후)의 continue는 새 기술을 만들지 않고 반환한다. 로그 흐름과 일치하는 원인이다. **모델이 거리를 벌리라고 했는데 공격을 고집했다고 평가하면 책임을 잘못 돌린다.** 이 현상은 확인됐지만 여기서 발생한 피해·죽음 전부의 원인이라는 뜻은 아니다.

### 2. 0.6초 동안 공격→대기→거리 벌리기→공격→복귀 — 모델 선택 의심과 시차가 섞임

**11019~11064행, t=712.3~713.6, #877~#881.** HP102 유지, BruteHP540와 버섯HP105가 동쪽에 있고 최근5초 피해 없음. 거리 벌리기가 3초로 종료된 뒤 최근접5.6칸에서는 회피 후보가 없어져 #877이 버섯 공격을 선택한다. #878은 버섯5.9칸·Brute5.6칸에서 기다리기(confidence0.08), #879는 가까워진 뒤 거리 벌리기(0.18), #880은 버섯3.5칸·Brute3.3칸에서 다시 공격(0.22), #881은 복귀(0.39)를 고른다.

실제로 공격0.45초→대기0.25초→거리 벌리기0.25초→공격0.17초로 바뀐다. 버섯 체력은105 그대로여서 이 짧은 공격들은 진척 없이 취소됐다. 체력 감소나 강한 적의 소실 없이 방금 만든 거리를 다시 좁히는 선택이라 **일관성 문제 의심**이 있다.

다만 입력 전문은 없고, 적 거리는 변했으며, #880은 거리 벌리기 START 전에 보낸 요청이다. ‘새 사실이 전혀 없는데 모델이 동일 입력으로 뒤집었다’고 확정할 수 없다. 설치 소스1817행의 회피 생성 조건은 최근접 `<4.5칸`; 로그에서도 #877/#878에는 away가 없다가 #879에는 생긴다. **모델 변동·후보 출입·입력/실행 시차를 함께 확인해야 하는 사례**다.

### 3. 이미 벌린 거리에서 코어 쪽으로 되돌아가 Brute와 다시 붙음 — 위험한 후보와 모델 선택 의심

**적 쪽으로 실제 되돌아간 것은 확인된다.** 이것은 전환 횟수나 패배 때문이 아니라 벌린 간격을 스스로 좁힌 구체 경로 때문에 문제 후보로 분류했다. 앞선 FULL #907에는 코어 복귀가 적 쪽이라는 사실도 있었다. 그러나 #911~#914의 그 설명 뒷부분은 잘려 있어 동일 경고가 각각 어떻게 제공됐는지는 확정하지 못한다.

‘코어까지 열린 길’은 경로가 통한다는 뜻이며 전투에서 벗어나는 안전한 길임을 보장하지 않는다. ‘물러나기(싸움을 떠남)’라는 후보명과 실제 적 쪽 이동이 충돌한다. 모델이 경고를 무시한 것인지, 방향·경로 정보가 부족했는지는 별도 확인이 필요하다. **이 장면의 부적절한 이동은 강하게 의심되지만 모델 단독 오판으로는 확정하지 않는다.** 반대로 더 오래 회피했다면 반드시 살았다고도 단정하지 않는다.
