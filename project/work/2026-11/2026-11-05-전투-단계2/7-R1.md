## 1. 고친 것 (커밋 fc8161b, 부모 33fb4bd)

### R1 — 전조로 요청을 끊을 때 보류 답을 버리던 경로
- **원인:** `ChargeTrigger`가 진행 중 요청을 끊을 때 부르는 `AIBrain.AbortRequest`(AIBrain.cs)가 이유와 상관없이 보류 답(`_held`)과 미리 받은 대기 답(`_queued`)을 버렸다. R3 원자료에서 `held switch dropped (charge anticipation)`가 6번 나왔다. `kept` 5번은 모두 끊을 요청이 없던 경우였다.
- **고침:**
  - `AIRunGate.AbortDropsWaiting(why)`를 두었다. 끊는 이유가 `AIRunGate.AbortForCharge`("charge anticipation")이면 요청만 끊고 보류 답·대기 답은 남긴다. 그 밖의 이유(목표 바뀜·쓰러짐·시간 초과·리셋·자기 방어 끝·미리 묻기)는 예전처럼 버린다.
  - 남긴 경우에는 `DECISION #n held switch kept (charge anticipation: only the request in flight is dropped)` 줄을 쓴다(대기 답이면 `queued answer kept`).
  - 보류 답은 긴급 재요청이 가는 동안에도 자기 경계에서 적용된다. `TryApplyHeld`는 이제 `AIRunGate.HeldApplyNow`(멈춤 → idle, 경계 → boundary, 2초 → timeout)를 쓴다. 규칙은 그대로다.
  - 긴급 답이 오면 실행 소유자 규칙(`ApplyOrHold`, `HeldSurvives`)으로 대체된다.
- **시험(core-tests C2, 동작 단위):** 뇌가 실제로 쓰는 규칙 함수로 순서를 따라간다.
  - 진행 중 요청 + 보류 답(away) + 전조 → 요청은 끊기고 보류 답은 남는다.
  - (a) 경계 전 긴급 답(짧은 이동, 긴급) → ApplyNow, 보류 답 대체. 긴 동작 긴급 답도 같다.
  - (b) 긴급 답 전에 경계가 오면 보류 답이 `boundary`로 시작한다(idle·2초 timeout도 확인).
  - (c) 버려지는 긴급 답(끝난 실행의 계속)은 보류 답을 남긴다.
  - (d) 다른 끊는 이유 9가지는 예전처럼 버린다.
  - 연결 확인(소스): AbortRequest가 `AbortDropsWaiting`을 묻고, ChargeTrigger가 `AbortForCharge`로 끊고, TryApplyHeld가 `HeldApplyNow`를 쓴다.
