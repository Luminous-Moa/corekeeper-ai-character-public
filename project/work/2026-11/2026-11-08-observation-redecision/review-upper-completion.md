## 적용 범위 확인

보호는 새 set 계획의 모든 단계가 실행 거절되고, 현재 유효한 목표가 활성 계획의 source와 같으며, 그 계획을 운반하는 미완료 원부탁에 done을 적용하려는 경우에 한정된다.

현재 계획의 후속 단계가 남으면 전체 부탁의 미완료 근거가 된다. 마지막 단계만 남았으면 현재 계량·기능 완료를 실제로 재관측한다. 현재 목표가 없거나 다른 source이면 이 보호 범위를 확장하지 않는다.

latest.order와 earlier.orders에 동일 조건을 적용한다. 보고가 보았던 요청 번호 검증을 유지하고 원본 응답은 보존하며 적용할 명령만 복사·보류한다. 무관한 완료 부탁의 done, defer·drop·answered, 비계량 마지막 목표의 완료 판단, 새 계획이 유효하게 채택되는 경우의 기존 권한은 유지된다.

## 원부탁 보존과 재보고

거절된 새 실행 계획과 충돌하는 done을 보류해 현재 목표·몸·계획과 원부탁의 open 상태를 유지한다. 재보고 JSON에서 last_answer_rejected의 모순 사실과 host_orders_open을 직접 검사한다. 기존 호출 중에는 후속 보고에 합치고 기존 상위 unavailable 재시도 대기를 따른다.

초기 구현의 전체 모순 문자열에는 거절 계획 설명이 들어 있어 같은 미완료 부탁에 다른 잘못된 새 계획을 내면 재호출이 이어질 수 있었다. 독립 검수 의견을 반영해 source·goal revision·원부탁 ID·실제 미완료 사실을 중복 판단 키로 사용한다.

또한 단일 마지막 키로는 A→B→A의 원부탁 완료 선언 교대에서 같은 모순A가 다시 호출될 수 있었다. 현재 계획·목표 세대별 보고 키 집합으로 보완했고, 동일 사실 A/B/A에서 호출이 추가되지 않는 생산 시험을 통과했다. 실제 부족 수량 등 새 사실은 다른 키로 재보고할 수 있다.
