# 장비 전달 지연과 반복 이동 분석

현재 시험판 09e418a의 실제 선택·실행 로그를 분석했다. 사용자 직접 조작과 시험 준비 구간을 구별했다.

## 장비 전달에 걸린 시간

세 부위 계획이 실제 적용된 뒤 마지막 수령까지 70.7초가 걸렸다. 실제 Give 실행은 투구 0.9초, 갑옷 0.7초, 바지 1.0초로 합계 2.6초였다. 많은 시간이 메뉴 선택과 재판단, 실행 준비에 쓰였다.

바지 목표에서 수령까지는 53.7초가 걸렸다.

- 첫 판단 #92는 ‘착용장비’가 선택 가능한 상태에서 ‘도구’를 골랐고, 실제로 도구 메뉴에 들어갔다. 응답과 메뉴 매핑은 일치한다. 모델이 그 선택을 한 내부 이유는 미확정이다.
- 이후 바지를 주지 않은 상태에서 완료를 6회 선택했다. 완료 검사는 이를 보류하고 약 5.3초 간격으로 재판단했다. 같은 오선택이 반복되면서 시간이 쌓였다.
- 메뉴 취소를 선택한 t410.2부터 다음 요청 t427.1까지 약 16.9초 동안 경로 준비가 28회 취소됐다. 주변 장애물 위치·범위 변화가 준비한 사실을 무효화한 구간이다.
- 올바른 메뉴와 수령자를 선택한 뒤 실제 바지 전달은 1.0초에 끝났다.

## 같은 곳으로 돌아가는 이동

t531~746.1 구간에 하위 요청·응답 52회가 있었다. 방향 선택 29회, 탐험 시작 15회, 계속하기 7회, 채집 1회였다. 응답 시간 중앙값은 0.315초, 최대는 0.89초였다. 경로 준비 취소는 114회였다.

캐릭터는 113개 타일에 걸쳐 움직였지만 같은 갈래를 반복 선택했다. `(28,8)→(28,9)`의 북쪽 출구를 서로 다른 실행에서 4회 골랐다. 매번 후보에는 너머의 자원·위험·연결이 ‘미확인’이라는 같은 설명이 붙었다.

현재 걸었던 간선 기록은 `TravelSkill` 실행 인스턴스 안에 있다. 새 탐험 행동으로 재시작하면 그 기록이 초기화된다. 지속 이동 기억은 통행 가능성 중심이어서, 이미 다녀온 출구와 막다른 길에서 돌아온 결과가 다음 실행의 후보에 충분히 전달되지 않는다. 판단모델이 재방문 여부를 결정할 경험 정보가 부족하다.

상위 재계획도 빈번했다. report #14~27의 14건에 미검토 자원에 대한 현장 이탈 사건이 담겼고, 탐험 목표가 13번 다시 설정됐다. `AIExpedition.Choosing`이 방향 선택·계속하기와 현장 이탈을 판정하는 경계가 이 보고를 생성한다. 반복 재계획과 실행별 방문 기록 초기화가 함께 작용하는 경로다. 구체적인 이동 방향은 매번 판단모델이 골랐다.

이 구간에서 새 5초 타이머의 ‘대기 조건 재관측’ 발행은 0건이었다. 요청은 새 갈림길·경로 끝 등의 사건에서 발생했다. 이번 왕복을 5초 타이머의 직접 회귀로 판정할 근거는 없다. 공유 길찾기가 자동으로 같은 방향을 강제한 증거도 없다.

## 개선 우선순위

1. 실행이 바뀌어도 출구 방문·막다른 길·되돌아온 결과를 보존하고 현재 후보에 표시한다. AI의 재방문 선택권을 유지하면서 실제 경험을 전달한다.
2. 같은 탐험을 이어가는 방향 선택·계속하기와 실제 현장 이탈을 구별한다. 같은 기회의 반복 보고로 계획과 실행이 계속 재설정되는 조건을 정리한다.
3. 경로와 무관한 주변 변화가 전체 준비를 취소하는지 확인하고, 유효한 결과를 재사용할 범위를 정확하게 정한다.
4. 명시된 장비·수량·수령자와 현재 메뉴의 관계를 판단 입력에 분명히 유지한다. 완료 미확인 사실과 함께 다음에 가능한 구체 행동을 이해할 수 있게 한다.

이번에는 세 부위가 각각 한 번씩 전달되고 원래 부탁도 완료됐다. 정확한 결과 관측과 재판단 호출이 작동해도, 반복 오선택과 실행 간 경험 소실·준비 재시작은 추가 지연을 만든다. 모델 내부 이유와 동일 조건에서 각 변경이 기여한 정도는 현재 자료로 확정하지 않는다.
