# 채팅 오버레이 가능성 판단

## 요청과 범위
- 큰 채팅 글자로 인해 AI들이 각각 1분에 한 번씩만 말해도 읽기 불편하다는 사용자 경험을 해결할 방법을 판단한다.
- 게임 화면에 채팅 UI를 덧씌워 선명한 작은 글자를 표시할 수 있는지, 그 UI에 AI별 스킬·장비 정보 버튼을 넣을 수 있는지 조사한다.
- 이번 범위는 기존 기록·코드·문서에 근거한 가능성과 난도 평가다. 제품 코드 수정·설치·실게임 실행은 포함하지 않는다.
- 이전 합의의 7초 흐려짐, 기존 입력·멘션 자동완성·시스템 알림 보존을 후속 설계의 기본 조건으로 취급한다. 새 UI의 세부 크기·디자인은 미결정이다.

## 판단
조사 완료. 덧씌우기는 현실적인 구현 경로가 있으며, 출력 교체와 호스트용 스킬·장비 조회를 중간 난도 작업으로 판단한다. 실제 실행 가능성 확정은 아래 대표 실게임 흐름 검증 뒤에 한다.

## 공식 기술 근거
Unity의 Screen Space - Overlay Canvas는 카메라 화면 위에 직접 그리며 화면 크기 변화에 대응한다. 따라서 기존 PugText 픽셀 격자와 별개 UI를 만들 수 있는 일반 기술 경로다. 이것만으로 현재 게임 빌드에서의 성공을 확정하지는 않는다.
- https://docs.unity3d.com/2021.3/Documentation/Manual/class-Canvas.html

## 결론과 권장 범위
- 가능성이 높다. 채팅 표시만 바꾸는 작업은 중간 난도로 판단하며, 전체 입력 UI까지 대체하면 한글 입력·멘션·Tab·포커스까지 구현 범위가 커진다.
- 권장안은 게임 모드 내부에 별도 표시 UI를 그리고 기존 입력·전송 경로는 유지하는 것이다. 기본 채팅 출력과 겹쳐 보이지 않게 출력 부분만 숨기거나 교체한다.
- AI 이름/버튼으로 읽기 전용 스킬·장비 패널을 여는 확장이 자연스럽다. 장비 교체·스킬 배분 같은 조작 기능은 이번 요청의 조회 범위와 별개다.
- 최초 검증 장면은 실제 AI 발언 한 건이 작은 한글로 표시되고, AI 정보 버튼을 눌렀을 때 실제 장비·스킬 상태가 보이면서 공격·이동 입력이 발생하지 않는 흐름이다. 기존 Enter·Tab·시스템 알림과 창 크기 변화도 확인해야 한다.
- 이번 판단은 조사 결과이며 실제 오버레이를 실행한 결과는 아니다. 제품 코드 변경·빌드·설치는 수행하지 않았다.


## 로컬 조사 결과 반영
[코드 조사 근거](2026-11-06-overlay-feasibility-evidence.md)를 확인했다. ai-character 902721e 기준이다.
- 게임 자체 BenchmarkRunner.OnGUI의 12px 텍스트 표시 선례와 SDK/게임의 UI·텍스트 모듈이 확인돼 별도 UI의 실현 가능성을 뒷받침한다.
- 기존 채팅 출력 경계에서 AI 말뿐 아니라 자기 말·시스템 알림도 옮겨야 한다. 부모 UI 전체를 숨기면 입력도 숨으므로 출력 객체만 대체해야 한다.
- AI의 스킬 레벨·현재 착용 장비는 호스트 서버의 현재 상태로 조회할 수 있다. 저장 파일을 실시간 상태로 간주하지 않는다.
- 이번 판단에서 스킬은 우선 스킬 레벨 조회다. 특성 트리·포인트 분배까지 가능한 것으로 확장하지 않는다. 다른 접속자 화면 지원은 데이터 동기화 조사·구현이 추가된다.
- 소규모 시제품은 게임 내 선례가 있는 IMGUI, 사용자용 패널은 루트 Canvas/UGUI를 후보로 둔다. 구현 방식 최종 선택은 작은 한글/입력 충돌 검증 결과로 정한다.
