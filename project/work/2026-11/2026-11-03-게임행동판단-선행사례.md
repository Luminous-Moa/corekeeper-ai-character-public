# 게임 행동 판단 구조 — GitHub·웹 선행사례 조사

작성일: 2026-11-03. 상태: 조사·기록 간 독립 검토 완료. 원자료 확인이며 실행 재현은 하지 않았다.

요청: “이런 발상은 엄청 많았을거 같은데 깃헙이랑 웹 찾아보고 결과들 알려줘”.

조사 목적: 앞서 설계한 LLM 목표·관련 지식 선별 → Jev 세부 행동 선택 → 프로그램 후보 구성·몸 조작 구조와, 풍부하고 유기적인 행동 선택지 구상의 선례·실제 성과·한계를 확인한다.

기준: 이전에 조사한 Jev 사례를 재사용하되 LLM 게임 에이전트 및 전통 게임 AI까지 확장한다. 원저자 논문·공식 프로젝트·GitHub 코드와 실험 기록을 우선한다. 작성자 주장과 독립 재현, 실시간과 일시정지, 고정 기술 선택과 코드 생성, 승률과 사람다움 평가를 구분한다. 설치·코드 변경·유료 실행은 수행하지 않는다.

현재 설계: [LLM·Jev 행동설계](2026-11-03-jev-행동설계.md).

## 전체 판단

목표·행동 선택·실행을 나누는 접근은 오래된 게임 AI부터 로봇과 LLM 게임 에이전트까지 선례가 많다. 구현 가능한 행동들을 재사용·조합하고 상황에 맞춰 계획을 바꾸는 구조는 성립한다. 그러나 각 연구가 증명한 성과는 서로 다르며, 그 조합이 Core Keeper의 실시간 전투와 사람다운 동작까지 보장하지는 않는다.

특히 현재 설계의 ‘현재 가능한 후보’를 두 범위로 구분할 필요가 있다는 시사점을 얻었다. 실행기에 주는 후보는 지금 실행 가능해야 하지만, 상위 목표·계획에는 준비하면 가능해지는 행동과 선행조건도 알려줘야 한다. 이는 설계 수정 제안이며 기존 설계 문서나 사용자 결정을 변경하지 않았다.

## 직접 관련 Jev 사례 재확인

### jevcraft

- [저장소와 교훈](https://github.com/mrubens/jevcraft), [full-2 완료 기록](https://github.com/mrubens/jevcraft/blob/main/docs/wins/full-2.md).
- 프로그램이 상태와 행동 후보를 구성하고 Jev가 선택하며 Mineflayer 기반 기능이 실행한다. 명확한 ‘목표 → 선택지 → 실행’ 선례다.
- 저자 보고: Normal 난이도 새 Survival 월드에서 full-2는 107.2시간, full-3는 150.1시간 후 드래곤 처치. README의 사망 수는 각각 81·95회. 성공은 보고됐으나 빠르고 안정적인 플레이와 같지 않다.
- full-2 사용량·비용은 저자가 실행 장부를 해당 시점까지 비례 계산한 추정치다. 약 25,700회·102M 입력 토큰·$4.30으로 보고하지만 독립 청구 검증이 아니며 다른 빈도의 전투 비용으로 일반화하지 않는다. 전체 서버 로그는 저장소 밖에 있다고 명시한다.
- 저자의 주요 교훈은 누락된 후보, 잘못된 비용·효과 정보, 오래된 사실, 반복 실패다. 교환을 금과 피글린이 이미 가까울 때만 후보로 넣자 새 실행이 그 경로를 추진하지 않았다는 보고가 있다.
- 해석: 당장 실행 가능한 원자 행동만 나열하는 방식은 준비가 필요한 전략을 드러내지 못할 수 있다. 목표·중간 단계와 실행 후보를 연결해야 한다. 우리의 설계에 자동으로 도입된 변경은 아니며 검토할 시사점이다.
- 프로그램이 긴급 방패 대응 등 일부 반사 행동을 담당하는 사례다. ‘전투의 모든 결정이 Jev이며 프로그램은 입력만 한다’는 근거로 쓰지 않는다.

- 공개 CSV를 구성별로 집계해 README와 일치함을 확인했다. pure random 0/10승, Jev-only 0/10승, Astra constrained+random 0/10승, Astra constrained+Jev 9/10승, Astra advisory+Jev 3승·3패·4시간초과. constrained+random은 리플레이 확인 9건, 나머지 1건은 저자 판정이다.

## 기억·인격·목표와 행동의 연결

### Generative Agents (2023)

- [논문](https://arxiv.org/abs/2304.03442), [논문 전문](https://arxiv.org/html/2304.03442v2), [GitHub](https://github.com/joonspk-research/generative_agents).
- 25명의 캐릭터가 관찰을 기억하고, 관련 기억을 검색하며, 성찰과 계획으로 행동을 갱신한다. 목표·기억·상황을 바탕으로 행동을 연결하는 선행 연구다.
- 논문은 파티 초대 전파·약속·참석 조율 등 사회 행동과 인간 평가, 구성 요소 제거 실험을 보고한다. 기억·계획·성찰이 행동의 그럴듯함에 기여했다.
- 주요 실패는 관련 기억 검색 실패, 기억의 허구적 보충, 지나치게 형식적인 말투·행동이다. 사회적 행동 평가를 실시간 전투나 사람 같은 무빙 검증으로 해석하지 않는다.

- 이번 검색에서 우리의 Core Keeper 모드+LLM+Jev 동료 구조와 일치하는 검증된 공개 구현은 확인하지 못했다. 모든 저장소를 망라한 부재 증명은 아니다.

## 이번 설계에 주는 시사점 — 조사자의 해석

1. **풍부한 행동을 미리 준비하는 방향에는 선례가 있다.** 대상·실행 조건·효과·중단·완료를 갖춘 재사용 행동을 만들고, 장기 목표와 현재 상황에 따라 연결할 수 있다. 행동의 숫자만 늘리는 것과는 구분한다.
2. **당장 실행 가능성과 준비 후 가능성을 분리한다.** 현재 도구로 못 캐는 광물이 있을 때 ‘채굴 불가’만 전달하면 수단이 끊긴다. 상위 계획에는 필요한 도구·제작법·재료 관계를 제공하고, 실행 시에는 그 계획의 현재 가능한 단계를 후보로 준다. GOAP를 반드시 추가해야 한다는 결론은 아니며, 현재 LLM 목표 계층에서도 이 역할을 맡을 수 있다.
3. **실행 능력과 판단 능력을 따로 본다.** 모델이 도망을 골라도 경로 탐색이나 행동 중단이 작동하지 않으면 실패한다. Mindcraft와 GOAP 구현은 실행 계약을 참고하기 좋다. Jevcraft는 모델에 무엇을 선택지로 제공해야 하는지의 실패 기록이 유용하다.
4. **유기적인 행동과 사람다운 동작은 다른 평가다.** Generative Agents는 사회 행동과 기억의 그럴듯함, STEVE-1은 화면 기반 제어, Jevcraft는 게임 진행, JEV-Star는 특정 운영·미세 조작 조건을 다룬다. 한 분야의 성과로 다른 분야까지 해결됐다고 결론내리지 않는다.
5. **이미 마련한 설계의 범위를 유지한다.** 이번 결과만으로 새 프레임워크 도입, 코드 생성 실행, 자동 방어 도입, LLM/Jev 정책 교체를 확정하지 않는다. 다음에 컴퓨터에서 몸 조작과 대표 상황을 확인할 때 비교 근거로 사용한다.
