# 분류부터 고르는 가방·장비 선택 트리

2026-11-07 사용자 방향 변경. [초기 구현 합의](agreement.md)의 게임 조작·관측·독립검수 조건은 유지하며, 평면 후보 나열과 개수 제한 부분은 이 합의로 교체한다. context.md는 변경하지 않는다.

## 사용자 결정

> 차라리 처음부터 트리로 하자. 인벤토리를 보고 장비를 선택하면 선택지가 나오도록. 버릴수도 있고 이전 선택지로 돌아갈수도 있고 선택지를 완전히 취소할수도 있게.

> 지금 설정해둔 선택지 상한은 삭제해. 그리고 아이템 선택도 트리로 해. 아이템 분류가 있을거잖아? 그럼 그 분류를 띄우고, 그 분류를 들어가면 인벤토리 내에 가지고 잇는 해당 분류의 아이템이 나오도록.

## 만들 결과

**인벤토리 → 실제 보유 물품이 있는 분류 → 그 분류의 보유 물품 → 가능한 조작 → 필요한 슬롯·대상·수량 → 실행**을 연결한다.

- 현재 메뉴의 자식 선택지만 현장 판단 모델에 전달한다. 트리 전체를 한 번에 보내 경로 문자열을 받는 방식 대신, 선택 경로와 현재 노드를 유지하는 실제 다단계 선택 상태를 사용한다. 이전으로 돌아가기와 전체 선택 취소가 실제 선택으로 작동해야 한다.
- 분류는 실제 게임의 아이템 유형·속성과 대응해 정한다. 물품이 있는 분류만 노출하며, 분류된 물품에는 현재 보유한 정확한 슬롯·종류·변형·상태·개수를 연결한다. 정적 DB 전체나 소유하지 않은 물품을 보유 목록처럼 노출하지 않는다.
- 가방·핫바·착용 중인 물품을 실제 위치와 함께 구별한다. 식별이 같은 개별 장비도 상태와 슬롯이 다르면 선택 가능하게 보존한다. 분류를 판별하지 못한 항목은 명시적으로 남겨 접근 불가가 되지 않게 한다.
- 현재 목표는 판단 맥락으로 유지하며 보유 목록을 목표 품목 하나로 숨기지 않는다. 다른 물품의 준비 조작도 고를 수 있고, 그 조작 성공과 현재 목표의 실제 충족은 구별한다.
- 한 물품을 고르면 그 위치와 현재 게임 조건에 맞는 착용·교체·해제·들기·보관·내려놓기·전달 등을 펼친다. 필요한 추가 인자만 다음 노드에서 선택한다. 모든 인자가 정해진 최종 실행 후보를 모델이 선택할 때 한 번 실행한다.
- 자기 상자에서 꺼내기는 기존 범위에서 유지한다. 자기 상자 선택·접근/열어보기 뒤 실제 관측한 내용의 분류와 물품을 고르는 경로로 연결한다. 열어보지 않은 상자의 내용을 추정해 보여주지 않는다.
- 각 단계에서 뒤로 가기와 선택 전체 취소를 제공한다. 뒤로는 부모 선택 단계로, 전체 취소는 일반 판단으로 돌아간다. 메뉴 조작 자체는 물품 이동·몸 동작 중단·현재 목표 완료·원래 부탁 취소를 수행하지 않는다.
- 물건을 버리는 동작은 기존 범위의 바닥 내려놓기(drop)로 연결한다. 영구 삭제(trash)는 별도 동작이며 이번에 추가하지 않는다.

## 선택지 상한 제거

- 기존 일반 가방 후보 8개와 전체 비전투 기본 후보 14개 제한을 제거한다.
- 분류·물품·조작·대상 목록을 임의 숫자로 자르거나 페이지로 분할하지 않는다. 현재 노드의 실제 항목을 모두 제공하며, 트리의 분류로 한 단계의 선택 범위를 나눈다.
- 현장 후보 생성·전달 경로의 개수 기반 잘라내기를 조사한다. 같은 목적으로 선택지를 누락시키는 상한은 제거하고, 실제 관측 범위·소유권·실행 가능성 조건이나 로그/기억 보관량 같은 다른 의미의 제한은 구별해 보존한다. 해상도가 다른 제한을 조용히 같은 것으로 취급하지 않는다.

## 실행·모델 연결 조건

- 기존 AICandidate/선택 응답 경로를 가능한 만큼 재사용한다. 메뉴 선택은 AISkill 실행·완료와 구별하며, 공통 stop_action/finish_goal/request_plan을 중복 구현하지 않는다.
- 원래 부탁과 목표, 실행 가능한 기존 몸 동작을 유지한다. 선택 메뉴를 탐색하는 동안에도 매 판단에 현재 상황·위험·실행 사실을 전달하고 기존 공통 대응 경로를 유지한다.
- 물품·슬롯·수량·상자·목표가 탐색 중 바뀌면 실제 상태를 대조한다. 오래된 메뉴 응답이나 이전 노드의 선택을 다른 물품의 실행으로 적용하지 않는다. 변경 사실을 보고하고 유효한 선택 단계에서 다시 판단한다.
- 최종 실행은 검수된 기존 Swap/MoveAmount/DropItem 및 실제 결과 관측을 재사용한다. 요청을 중복 전송하지 않고, 양 슬롯 변화·드롭 실소비·지정 수령자의 실제 증가로 결과를 판단한다.
- 단계별 모델 호출은 생기지만 기존 호출·비용 상한을 늘리지 않는다. 예산 제한이나 응답 실패를 이유로 메뉴 선택을 실행으로 승격하거나 유효한 몸 동작을 강제 취소하지 않는다.
- 이번 변경은 가방·장비 선택 트리와 요청한 후보 상한 제거다. 채굴·전투·시설 전체를 별도 다단계 트리로 재설계하거나 숨겨진 장비 스탯·DB 전체를 새 공개 정책으로 노출하는 작업은 포함하지 않는다. 현재 후보에 성능 비교 정보가 적다는 한계는 기록한다.

## 검증과 전달

- 중간 평면판 1fc89b9의 조작·관측과 준비 용량 수정은 재사용한다. 그 판의 검수 통과는 새 선택 트리의 통과 근거로 대신하지 않는다.
- 대표 실행: 인벤토리 열기 → 분류 → 물품 → 뒤로 → 다른 물품 → 조작 → 필요한 인자 → 정상 실행 → 실제 결과 확인. 별도로 각 단계 전체 취소에서 물품·몸 동작·목표·원래 부탁이 유지되는지 확인한다.
- 8개·14개를 넘는 항목을 실제 생성·전달해 임의 누락이 없음을 확인한다. 여러 분류와 장비 변형·내구도가 있는 보유 물품, 빈 분류, 인벤토리 변경과 오래된 응답, 자기 상자 내용 관측, 일부 이동·가득 찬 상자, 수령 미확인, 호출 상한을 핵심 사례로 본다.
- 실제 모델에 보내는 메뉴 문구와 단계 전이 예시, 최종 실행 때의 후보·관측 연결을 산출물에 남긴다. 실제 외부 모델·실게임이 없으면 그 한계를 명시한다.
- 최종 변경판을 독립 검수하고 관련 오프라인 회귀·Unity 컴파일·설치 없는 SDK 후보 패키지를 준비한다. 공식 본/그래프 반영은 HEAD가 최종 결과를 보고 판단한다. 설치·게임·외부 모델 시험의 기존 보류는 유지한다.

이 문서는 앞선 페이지 분할 제안을 철회하고 분류 기반·상한 없는 트리로 확정한다. 중간 평면판의 코드·검증·Unity 근거는 역사적 중간 결과로 보존한다.
