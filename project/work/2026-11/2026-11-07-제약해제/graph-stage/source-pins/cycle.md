# 행동을 제공하는 모드와 동적 수행 흐름

## 모드를 보는 방향

코어키퍼라는 게임에서 대상과 행위를 찾아내고, 그 조합으로 행동을 정의한다. 공통 행동은 유형으로 묶을 수 있다. 예를 들어 구리 광석 × 캐기와 철 광석 × 캐기는 광석 캐기로 묶고, 도구 등 개별 조건의 차이는 남긴다.

구조는 코어키퍼 → 대상·행위 → 조합·분류한 행동 → 구현 코드다. 기존 코드에서 기능을 추출하는 방향이 아니라, 게임에서 필요한 행동을 먼저 정의하고 그 행동을 AI에게 제공하는 시스템으로 모드를 본다. 기존 코드는 각 행동을 얼마나 구현하는지 대응시키는 대상이다.

## 제품 그래프 개념의 대응

- 기능: AI에게 제공할 게임 행동. 이번 모드 분석에서는 이 행동이 기존 제품 그래프의 기능 자리를 맡는다. API·명령 등 코드 입구 단위의 기능 정의와 구별되는 프로젝트 관점이다.
- 화면: AI가 행동을 선택·실행하고 결과를 받는 인터페이스.
- 유저플로우: 특정 상황에서 목표를 이루기 위한 행동의 순서와 분기. 단순한 행동 목록이 아니라 목적과 흐름이 있는 행동 묶음이다.

## 행동만으로는 부족한 것

대상 × 행위와 그 결과만으로 전체 수행 흐름이 만들어지지는 않는다.

- 현재 상태를 관찰해야 한다. 대상의 위치, 자신의 도구·재료 등을 알아야 한다. 관찰은 별도 API 같은 인터페이스로 제공할 수도 있지만 구체적 방식은 아직 정하지 않았다.
- 대상에 행동할 수 있는 위치까지 이동해야 한다. 이미 그 자리에서 가능한 행동은 이동을 건너뛴다.
- 목표·대상을 선택하고 실행 조건을 확인해야 한다. 도구·재료 등이 부족하면 준비 과정이 필요하다.
- 결과를 확인하고 상태를 갱신해야 한다. 실패하거나 상황이 바뀌면 다시 판단한다.

## 합의한 수행 순환

각 과정에 알고리즘이 들어간다고 할 때 다음 네 단계로 본다.

1. 판단: 현재 상태에서 무엇을 할지 정한다.
2. 계획: 고정된 액션 하나를 고르는 데 그치지 않고, 어디까지 이동해서 무엇을 할지 대상·위치·조건에 맞춰 행동 묶음의 순서와 분기를 즉석에서 구성한다. 필요한 준비도 여기에 포함한다.
3. 실행: 구성한 계획을 실제로 수행한다.
4. 갱신: 결과를 상태에 반영하고 다음 판단으로 돌아간다.

즉, 현재 상태를 인식하고 목표를 정한 뒤 필요한 준비·이동·행동을 구성하여 수행하고, 결과로 다음 판단을 이어 간다.

## 범위

이번 기록은 사용자와 합의한 개념과 흐름이다. 각 단계의 구체적 알고리즘, LLM과 코드의 역할 분담, API 형태, 그래프 스키마는 아직 정하지 않았다. 기존 그래프·코드·세션 목적 문서를 변경하거나 구현에 착수한 것은 아니다.
