# 공통 실행 구현 합의

## 맡은 결과

이 대화가 공통 실행을 구현한다. 사용자는 나머지 채집·이동, 장비·가방, 전투 수단, 시설 행동을 다른 대화에서 맡긴다. 구현 위치는 C:/Dev/CoreKeeperModSDK-common-execution, Git 브랜치는 common-execution-20261107, 출발 커밋은 11eb461이다.

## 판단 기준

- 수량 충족, 시간 경과, 진척 없음, 호출 실패 등 코드가 정한 기준은 관측 사실로 AI에게 전달한다. 실행 가능한 기존 선택을 강제로 취소하는 정책을 제거한다.
- AI가 명시적으로 계속·중단·전환할 수 있게 한다. 새로운 AI 선택과 사용자 직접 중지는 실행한다.
- 중간 단계 진척과 사용자 원래 부탁을 보존한다. 구리 확보가 갑옷 부탁 완료로 처리되지 않아야 한다.
- 사라진 대상이나 실제 실행 실패는 결과와 이유로 전달한다. AI가 현재 상태에서 다음 행동을 결정한다.
- 새 응답을 기다리는 동안 실행 가능한 선택을 이어 간다. 응답이 늦었다는 이유만으로 유효한 선택을 무조건 버리는 경로도 검토한다. 대상과 실행 회차 및 후속 AI 결정에 맞춰 적용한다.
- 다른 작업에서 사용할 후보→몸 실행→결과와 중단·전환의 공통 연결을 문서화한다.
- 호출·비용 상한에 도달하면 그 사실을 보고하며 실행 가능한 현재 동작을 유지한다. 이번 작업으로 기존 요금·호출 예산을 늘리지 않는다.

## 구현 중 정한 공통 입구

- stop_action은 몸의 현재 행동만 중단하고 목표와 원래 부탁을 유지한다.
- finish_goal은 AI가 현재 계획 단계의 완료를 명시한다. 원래 부탁의 완료는 상위 LLM의 order=done으로 결정한다.
- request_plan은 현재 상황을 상위에 전달한다. 상위 응답을 기다릴 때 실행 가능한 현재 동작을 이어 간다.

## 검증과 전달

독립 세부 구현과 독립 검수로 위 조건과 실제 변경을 대조한다. 기존 오프라인 회귀에 더해 대표 실행 흐름에서 수량 충족 후 선택 유지와 명시 중단·전환, 원래 부탁 보존을 확인한다. 게임 실행이나 설치가 필요하면 기존 보류와 승인 상태를 확인해 진행하고 실제로 확인한 검증 범위를 보고한다.
