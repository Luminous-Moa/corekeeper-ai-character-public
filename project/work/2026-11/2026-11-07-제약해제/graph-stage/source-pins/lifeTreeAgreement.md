# 기지 생활 선택지 트리 구현 합의

## 목적과 승인

사용자는 시설 생활 계획에 이어 농사의 칸·수량 조합 폭증을 지적했고, 속도가 중요하지 않은 기지 생활에서는 선택지를 트리로 탐색하는 방향을 승인했다. 농사 외 제작·요리·장비 강화·거래·가방/상자 정리에 우선 적합하고 수리·제련은 선택이 단순하면 직접 제시할 수 있다는 설명 뒤 구현 시작을 요청했다.

## 지킬 결과

- 트리는 AI가 필요한 선택지를 좁혀 조회하는 구조다. 작업 순서·종류·재료를 코드가 미리 정한 생활 루틴으로 바꾸지 않는다.
- 작업→대상/재료→시설/구역→수량처럼 필요한 수준만 탐색한다. 수량은 지정값으로 받고 모든 수량·칸 조합을 후보로 열거하지 않는다.
- AI가 이미 대상과 수량을 알면 바로 실행한다. 매번 루트부터 내려가도록 강제하지 않는다.
- 탐색 도중 돌아가기와 다른 작업 선택이 가능하다. 탐색 요청은 현재 유효한 몸 행동을 취소하지 않는다.
- 실행 시 현재 대상·재료·권한을 다시 확인하고 달라진 사실을 전달한다. 현재 관측과 화면 밖 마지막 관측을 구별한다.
- 시설 투입·생산·가방 수령과 실제 장비 변화, 작업 단계 완료와 원래 부탁 완료를 구별한다. 공통 실행 계약을 재사용한다.
- 대상은 농사 및 계획의 생활 행동이다. 이미 있는 실행을 먼저 연결하며, 새 몸 실행이 필요한 수리/강화/낚시/거래와 타담당 가방장비의 상태를 조사해 구현 단계·의존 경계를 명시한다. 이름만 있는 실행 선택지를 지원 능력으로 노출하지 않는다.
- 기존 자기 밭/솥/상자 등 권한과 캐릭터에게 열린 지식을 유지한다. 공유 자원·장기 소비 정책은 새로 정하지 않는다.

## 진행과 검증

공식 코드 출발은 C:/Dev/CoreKeeperModSDK ai-character 685dde4이다. 기존 미커밋 상태는 보존하고 격리 worktree에서 진행한다. 실제 코드와 양쪽 그래프를 이용한 개발 방향→HEAD 판단→구현 명세→HEAD 판단→구현·검증→독립 검수를 수행한다. 제품 그래프에는 승인·구현·실게임 미확인 지위를 구별해 반영한다.

기존 게임 실행·설치 보류를 유지한다. 오프라인 대표 실제 파이프라인·관련 회귀·Unity 컴파일을 확인하고, 실게임 성공은 수행하지 않았으면 미확인으로 남긴다. 새로운 사용자 화면은 만들지 않는다.
