# Jev 실제 활용 사례 추가 조사

2026-11-03. 요청: “jev 활용한것들을 더 찾아봐줘. 위 내용 중에선 1개뿐인거 같은데.”

범위: TypeSafe Jev를 실제 호출하는 게임·캐릭터·제어 프로젝트. 이전 보고서의 일반 GOAP/LLM 사례와 구분한다. GitHub 연결 도구로 README와 주요 호출 코드를 읽고 웹으로 탐색했다. 외부 프로그램 실행·유료 API 호출·독립 플레이 재현은 하지 않았다. 성과 수치는 작성자 보고다.

## 추가 사례

### 1. Pokémon Red — 목표 선택, 기억, 이동

- [저장소](https://github.com/milanboers/jev-plays-pokemon), [README](https://github.com/milanboers/jev-plays-pokemon/blob/main/README.md), [실제 호출·선택 코드](https://github.com/milanboers/jev-plays-pokemon/blob/main/jev_plays_pokemon/agent.py).
- 게임 RAM·대사·통행 지도·근처 NPC와 현재 후보를 구성한다. Jev가 대화·탐색·출구 이동 등의 목표를 고르고 프로그램이 A*/BFS 경로 및 버튼 입력을 실행한다. 목표 완료나 상황 변화 때 제어를 Jev로 되돌린다는 구조다.
- 최근 대사 8개·행동 12개 등 기억을 프로그램이 유지해 요청에 다시 넣는다. 같은 행동 반복 방지를 위해 반환 분포를 변환한 뒤 프로그램의 random.choices로 목표를 샘플링한다. Jev 자체가 무작위성을 보장한다는 뜻이 아니다.
- 저자는 집→마을→오박사 연구소→스타터 선택→밖으로 나오는 초반 흐름을 보고한다. 첫 라이벌전과 야생전은 불안정하다고 명시한다. 전체 게임 완주 사례가 아니다.

### 2. jev-drone — 상황 변화 때만 판단

- [저장소·결과](https://github.com/RomanSlack/jev-drone), [호출·상황 지문 코드](https://github.com/RomanSlack/jev-drone/blob/main/tactics.py).
- MuJoCo 시뮬레이션. 카메라 깊이/분할 정보를 코드가 기호 상태로 만든다. Jev는 직진·좌/우 우회·상승·제동·목표 재탐색 Choice, 위험 Score, 목표를 정말 잃었는지 Noul을 답한다.
- decision_needed와 거친 scene fingerprint로 판단 필요·변화를 확인한다. 별도 worker에서 호출하고 최신 판단을 캐시한다. 비행 제어 500Hz·안전 반사 50Hz는 코드, Jev 전술 판단은 약 2.5~3Hz다.
- 저자 보고 단일 65초 실행에서 전 코스 도달 77.5m, 80회 호출, 중앙 지연 0.11초. 비교 baseline 3회는 17.7m에서 정체했다. baseline에 상승 판단이 없었던 구조적 제한이며, 앞선 다른 3-seed 조건에서는 Jev 이득이 없었다고 저자 스스로 명시한다.
- 별도 터널 실험은 Jev만 항법을 맡는 부분 결과다. 0.118초 중앙 지연·병렬 21결정/초를 보고하지만 코스를 안정적으로 완주하지 못한다. 병렬 처리량을 1회 응답 지연으로 해석하지 않는다.
- 원래 모든 전투 선택을 Jev에 맡기려는 구상과 달리 기본 코스에는 코드 안전 개입이 있다.

### 3. tsai-sc — 오리지널 스타크래프트

- [저장소·상세 실행 구조](https://github.com/phyous/tsai-sc), [README](https://github.com/phyous/tsai-sc/blob/main/README.md).
- 기존 JEV-Star(스타크래프트2)와 다른 프로젝트다. 원작 shareware Strongarm 임무에서 관측 가능한 상태→상황별 명령 후보→Jev→실제 마우스·키보드 입력을 연결한다.
- 채광·병력 생산·교전·탐색·후퇴·현재 명령 지속 후보가 있다. 범주 선택과 범주별 구체 명령을 병렬 질문하고 코드가 선택한 가지의 명령만 실행한다.
- 저자 보고 개발 시도16에서 승리, 모델 결정421회, 중앙 API지연382.95ms. 영상·검증보고·증거 번들 링크를 제공한다. 개발 시도16은 16경기 중 1승과 다르다.
- 관측 및 추론 동안 게임을 일시정지한다. 실시간 전투 성공 증거로 쓰지 않는다. 이번 확인은 README·증거 링크 확인이며 번들 재검증은 하지 않았다.

### 4. typesafe-snake — 응답 마감과 지속 실행

- [저장소](https://github.com/sorrycc/typesafe-snake), [제어기](https://github.com/sorrycc/typesafe-snake/blob/master/src/game/controller.ts), [호출 서버](https://github.com/sorrycc/typesafe-snake/blob/master/server/index.ts), [후보·fallback](https://github.com/sorrycc/typesafe-snake/blob/master/src/game/analysis.ts).
- 프로그램이 합법 이동·먹이 거리·도달 가능 공간·막다른 길을 계산하고 Jev가 Choice로 방향 선택. 후보가 2개 미만이면 호출하지 않는다.
- 고정 tick 마감까지 온 응답을 실행하고 늦은 응답은 epoch로 배제한다. 기본 tick은 1200ms다. 마감 실패/오류 때 fallbackMove는 직진이 합법이면 직진, 아니면 첫 합법 방향으로 간다. README의 단순 ‘직진 지속’ 설명보다 코드가 정확하다.
- 지연 대응 구현의 선례이며 고승률·100ms 제어 성과를 확인한 사례는 아니다.

### 5. Jev Plays Clash Royale — 구체 행동 후보 중 선택

- [저장소](https://github.com/Amrit-Nigam/jev-royal), [실제 판단 코드](https://github.com/Amrit-Nigam/jev-royal/blob/main/src/decide.ts).
- macOS iPhone Mirroring 화면을 로컬 템플릿/OCR로 읽고 카드·배치 위치 후보를 코드로 구성한다. Jev는 지금 사용할지 Noul과 어느 후보인지 Choice를 답한다.
- 급박한 상황에는 모델 왕복을 생략하고 로컬 전술이 즉시 행동한다. 키가 없거나 API 실패 때도 로컬 전술. 전투를 Jev에 온전히 맡기는 사례가 아니다.
- 적 체력 막대로 위치·진영은 읽지만 적 카드 정체는 인식하지 못한다고 명시한다. 이번 확인 자료에서 신뢰할 대전 승률은 찾지 못했다.

### 6–9. 경비 NPC·Doom·SuperTuxKart·JevBird

독립 사실 조사에서 실제 호출 코드 확인. 상세 근거와 성과 조건은 [추가 GitHub 조사](2026-11-03-jev추가사례-깃헙.md)에 있다.

- [heist-one](https://github.com/AbdelStark/heist-one): 경비 NPC의 위협·의심·의도·주의대상을 Jev로 판단하고 서버가 행동을 검증·실행. 저자 검증 문서는 제한된 sandbox에서 플레이어 1회 extraction 성공을 보고하며 원본 로그는 로컬 비공개다. Jev 경비의 승리나 지능 우위가 입증됐다는 뜻이 아니다.
- [doom-jev](https://github.com/AmoghCreator/doom-jev): ViZDoom의 구조화 관측을 Jev로 보내 목표·이동·공격 판단. 실제 API 호출 코드가 있으나 정량 전투 성과는 확인하지 못했다. 코드의 기하 조준 및 자동 사격이 Jev 판단을 덮어쓸 수 있다.
- [SuperTuxKart-Jev](https://github.com/mizuamedesu/SuperTuxKart-Jev): 엔진 상태와 Jev 판단을 UDP bridge로 연결한 실제 게임 포크. 10Hz 설정은 달성한 응답 속도·우승률을 뜻하지 않는다.
- [JevBird](https://github.com/leftspace89/JevBird): 코드가 미래 비행 경로를 시뮬레이션·추린 뒤 Jev가 경로를 선택한다. 저자 녹화에서 47개 파이프 통과 보고. 키 입력마다 새로 추론하는 방식과 다르다.

### 10. christianmat/jev-pokemon — Pokémon Red 완주 보고

- [저장소·결과](https://github.com/christianmat/jev-pokemon), [실제 Gateway 호출](https://github.com/christianmat/jev-pokemon/blob/main/src/jev/gateway.ts), [캐시·선택 구현](https://github.com/christianmat/jev-pokemon/blob/main/src/jev/client.ts).
- 위 1번과 별개 프로젝트다. RAM 관측·합법 선택지와 타입 상성/피해 추정·목표까지 거리 등의 사실을 주고 Jev가 메뉴·이동 목적·전투 행동을 선택한다. A* 이동과 메뉴 조작은 프로그램이 실행한다. Vercel AI Gateway의 typesafe-ai/jev 호출을 코드에서 확인했다. 기본 실행 설정은 mock이므로 실제 실행에는 gateway 설정이 필요하다.
- 저자 보고 37시간40분에 완주, 결정16,150회, 약39.2M 입력 토큰, 약$1.65, 중앙 결정 시간 약0.4초, 파티 전멸16회·사천왕 도전15회. 9/25–26 생방송 및 랜딩 페이지 하이라이트를 언급한다. 이번 조사에서 전체 영상이나 로그·청구를 재검증하지 않았다.
- 스토리 이정표 지식이 사전 제공된다. 실패 선택 반복 시 다른 후보를 샘플링하고 최후에는 체크포인트를 다시 불러온다. 따라서 ‘아무 도움 없는 순수 모델 단독 완주’로 해석하면 안 된다. 코드에서도 똑같은 상태·질문 캐시, 후보1개 때 호출 생략, 반복 탈출용 분포 변환·샘플링을 확인했다.

## 현재 구상에 대한 판단

‘상황을 코드로 읽고 실행 가능한 행동을 만들기→Jev가 선택→프로그램이 여러 프레임 실행→변화·완료 시 재판단’은 실제 여러 공개 구현에서 쓰인다. 특히 포켓몬은 목표·이동·기억, 드론은 사건 기반 호출 생략, heist-one은 NPC 판단 분리와 관련이 높다.

성공 범위는 제한적이다. 정지 추론·프로그램 긴급 개입·좋은 후보의 사전 계산·초반 구간 조정 등을 구분해야 한다. 이 자료는 Core Keeper의 사람다운 무빙, 모든 전투의 실시간 Jev 전담, 안정적 100ms 응답을 입증하지 않는다. 반대로 ‘100ms 부근 응답 자체가 불가능’하다는 단정도 맞지 않다. 보고된 지연은 환경에 따라 0.11초부터 약0.4초 이상으로 다르며 우리 게임·네트워크에서 확인해야 한다.

설계·구현은 변경하지 않았고 조사만 완료한다.

독립 검토: 별도 에이전트가 본 문서와 관련 README를 대조하여 포켓몬 두 사례의 구분, 드론 단일 실행과 제한된 baseline, 스타크래프트 정지 추론, 코드 전술 개입에서 중대한 오해·과장을 발견하지 못했다. 실행 재현이나 모든 원코드의 추가 검증은 아니다.
