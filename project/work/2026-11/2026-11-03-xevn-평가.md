# Xevn-4B 평가

조사일 2026-11-03. 사용자 지정 저장소 https://github.com/Nhahan/Xevn 평가. 공개 파일·모델 카드·제삼자 집계 열람이며 가중치 다운로드, 로컬 추론, 유료 API, 게임 변경은 하지 않았다.

## 현재 프로젝트와 결론

다른 작업 브랜치에서 OpenAI Decisions를 행동 판단 모델로 선택하고 API 호출도 성공했다는 최신 기록이 있다. 크레딧 약200달러 예상은 사용자 조건이며 잔액을 이 조사에서 확인하지 않았다. 이 평가는 현 선택을 바꾸는 결정이 아니다.

**Xevn은 한국어 상태·목표를 읽는 로컬 행동 선택 후보로 검토할 가치가 있다. 그러나 현재 OpenAI Decisions를 대체할 만큼 전반적 품질이나 실제 게임 성능의 우위가 입증되지는 않았다.** 한국어 자체 평가가 강점이고 실제 공개 가중치·추론 코드가 있다. 공급자 API 비용 없이 로컬에서 쓸 수 있으나 게임과 GPU를 공유하며 운영·통합 작업이 필요하다.

## 무엇인가

[공식 모델 카드](https://huggingface.co/quevirus/Xevn-4B): Qwen3.5-4B 기반, 한국어 중심의 결정 모델. `choice` 2~26개 후보, `noul` 예/아니오, `score` 2~10등급을 지원한다. 문장을 생성하지 않고 질문별 forward 한 번으로 확률을 읽는다. 여러 질문이 들어간 요청 전체가 단 한 번으로 처리되는 것은 아니다. 공개 helper는 텍스트·JSON 상태를 처리하며 멀티모달 원본 구조가 남아 있다는 이유로 게임 화면 판단 기능을 가정하지 않는다. Apache2.0로 공개돼 있다.

우리 구조의 ‘LLM 목표 → 프로그램이 가능한 후보 구성 → 판단 모델 선택 → 프로그램 실행’에서 판단 모델 자리에 들어갈 수 있다. 선택지 자체를 무한히 생성하거나 경로탐색·키 입력을 해결하는 모델은 아니다. 기본 choice는 최고 확률 선택이므로 같은 상태에서 자동으로 다양한 행동이 나오는 것도 아니다.

## 제작자 한국어 평가

[GitHub 한국어 README](https://github.com/Nhahan/Xevn/blob/main/README.ko.md)와 모델 카드의 자체 실행 결과. 모든 모델을 M4 Max에서 같은 프롬프트·채점, BF16(Decider FP16) 조건으로 비교했다고 설명한다.

| 과제 | Xevn 정확도 | README의 JevK5 | 판단 |
|---|---:|---:|---|
| KoBEST | 89.7 | 69.7 | 한국어 추론·상식에서 큰 차이 |
| Belebele | 89.0 | 87.4 | 독해에서 소폭 우위 |
| KMMLU | 56.3 | 52.8 | 전문지식에서 우위 |
| CSAT-QA | 68.8 | 69.4 | Xevn이 낮음 |
| CLIcK | 66.5 | 67.3 | Xevn이 낮음 |

한국어8개 과제 중 정확도 기준5개에서 표 내 최고다. 단, README의 `JevK5`는 TypeSafe Jev1.14와 다른 공개 모델이다([JevK5 카드](https://huggingface.co/alibiserikbay/JevK5)). `Decider` 열도 정확한 checkpoint/version 연결이 제시되지 않아 앞선 Perplexity v1.2 결과와 동일시하지 않는다. OpenAI Decisions와 직접 비교한 한국어 표는 없다.

GitHub에 확인된 파일은 README·라이선스·차트·소개 사이트 중심이다. 공개 추론 코드는 HF에 있지만 자체 한국어 평가의 실행 harness, 문항별 원응답, 정확한 비교 checkpoint, 표본수와 신뢰구간, 학습/평가 중복 감사는 확인한 자료에서 찾지 못했다. 이는 오염이 있었다는 증거가 아니라 독립 재현의 한계다. Headline은 정확도 자체가 아니라 Intelligence와 Calibration의 평균이며 이전 system-one-bench 지수와 수치를 섞지 않는다.

## 제삼자 평가

[Benchmark Heaven JevBench v1.8.4](https://benchmarkheaven.com/jev-models/v1.8.4), [공개 집계 JSON](https://benchmarkheaven.com/api/jevbench/v1.8.4)의 해당 모델 행을 읽었다. 이 버전은2026-10-31 보존본으로 수치 출처를 고정하려고 사용했으며 현재 최신판이라고 주장하지 않는다.

| 모델 | Intelligence | Calibration | Capability |
|---|---:|---:|---:|
| Xevn-4B | 52.15 | 85.13 | 68.64 |
| Jev1.14 | 59.94 | 90.08 | 75.01 |
| OpenAI Decisions | 56.9 | 90.1 | 73.5 |

Capability는 위 두 품질 지표의 평균이며 정확도%가 아니다. Xevn/Jev는12 Oct draw이며, OpenAI는 별도의 sealed A5∪P600문항을 보정해 기준 척도에 연결한 값이다. 따라서 특히 OpenAI와의 숫자 차이를 동일 문항 직접 승률로 해석하지 않는다. 우리 코어키퍼 성능을 측정한 표도 아니다. 일반 평가에서 Xevn이 두 API를 앞선다는 근거는 되지 않는다.

Xevn은2026-10-24 평가자가 임대한 RTX PRO6000 Blackwell96GB에서 native BF16 PyTorch helper를 수정 없이 실행했다. 고정 모델 revision `ba11f0c2d8100a1e8b7789a1174ddee7c24dcab0`. 순차 loopback HTTP 요청1500개 기준 raw p50 41.094ms·p95 72.356ms. 사이트의232ms는 `2×실측+150ms` 가정으로 변환한 값이며 실측 네트워크 API 시간이 아니다.

1500개 중1485개 답변, 약76k~80.5k토큰의 초장문15개는96GB에서도 OOM으로 실패 처리했다. 정상 응답 중 가장 긴 입력은1789토큰. 이것이 짧은 게임 상태에서도 메모리가 부족하다는 뜻은 아니지만 기본 eager 추론에 장문 전체를 무작정 넣으면 안 된다는 근거다. 첫50개 재실행은 전부 동일, argmax 변경0건. 평가자는 제작자 한국어 suite를 독립 검증하거나 학습 중복 감사한 것은 아니라고 명시한다.

## 속도·로컬 조건

제작자 속도는 M4 Max MLX, BF16, 질문1개/요청, 총3000요청이다. 입력≤64토큰 p50/p95 56/64ms,65~128토큰88/103ms,129~256토큰156/188ms. 상태·목표·기억·여러 후보를 넣은 긴 게임 요청이나 RTX5080의 수치가 아니다.

현재 PC는 이전 읽기 확인상 RTX5080 16303MiB·RAM32GB급이다. NVIDIA는 Transformers CUDA 또는 GGUF 전용 helper 경로를 검토한다. GGUF Q5_K_M파일3.16GB·Q6_K3.56GB·Q8_04.61GB는 실행 VRAM 사용량과 다르다. 게임 동시 실행 프레임·지연은 미측정이다. 공식 양자화 품질 표는 MLX용이므로 GGUF Q5/Q6에서도 동일한 품질 손실이라고 가정하지 않는다. 별도 GGUF 카드의 Q8_0 38/40은40개 예제에서 BF16과 최상위 답의 일치 건수이며 실제 정답률95%라는 뜻은 아니다.

상세 실행조건·공개 코드 확인은 [실행조건 조사](2026-11-03-xevn-실행조건.md)에 정리한다. [GGUF 공식 카드](https://huggingface.co/quevirus/Xevn-4B-GGUF)는 Q8_0을 추천하며 `llama-cpp-python>=0.3.36`과 전용 helper를 안내한다. GGUF helper의 기본 context는8192이고 매질문 reset해 공유 문맥 캐시를 재사용하지 않는다. 공식 HF 카드상 호스팅 Inference Provider는 없으며, Ollama는 prompt logits가 필요해 명시적으로 미지원한다. GGUF helper를 통한 결정 추론 경로를 사용해야 한다.

## 확률과 행동에 대한 중요 조건

공식 설명과 제삼자 실행은 `noul`의 yes확률이0.2~0.8 사이면0.5 미만은0.2, 나머지는0.8로 이동시키는 동작을 명시한다. 예를 들어 보정 후0.55는 반환 시0.8이 된다. 이를 ‘전투 승률80%’ 또는 자연스러운 불확실성 값으로 읽으면 안 된다. 선택지 확률도 실제 성공률과 같지 않다.

‘현재 실행 가능한 후보 중 무엇을 할까’에는 choice를 우선 검토할 만하다. 누적 기억·성향·관측은 여전히 별도 관리해야 하고, 결과를 보며 자동 학습하는 기능은 확인하지 않았다. 보류가 필요하면 판단 후보에 명시적으로 포함시키고 실제 게임 상태로 검증해야 한다.

## 제안

현재 채택된 OpenAI Decisions의 연결을 유지하면서 Xevn은 한국어 로컬 비교 후보로 둔다. 비교하게 된다면 같은 상태·목표·후보를 고정하고 한국어 지시 준수, 무효 행동 반복, 위험 접근/도주, 임무 완료를 확인한다. 지연은 모델 단독과 게임 동시 실행을 나눠 p50/p95 및 프레임 변화를 측정한다. 0.1초마다 확정 응답할 수 있다는 보장은 현재 근거로 만들 수 없다.

이 보고서는 모델 선정 자문이다. 실제 추론 재현·설치·교체는 수행하지 않았다.
