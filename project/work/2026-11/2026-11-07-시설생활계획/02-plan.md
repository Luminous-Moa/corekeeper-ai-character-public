# 시설 생활 행동 선택지 보완 계획

현재 구현과 두 그래프를 읽고 제안한 계획이다. 아직 제품 구현·실게임 검증을 수행하지 않았다. 조사 근거와 현재 코드 기준은 [근거 문서](01-evidence.md)에 있다.

## 왜 하는가

AI가 생활을 돕는 동료로 행동하려면 “요리하기”, “농사하기”라는 큰 명령뿐 아니라 **무엇을, 얼마나, 어느 시설에서 할지 고르고, 실제 결과를 받은 다음 원래 부탁을 이어 가는 선택**이 필요하다.

제작·요리·농사의 몸 실행은 이미 있다. 요리는 배고픔 이득이 큰 한 짝, 농사는 첫 씨앗 종류처럼 코드가 후보를 미리 좁힌다. 수리·강화·낚시·거래는 게임 규칙 근거는 있지만 모드의 일반 목표부터 결과 확인까지 이어지는 연결이 부족하다. 따라서 기존 생활 실행을 넓히는 것부터 시작해, 새 시설 행동을 하나씩 완결하는 순서를 권고한다.

## 선택할 수 있게 만들 것

위쪽 AI는 부탁을 보고 목적·대상·필요 수량·중요한 작업 순서를 정한다. 현장 AI는 보이는 시설과 가진 재료, 기억한 시설의 마지막 상태를 바탕으로 이동·투입·수령·계속·중단·전환을 고른다. 프로그램은 선택한 행동을 실행하고 실제 전후 상태를 보고한다.

각 시설에는 할 수 있는 일과 그 결과, 필요한 재료/장비·수량, 현재 부족한 조건, 생산 중인지와 출력 공간을 제공한다. 화면 밖의 현재 상태는 아는 것으로 다루지 않는다. 개발용 행동 그래프 전체를 판단 입력에 넣지 않고, 캐릭터에게 열린 지식과 현재 작업에 관련된 사실만 제시한다. 게임 내 지식 조회 전체를 개편하는 별도 작업을 기다리게 만들지는 않는다.

시설을 이용한 결과는 다음처럼 나눠 전달한다.

- 재료를 넣었다 / 작업을 시작했다.
- 물건이 완성됐지만 시설이나 커서에 남아 있다.
- 가방에 받았다 / 실제 장비 상태가 바뀌었다.
- 공간·재료·권한·대상 변경 때문에 어디까지 진행됐는지.

AI는 이 사실을 보고 다음 행동을 정한다. 투입 성공이나 목표 수량 달성만으로 원래 부탁을 자동 종료하지 않는다. 완성품이 가방 밖에 남아 있는데 수령 완료라고 말하지 않는다.

## 권장 착수 순서

| 순서 | 보완 범위 | 먼저 하는 이유와 완료 장면 |
|---|---|---|
| 1. 요리 선택과 수령 | 재료 짝·순서·수량과 자기 솥을 고를 수 있게 한다. 배고픔뿐 아니라 캐릭터가 아는 음식 효과를 비교한다. 이미 있는 예측·투입·대기·수령을 재사용한다 | 가장 작은 범위로 선택→몸 실행→결과를 닫을 수 있다. 지정한 재료로 원하는 양을 요리하고, 다른 일을 하다가 돌아와 완성품을 실제 가방에 받는 흐름 |
| 2. 제작·제련 | 일반 제작과 용광로 같은 자동 가공을 구분한다. 레시피 조건·재료·생산 단위·출력 공간을 검수된 게임 규칙에 맞추고, 시설 선택·투입·완성품 수령을 연결한다 | 제작 준비와 장비 유지에 주괴가 필요하다. 구리 확보→제련→주괴 수령→장비 제작→제작물 수령까지 원래 부탁을 유지하는 흐름 |
| 3. 수리 | 가진 장비 중 어떤 것을 수리할지, 필요한 재료와 실제 내구도를 보고 선택한다. 수리대까지 이동하고 실제 요청과 내구도·재료 전후를 확인한다 | 농사·채집·전투 모두에서 도구가 닳는다. 새 도구 제작만 반복하지 않고 선택한 도구를 고쳐 원작업에 복귀하는 흐름 |
| 4. 농사 선택 | 씨앗 종류·심을 자기 밭의 칸/범위·수량, 일구기·물 채우기·물주기·수확을 선택하게 한다. 식용 종자 위주 제한은 게임 규칙과 필요한 사용처를 보고 보완한다 | 요리·제작·수리의 공통 결과 처리와 물품 조작을 재사용한다. 지정 종자만 필요한 칸에 심고 물을 준 뒤, 성장 중 다른 일을 하고 돌아와 수확물을 받는 흐름 |
| 5. 장비 강화 | 수리대의 내구 강화와 대장간의 레벨 업그레이드를 구분한다. 정확한 장비·현재 상태·다음 효과·실제 비용을 비교해 선택한다 | 장비 identity·내구도·레벨 관측과 수리 실행을 확보한 뒤 넓히는 편이 직접적이다. 지정 장비를 선택한 단계까지 바꾸고 비용/상태 전후를 확인한 뒤 원작업 재개 |
| 6. 낚시·거래 | 낚시는 물·장비·미끼·입질/당기기·전리품 수령을, 거래는 실제 상품·재고·가격·보유 수량과 구매/판매 결과를 연결한다. 각각 독립 단위로 진행한다 | 새 상태 처리와 별도 소비자가 필요하다. 낚시 시작/상점 열기를 완료로 세지 않고, 물고기 또는 거래 결과물을 가방에 받는 장면까지 확인 |

2와 3을 농사보다 먼저 두는 것은 제련·도구 유지가 여러 생활 행동의 준비를 공통으로 풀기 때문이다. 순서는 계획 제안이며, 사용자에게 당장 필요한 경험이 농사라면 4를 앞당길 수 있다. 자동 농사팔·어망·회로 등 설비 운영은 손으로 하는 농사·낚시와 구별하고, 위 기본 흐름 이후의 별도 단위로 다룬다.

### 첫 단위: 요리 부탁 한 번을 끝까지

예를 들어 “가진 재료로 필요한 효과의 음식 두 접시를 준비해 줘”라는 부탁을 받는다. AI는 알고 있는 재료 짝의 결과·효과와 가진 수량을 비교해 한 짝과 자기 솥을 고른다. 자기 상자에서 부족한 재료를 꺼낼 수 있으면 그 동작을 계획하고, 불가능하면 모자란 사실을 보고 다른 재료·채집·질문 중 다음 행동을 고른다.

AI가 선택한 재료와 수량을 솥에 넣는다. 한쪽만 들어가거나 출력 칸이 막히면 그 상태를 전달한다. 요리 중에는 솥 곁에서 기다리거나 실행 가능한 다른 일을 고른다. 돌아왔을 때 솥의 현재 상태를 다시 보고 완성품을 꺼낸다. 가방에 정확한 요리와 수량이 들어온 뒤 현재 단계를 완료했다고 판단하고, 상위 AI가 원래 부탁의 완료 또는 다음 일을 결정한다. 누군가에게 전달하는 부탁이라면 전달 실행은 가방장비 작업의 기능을 사용한다.

현재 BestPair 계산은 추천·정렬·예측에 재사용할 수 있다. 가장 나은 한 짝만 허용하는 필터를 모델의 선택권으로 바꾼다. 이미 선택된 재료를 코드가 다른 짝으로 바꾸는 방식은 채택하지 않는다. 수량·재료 순서·다른 솥이 구분되는 후보를 만들고, 후보가 많으면 필요한 목록을 좁혀 더 조회할 수 있게 구체화한다. 정확한 응답 필드와 조회 방식은 이 계획의 범위가 정해진 뒤 명세에서 정한다.

## 기존 작업과 연결하는 방법

공통 실행은 이미 본 저장소에 통합되어 있다. 현재 행동만 중단하기, 현재 단계 완료하기, 상위에 다시 계획 요청하기의 계약을 그대로 사용한다. 요청 대기나 진척 없음만으로 유효한 행동을 시설 코드가 강제 취소하지 않는다. 중단/전환은 해당 실행 회차와 대상에 맞을 때 적용한다.

가방장비 작업은 정확한 물건 선택·장착/교체·부분 꺼내기/보관·전달을 맡는다. 시설 작업은 선택할 작업·입력과 수량·시설 상태·가공/수리 결과를 맡는다. 수리와 강화 전에 장비를 ObjectID만으로 뭉치지 않고 정확한 슬롯·variation·내구도·레벨로 식별하는 관측 계약을 맞춘다. 공동 수정이 필요한 연결은 한쪽이 소유하고 다른 쪽은 계약을 사용한다.

각 단계는 기존 후보·실행·관측 구조에 필요한 선택만 추가한다. 시설마다 처음부터 따로 만든 큰 자동 루틴이나 전체 그래프를 실시간 실행하는 새 엔진은 지금 필요하지 않다. 일반 제작·자동 가공·장비 상태 변경은 소비자와 결과가 달라 하나의 “사용” 동작으로 합치지 않는다.

## 지킬 조건과 검증

자기 상자·솥·밭의 기존 사용 범위와 알려진 제작법의 공개 범위를 유지한다. 호스트/다른 AI의 시설·재료를 공유하는 정책, 새 소비 예산, 희귀 재료의 일괄 사용 규칙은 이번 계획에서 정하지 않는다. 현재 목표 수량·시설 조건은 사실로 보고하고, 중요한 계획 변경은 위쪽 AI에게 맡긴다.

먼저 검수된 source/variation별 규칙을 고정하고 현재 코드와 대조한다. 그다음 선택지 생성·계획 응답·몸 실행·관측 보고의 오프라인 확인과 독립 검수를 한다. 특히 두 후보가 같은 이름으로 합쳐지지 않는지, 재료 일부만 옮겨진 경우·가방 가득 참·대상 교체를 실제 사실로 돌려주는지, 단계 완료와 원래 부탁 완료를 구별하는지 확인한다.

각 묶음의 완료는 표에 적은 대표 실게임 흐름으로 판단한다. **현재 실게임 보류가 유지되므로, 구현과 오프라인 확인이 끝나도 실제 플레이 검증 완료로 보고하지 않는다.** 시험을 재개할 때에는 사용자 상태 보존과 시험 월드 정리 조건을 기존 절차대로 적용한다.

## 범위와 남은 선택

이번 문서는 위 여섯 묶음의 단계별 계획이다. 지금 권고하는 첫 구현 범위는 1의 요리 흐름이며 나머지는 후속 묶음이다. 사용자 화면 추가는 현재 제안하지 않는다. 기존 자연어 지시·판단 입력·상태 보고의 내용이 달라지는 계획이다.

상점의 구매 소비자와 내구 강화는 추가 조사 후 세부 범위를 고정해야 한다. 아이템을 없애는 분해·일반 시설 회수/재배치, 자동화 공사와 기지 배치 설계는 현재 첫 구현 범위에 섞지 않고 별도로 정한다. 게임 내 지식 조회 전체 개편과 AI끼리 멘션 호출도 기존 후속 작업으로 유지한다.

사용자가 정할 실질 선택은 **추천대로 요리부터 작은 흐름을 완결할지, 당장 필요한 수리나 농사를 먼저 할지**이다. 공용 자원 접근과 장기 자율 소비 규칙은 해당 범위를 실제로 넓힐 때 정하면 된다.
