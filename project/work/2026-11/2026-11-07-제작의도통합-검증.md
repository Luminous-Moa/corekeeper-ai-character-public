# 제작 의도를 먼저 조회하는 프로젝트 그래프

프로젝트 그래프의 [작업 시작 안내](../지식그래프/README.md)와 [조회 방법](../지식그래프/제품그래프-사용법.md)에서 제작 의도, 작업과 관련된 합의, 원문 근거 순으로 읽는다. 재기획 전용 색인과 제품 그래프 모두 [같은 선언](2026-11-07-기획연결/source.mjs)과 [공통 생성 코드](2026-11-07-기획연결/compile.mjs)를 사용한다.

## 연결한 내용

기획 항목 39개와 참고 항목 12개, 그 사이의 관계 68개를 통합했다. 근거 문서는 재기획 10개와 참고 9개다. 제품 정의서에서 제작 의도로 이어지는 연결과 기존 기획을 참고하는 연결 4개를 더했다. 과거 제품 노드 5,973개와 관계 22,771개를 보존한 결과는 6,024개 노드와 22,844개 관계다. 항목의 지위와 각 연결의 해석 여부를 유지했다.

## 조회 확인

`node tools/product.mjs intent P.original-request`는 공동생활 경험 → 생활과 사용자 도움 → 목표 계층 → 중간 단계 뒤에도 원래 부탁 유지 순으로 읽힌다. 여기에서 기존 제작 활동 UA-03과 과거 구리 갑옷 관측 R.copper로 갈 수 있다.

- `source P.original-request`에서 현장 행동과 부탁 종료의 판단 주체, 구리 10/10의 의미를 원문으로 확인했다. [행동 취소의 판단 주체](2026-11-07-행동취소-판단주체.md)
- `source P.valid-action`에서 응답 대기 중 실행 가능한 동작을 이어 가는 조건을 확인했다. [공통 실행 합의](2026-11-07-공통실행-합의.md)
- `source R.copper`에서 11eb461 코드와 보존 로그 대조 범위, 당시 파기 취소와 상위 재계획 장면을 확인했다. 개선판의 실게임 성공 여부는 후속 확인 항목이다. [기존 조사](2026-11-07-동료행동-현재부족분.md)

원래 제품 노드와 관계 전체를 통합 전 해시와 대조해 내용이 같음을 확인했다. 재기획 51개 항목은 P.experience에서 모두 도달하며, 노드 근거 위치 60곳은 실제 문장과 원본 해시가 일치했다. `node tools/product.mjs check`의 구조 오류와 낡은 입력은 각각 0건이고, `node tools/product-build.mjs --check`에서 재생성 결과가 바이트 단위로 일치했다.
