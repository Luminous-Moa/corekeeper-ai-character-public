# 행동 결과 그래프의 선택지 활용 검토

사용자 요청은 현재 추출 중인 행동 결과 그래프를 살펴보고 판단 모델의 선택지에 활용하는 방법을 설명하는 것이다. 아래는 제안이며 제품 설계의 확정이나 구현 착수를 뜻하지 않는다.

## 확인한 사실

- [정본 설명](../게임행동-그래프/README.md): 대상 원본→행위/처리 단계→조건·결과·실패·근거 구조이다. sourceKey와 variation을 유지하며 현재 AI 소비 경로에는 연결되어 있지 않다. 주장 없음은 불가능 판정이 아니다.
- [증분 통합 설명](2026-11-07-행동결과완결/integration/PROGRESSIVE.md): 검수된 개별 적용과 공통 소비자 규칙을 분리하여 연결한다. 전체 수집과 정본 최종 통합은 진행 중이다.
- 현재 증분 그래프에서 8005 variation2 대상 조회→조건부 농사팔 적용→결과 필드→원문 조회를 실제 수행했다. 결과 설정 ID는8101이며 실제 성장·전력·위치·목적지 상태는 별도 관측이 필요하다.
- 판매 대상5010 variation0의 개별 적용에는 sellValue10, 양수 판매수량·UI/요청 gate 등의 조건, 수량n 소비와10×n 코인 생성이 연결된다. 실제 판매 실행은 확인하지 않았다.
- 삽 파기 사례는 도구/대상 역할, 입력, 조건, 처리 흐름, 내구도, 전리품 후보와 후속 수령 경계를 구별한다. 전리품 생성은 인벤토리 수령 완료와 다르며 가중치는 확률 자체가 아니다.
- [비전투 기존 합의](2026-11-07-비전투-연속판단.md)는 위쪽LLM의 목적·계획, Decisions의 반복 행동 선택, 코드의 몸 실행을 나눈다. 다음 대상도 판단 모델이 선택한다.

## 활용 제안

연결할 흐름: 현재 관측/허용된 기억의 대상과 목표 → 정확 원본에 해당하는 행동 규칙 조회 → 현재 상태 및 모드 실행 능력과 결합 → 구체적인 선택지 → 모델 선택 → 코드 실행 → 실제 변화 관측 → 다음 선택.

1. 그래프에서 대상·도구·재료·결과 역할을 보존한 행동 틀을 만든다. 내부 처리 단계와 자동 장치의 동작은 캐릭터가 직접 실행하는 행동과 구별한다. 자동장치 규칙은 조작 가능한 준비 행동의 결과 예측에 활용할 수 있으나 준비 행동 자체의 근거와 실행 지원을 별도로 확인한다.
2. 관측한 인스턴스/슬롯/좌표를 틀에 채운다. 거리·도구 소지·내구도·성장·전력 등은 현재 관측과 대조한다. 정적 prefab 값은 현재 인스턴스 상태로 취급하지 않는다.
3. 선택지에 구체 행동과 대상, 예상 변화, 소모·부작용, 충족/미충족/미확인 조건을 제공한다. 원문·해시·코드 경로는 내부 근거 참조로 둔다. 실제 실행 명령과 연결되지 않은 항목은 실행 가능한 선택지로 제시하지 않는다.
4. 준비가 필요한 후보는 이유와 필요한 준비를 남겨, 모델이 이동·장비변경·확인 등을 선택할 수 있게 한다. 준비 행동의 지원 여부도 확인한다. 코드가 임의로 넓은 작업이나 다음 대상을 결정하지 않는다.
5. 목표 결과에서 후보 행동을 역으로 찾으면 위쪽LLM의 계획을 도울 수 있다. 원본참조·동일ID관계·단순 그래프 경로를 실행 가능한 인과나 계획으로 취급하지 않고 조건·역할·수량을 확인한다. 캐릭터에게 허용된 지식 범위도 반영한다.
6. 실행 후에는 예측과 실제 관측을 비교한다. 드롭 생성, 수령 완료, 장치 처리 대기 등 완료 경계를 나누고 갱신 상태로 계속하기·다른대상·이동·중단 등을 선택하게 한다.

현재 자료는 행동의 가능성과 결과를 설명하는 기반이다. 지금 실행할 수 있는 구체 선택지를 만들려면 현재 월드 관측, 캐릭터의 지식 범위, 모드의 실행 수단 연결이 추가로 필요하다. 본 검토에서는 제품 코드·추출 그래프·게임을 변경하지 않았다.
