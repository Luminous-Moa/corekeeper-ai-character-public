# Jev 대체 공개 판단 모델: Core Keeper 후보 조사

확인일: 2026-11-03. 모델 다운로드·설치·유료 호출·성능 실측 없이 공식 모델카드, 원저장소, 공개 독립 평가를 조사했다. 디렉토리는 발견에만 사용했다. 조사 중 root가 읽기 확인한 PC는 **RTX 5080 16,303 MiB VRAM, 물리 RAM 약 32GB**다. 해당 PC에서 게임과 함께 모델을 실행한 결과는 없다.

## 판단

**우선 비교 후보군은 hosted `pplx-decider-v1.2`와 `pplx-decider-flash-v1.2`, API 대조군은 Cloudflare Clef/Clef-flash다.** 공개 가중치도 있어 배포 선택지가 남는다. 로컬에서는 Kev-4B의 GGUF 경로와 Mapika decider-2b를 조건부 후보로 두되, 게임 병행 자원 경합을 먼저 확인해야 한다. Laya는 매우 작은 비용으로 도메인 맞춤 학습을 할 때 유용할 후보이고, 지금 바로 범용 게임 판단을 맡길 근거는 약하다. 이는 후보 우선순위이며 Jev보다 반드시 낫다는 판정이 아니다. 두 Perplexity 후보 사이의 최종 순서는 root가 별도로 확인한 최신 주벤치 raw 결과와 합쳐 판단한다.

목적은 기존의 **큰 목표 → 판단 모델이 프로그램 후보 중 선택 → 프로그램 실행**이다. 평소 2~3초 간격은 잠정 조건이고, 응답이 늦는 동안 반사행동을 허용했다가 응답 시 해제한다는 세션 조건을 유지한다. 아래는 설계 변경안이 아니라 이 자리에 넣을 모델 비교다. 공개 평가 어디에도 Core Keeper 실제 전투·이동·자원수집 성공률을 입증한 자료는 확인하지 못했다.

## 6개 실용 후보군

### 1. Laya: 가벼운 로컬·특화용

- 정확한 ID: `convaiinnovations/laya`(ModernBERT-large 기반 421M), `convaiinnovations/laya-multilingual`(mmBERT 기반 322M), `convaiinnovations/laya-typed-decisions`(421M). Apache-2.0. SDK 버전과 체크포인트를 혼동하면 안 된다.
- Python SDK와 Jev 호환 `POST /v1/systemone`. 텍스트 상태를 받고 choice/score/noul을 반환한다. 영어 가중치 약 808MB, multilingual 약 647MB는 **파일 크기**다.
- 제조사 T4 측정: 한 질문 영어 39.5ms, multilingual 32.8ms; 10질문 158.6/72.3ms. CPU·게임 병행 결과가 아니다. Router 언어 전환 시 재적재 설정은 수 초를 만들 수 있다.
- 가장 중요한 제한: typed-decisions에서 영어 기본 0.362, multilingual 0.352, random 0.318, majority 0.461. 0.766은 그 벤치마크 학습 split으로 fine-tune한 모델이다. “76.6%”를 범용 zero-shot 정확도로 읽으면 안 된다.

출처: [Laya 공식 카드](https://huggingface.co/convaiinnovations/laya), [multilingual 공식 카드](https://huggingface.co/convaiinnovations/laya-multilingual).

독립 연구는 18개 공개 원천에서 만든 7,283 기본 사례와 6,640 변형을 비교했다. Jev가 11개 의사결정 지점 중 9개에서 유의하게 우세했고, Laya는 옵션 순서 반전 시 약 30%의 답이 바뀌었다. 유사한 도구 50개 중 선택에서는 Laya 31%, Jev 98%였다. 속도는 RTX 2080 Ti p50 31ms, M4 CPU 200ms; Jev API는 클라이언트 위치에 따라 325ms 또는 83ms였다. 특정 버전·영어 중심·zero-shot 결과이며 한국어 게임 상태 전체로 일반화할 수 없다. [독립 논문과 원자료 링크](https://arxiv.org/html/2610.02267v1)

### 2. Kev 1.0: 비교적 투명한 로컬 선택지

정확한 후보는 `jaredpalmer/kev-4b`와 저자원 대안 `jaredpalmer/kev-0.8b`다. 과거 Qwen2.5-0.5B 기반 Kev의 수치를 현재 모델에 붙이지 않는다. 현재 1.0은 Qwen3.5-Base의 0.8/4/9B, Qwen3.8의 27B 계열이며 Apache-2.0이다. TypeSafe System One 호환이고 한 요청의 질문들은 상태를 공유하지만 서로를 읽지 않는다. [공식 저장소](https://github.com/jaredpalmer/kev)

| 버전 | 제조사 지연 측정 | 자원·정확도 근거 |
|---|---|---|
| Kev-4B 1.0 | BF16+fused kernels+CUDA graphs, 20회 median. 신규 짧은 상태 6질문: L40S 41.5ms, H100 18.1ms. 2,200토큰 5질문: 145.2/89.4ms | resident GPU 14.3GB. 미학습 원천/정책 구조의 locked transfer-v4 test 656문항 정확도 0.838; breadth test 3,089문항 0.690. 모두 제조사 평가 |
| Kev-0.8B 1.0 | 같은 방식 L4: 신규 짧은 상태 6질문 22.7ms, 2,200토큰 5질문 108.6ms | resident GPU 3.8GB. 같은 transfer test 0.697, breadth test 0.586. 자원 절감과 일반화 성능 저하가 함께 있음 |

출처: [Kev-4B 카드](https://github.com/jaredpalmer/kev/blob/main/docs/model-cards/kev-4b.md), [Kev-0.8B 카드](https://github.com/jaredpalmer/kev/blob/main/docs/model-cards/kev-0.8b.md).

RTX 5080에서 4B 공식 구성의 14.3GB 점유는 게임용 여유를 거의 남기지 않는다는 **자원상 추론**이다. ggml-org가 Kev-4B GGUF와 `/v1/systemone` 지원을 공개했으므로 양자화 경로는 실제 존재한다. 단, 소개의 12ms는 RTX PRO 6000의 한 질문 median이며 5080·양자화별 품질·게임 병행 지연을 증명하지 않는다. [ggml-org 공식 소개](https://huggingface.co/blog/ggml-org/decision-models-in-llamacpp)

독립 Opper 평가는 출시 이후 게시된 362개 사례에서 Jev/Kev-4B가 대체로 비슷했다. arXiv 분류 96.9/95.0%, Stack Exchange 분류 97.5/98.3%, GitHub 이슈 분류 95.1/93.9%. 동일 endpoint와 요청을 사용했지만 쉬운 분류가 중심이고, 5%p 미만 차이는 표본 잡음 범위라고 저자가 명시한다. 2026-09-24 당시 hosted `opper/kev-4b` 결과이지 최신 로컬 빌드 보증은 아니다. [코드·방법](https://github.com/opper-ai/jev-vs-kev), [원결과](https://github.com/opper-ai/jev-vs-kev/blob/main/results.md)

### 3. Mapika decider-2b v12: 작은 멀티모달 후보, 기본 확률 설정 주의

`Mapika/decider-2b`, **v12(2026-10-20)**, Qwen3.5-2B-Base 기반 약 1.9B 텍스트 모델. BF16 텍스트 가중치 3.8GB와 별도 vision tower 0.6GB. Apache-2.0 표기지만 카드가 학습 원천별 NC 등 별도 이용조건도 공개한다. 코드 `decider-ai` 1.10.0부터 영상이 아닌 **이미지** 입력 지원; Python 및 `POST /v1/systemone`. [공식 모델카드](https://huggingface.co/Mapika/decider-2b)

v12 공개 Decision Index 0.3의 **4,500-request 부분 표본** 38.17은 제조사 자체 측정이며 전체 suite/독립 검증이 아니다. 일부 benchmark train split을 학습했고 두 checkpoint 중 선택할 때 benchmark readout도 보았다. 기본 noul temperature 0.05는 JevBench의 0.2~0.8 확률 오답 규칙을 위해 확률을 극단화한다. 399개 held-out yes/no에서 ECE 0.341이며 fitted temperature이면 0.095다. 실제 오류 확률로 이용하려면 기본 출력이 보정됐다고 가정할 수 없다. 같은 카드에 이 한계가 명시돼 있다.

v12 지연 재측정은 없다. 공개 speed는 **v10, B300 한 장, decider-ai 1.2.1, 약 230토큰 상태+3질문**: eager 18.9ms, compiled CUDA graph 3.2ms, BF16 HTTP 단일 client p50 6.1ms. 이 값을 RTX 5080에서 6ms라고 옮기면 안 된다. [원저장소 모델카드·측정조건](https://github.com/Mapika/decider/blob/main/MODEL_CARD.md)

### 4. Perplexity 27B: v1.1보다 v1.2를 신규 비교 대상으로

`perplexity-ai/pplx-decider-v1.1-27b`와 후속 `perplexity-ai/pplx-decider-v1.2`는 Qwen3.8-27B 기반, Apache-2.0 공개 가중치다. v1.1 저장소는 약 52.2GB다. BF16 로컬 27B를 16GB GPU 게임 동시 실행의 기본 후보로 두기 어렵다. v1.1은 한 forward당 질문 하나; v1.2는 질문별 marker에서 joint readout한다. 일반 causal LLM 서버나 LM head로 그대로 로드하면 평가된 동작과 달라진다. [v1.1 카드](https://huggingface.co/perplexity-ai/pplx-decider-v1.1-27b), [v1.1 파일](https://huggingface.co/perplexity-ai/pplx-decider-v1.1-27b/tree/main)

v1.2 공식 Decision Index 0.3(public) 68.09(joint)/67.75(질문별), 같은 카드의 v1.1 62.30. 원래 v1.1 발표의 61.56과 서로 다른 suite 판독을 혼용하지 않는다. v1.2는 benchmark train split 일부를 학습하되 test와 decontaminate했다고 공개한다. joint는 관련 속성에 유리하고 독립 tool/document 후보를 질문별로 나열하면 성능을 떨어뜨릴 수 있다. 공개 27B 로컬 성능은 GB200에서 평균 1,050토큰·1~64질문 request의 최적 경로 약 19.8req/s **throughput**이지 단일 요청 왕복 50ms가 아니다. [v1.2 공식 카드](https://huggingface.co/perplexity-ai/pplx-decider-v1.2)

### 5. Perplexity Flash v1.2: 최신 소형 비교 후보

`perplexity-ai/pplx-decider-flash-v1.2`는 공식 명칭상 Qwen3.5-4B 기반(카드의 HF 자동 집계는 5B 표기), Apache-2.0. 텍스트·이미지 지원. 공개 DI 0.3은 joint 58.88, 질문별 60.05다. 공개 가중치의 joint 질문은 서로 영향을 주며 BFCL에서 질문별 대비 −15.4점 사례가 보고돼 있다. 27B보다 작지만 실제 Windows 상주 메모리와 게임 병행 short-state p95는 확인하지 못했다. 카드의 243k-token GB200 측정(수십 GB·20초)은 초장문 검사이며 평소 게임 상태의 지연 근거로 쓰지 않는다. [공식 Flash 카드](https://huggingface.co/perplexity-ai/pplx-decider-flash-v1.2)

**Perplexity hosted API와 공개 가중치의 구분:** endpoint는 `POST https://api.perplexity.ai/v1/decisions`. 현재 hosted v1.2는 input $0.02/M, Flash $0.01/M, output 무료. 27B는 질문을 묶어 상태를 한 번 과금하지만 Flash hosted는 질문을 각각 처리해 상태도 질문마다 과금한다. 공개 Flash 가중치의 joint 가능성과 다르다. 현재 v1.1 API 이름은 v1.2를 선택하며 응답의 `model`은 요청 이름을 그대로 되돌리므로 실행버전 확인 수단이 아니다. 과거 수백 토큰 요청 <2초라는 공식 기록은 이전 모델·2026-09-30 측정이며 최신 모델의 한국 p95 보장이 아니다. [공식 API 계약](https://docs.perplexity.ai/docs/decisions/quickstart)

### 6. Cloudflare Clef/Clef-flash: API 대조군

`Cloudflare/clef` 27B(Qwen3.8), `Cloudflare/clef-flash` **9B**(Qwen3.5), Apache-2.0. 공개 가중치와 hosted Workers AI 양쪽이 있고 Jev/System One 호환이다. Flash를 4B 모델로 오해하지 않는다. 공식 로컬 예시는 두 모델 모두 H200에서 테스트했다. BF16 가중치만 단순 계산해도 9B 약 18GB, 27B 약 54GB이며 실제 전체 메모리는 더 필요하므로 이 PC의 기본 로컬 후보로는 맞지 않는다. 양자화 시 별도 검증이 필요하다. [Clef 카드](https://huggingface.co/Cloudflare/clef), [Flash 카드](https://huggingface.co/Cloudflare/clef-flash)

제조사 43-run 출시 benchmark의 p50/p95는 Clef 209.3/238.6ms, Flash 38.8/122.4ms, Jev 524.1/536.0ms. 같은 회사의 10월 9일 serving 개선 기록에서는 Clef 약 800토큰 152/351ms, 3,400토큰 305/531ms, 16k토큰 1,635/1,805ms다. **별도 시점·입력 조건**이며 한국 PC 왕복을 측정한 자료는 아니다. 현행 게시 요금은 Flash $0.038/M input, Clef $0.240/M; hosted context 24k/64k. [출시 발표](https://developers.cloudflare.com/changelog/post/2026-10-01-clef-workers-ai/), [개선·가격 발표](https://developers.cloudflare.com/changelog/post/2026-10-09-clef-omni-workers-ai/)

## 독립 평가가 말하는 범위

`etsabary/system-1-decision-benchmark`의 2026-11-02 v4 공개 결과는 43범주 2,157문항에서 Perplexity v1.2 76.50%, median 247ms/p95 374ms를 보고한다(usable 2,156/2,157). Clef는 60.22%. 그러나 기존 문항은행 대부분이 프로젝트 작성물이고, 양적 추론 문제 일부는 다른 모델이 틀린 항목을 선택한 편향을 공개한다. 모델 제공자와 독립인 공개 **1차 실험**으로 참고하되, 비공개 held-out·한국 지역·게임성공률·장기 SLA를 뜻하지 않는다. 검색 인덱스의 옛 v1/v2 점수와 현재 v4를 섞지 않는다. [원저장소 v4 결과·방법](https://github.com/etsabary/system-1-decision-benchmark)

한국어 관련 독립 근거는 `tak-bro/local-jev-bench`에 있다. M3 Max 36GB idle 상태에서 영어·한국어 ticket, BANKING77, NSMC, KLUE-YNAT 등과 순서 반전을 검사했다. 모델·runner·양자화가 다양하고 일부 Mapika 실행은 CPU여서 속도 순위를 GPU 결과와 바로 비교할 수 없다. 한국어 30문항 결과만으로 일반화하지 않는다. 이 자료에서도 Laya-typed-decisions의 우세는 그 학습 도메인에 국한되며, 한국어 뉴스/감성과 게임 상태 판단은 다른 과제다. [원저장소와 원결과 연결](https://github.com/tak-bro/local-jev-bench)

## 출력 의미와 비교 시 꼭 지킬 구분

1. **choice의 argmax는 행동 후보 ID 선택에 대응한다.** `score`는 순서가 있는 수준의 기대값이다. 예컨대 확률 `[0.5, 0, 0.5]`의 기대 점수는 1이지만 가장 그럴듯한 중간 행동이라는 뜻은 아니다. 행동 ID를 0,1,2로 놓고 score를 반올림하면 의도와 달라진다. 이것은 API 의미 설명이며 기존 설계를 변경한 것이 아니다. [공식 score 정의](https://docs.perplexity.ai/docs/decisions/quickstart)
2. **확률과 confidence를 혼동하지 않는다.** 적어도 Perplexity choice confidence는 top probability 자체가 아닌 균등분포 대비 정규화 수치다. 다른 구현도 필드 의미를 각각 확인해야 한다. 공개 calibration 점수는 평가 분포에서만 관측된 결과이며 Core Keeper 성공 확률 보증이 아니다. [공식 응답 정의](https://docs.perplexity.ai/docs/decisions/quickstart)
3. **held-out 문항 ≠ held-out 도메인 ≠ 한 번도 개발에 사용하지 않은 테스트.** 학습 split이 있는 공개 benchmark의 test 고득점, checkpoint 선택에 쓴 development 성적, 완전히 새 원천 test, 공개 소수 문항을 따로 취급한다. 선택지 순서·유사 후보·후보 개수·이미지 유무도 고정해야 비교가 된다.
4. **로컬 model time ≠ API RTT ≠ 게임 부하 중 결정을 적용할 때까지의 시간.** 후자에는 직렬화·전송·대기·전처리·실행 연결이 포함된다. 모델을 상주시키지 않았거나 최초 compile/warmup이면 수 초 이상의 다른 분포가 된다. 평균 throughput을 개별 응답 시간으로 역산하지 않는다.
5. 한국 Windows라는 위치·운영체제와 입력 언어는 별개다. 영어/한국어 상태 표현을 정하지 않은 상태에서 multilingual이라는 이름만으로 적합성을 정할 수 없다. MLX/Mac 성능은 Windows 성능이 아니다.

## 월 10만원 조건에 대한 계산 참고

**가정 계산:** 하루 2시간, 30일, 2~3초마다 1요청, 요청당 실제 과금 input 1,000토큰이면 월 72,000~108,000요청, 72~108M input이다. 위 공식 단가를 대입한 판단 모델 부분만의 비용:

| API | 월 USD 추산 |
|---|---:|
| pplx-decider-v1.2 | $1.44~2.16 |
| pplx-decider-flash-v1.2, 질문 1개 | $0.72~1.08 |
| Clef-flash | $2.74~4.10 |
| Clef | $17.28~25.92 |

이는 환율·세금·큰 목표용 LLM·이미지 토큰·재시도·다중 질문의 상태 반복 과금을 제외한 계산이다. 10,000 input이면 10배다. 월 10만원의 전체 적합성을 이 표만으로 확정하지 않는다. 특히 Flash의 복수 질문은 전송 payload 1,000토큰과 실제 청구 토큰이 다를 수 있으므로 `usage.input_tokens` 기준이어야 한다.

## 인계 결론

신규 후보 검증에서는 **pplx v1.2와 Flash v1.2 API를 Jev와 같은 게임 상태·같은 후보로 비교하는 것이 현재 근거상 우선**이다. Clef-flash는 비용/속도 대조군이고, 로컬은 5080 자원 확인 후 별도로 판단한다. 2~3초 목표는 공개된 짧은 입력 측정으로 가능성을 볼 수 있지만 한국 경로 및 게임 병행 p95·오래된 상태에서 선택한 행동의 유효성은 미확인이다. 현 단계에서는 설치·API 전환·설계·세션 기록 변경을 수행하지 않았다.
