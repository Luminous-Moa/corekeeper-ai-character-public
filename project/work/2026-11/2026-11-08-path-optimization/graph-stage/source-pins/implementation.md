# 길 계산 최적화 구현

후보 커밋은 `2a0112d`이며 격리 작업 경로는 `C:/Dev/CoreKeeperModSDK-path-opt`, 브랜치는 `ai-path-optimization-20261108`이다. 공식 출발점은 `7af8f91`이다.

## 동작

- 후보 생성과 경로 내부 탐색, 경로 복원, 위험 설명, 요청 JSON의 후보 직렬화를 메인 스레드에서 단계별로 이어 실행한다. 모든 AI가 한 프레임의 3ms 목표 예산을 공유하고, 예산을 받지 못한 AI는 다음 프레임에 먼저 진행한다. 한 작업 단위 자체가 예산보다 오래 걸릴 수 있다.
- 후보 준비 한 번에 만든 경로 결과를 준비가 끝날 때까지 보존한다. 후처리에서 같은 경로의 설명과 위험을 만들 때 완성된 결과를 재사용한다. 일반 경로 힌트의 64개 초과 전체 삭제는 256개 한도에서 가장 오래된 항목 하나를 교체하는 방식으로 바꿨다.
- 같은 후보 준비의 모든 경로는 배치가 캡처한 출발 위치, 도구 피해, 장애물, 타일·문·경계 사실을 공유한다. 경로별 검색 순서와 실패 진단은 각 경로 작업에 속한다. 전송 직전에 배치가 읽은 고유 타일 집합을 검증한다. 변경되면 전체 준비를 취소하고 다시 준비한다.
- 위협 관측을 준비 중에도 실행한다. 새 적, 사라진 적, 대기 중 위협 집합 변화, 피해와 급박한 사건, 목표·실행·월드 변경은 준비 취소에 연결한다. 프리패치 중 원래 행동이 정상 완료되면 완료 사실을 보존하고 실패하면 해당 준비를 취소한다. 플레이어 또는 thin world 소멸 시 준비를 해제한다.
- HTTP 400 등의 오류 응답에 `error.message`가 없으면 응답 본문을 최대2048자로 기록한다. API 키 패턴을 가리고 request ID를 함께 기록한다. 준비가 여러 프레임 걸린 경우에도 실제 전송 직전에 시각과 비용·호출률 가드를 다시 확인한다.
- 평상시 SEND 로그는 후보 수와 준비 통계를 기록한다. 전체 선택지는 API 요청에 포함되며 기존 `decisionlog.on`은 원문 기록을 제공한다.

## 남은 측정과 경계

배치의 lazy 사실 수집과 최종 검증은 시간 구간에 걸친다. 원자적 세계 스냅샷을 보장하는 epoch는 없다. 후보는 캡처한 관측 위치 기준임과 준비 경과시간을 입력에 명시하고, 실제 행동은 기존 대상·경로 재검사를 거친다. 초기 관측, 일부 소수 생활 기능의 동기 PlanC 호출, 단일 장애물 쿼리, BuildInput과 최종 문자열 버퍼 변환 비용은 실행 단위로 남는다. 따라서 전체 모드의 모든 프레임을3ms이하라고 표현하지 않는다.

실기 담당 `/root/path_live_verify`에 검수 수용 후보를 전달했다. 임시 설치와 전용 ai2 월드 검증은 HEAD가 소유하며 결과를 받은 뒤 최종 통합·설치 여부를 판단한다. 이 문서 작성 시 실게임 완료 수치는 아직 없다.

## 반영 파일 범위

제품 코드와 필요한 회귀·벤치마크 소스23개 파일을 커밋했다. 작업 폴더의 Packages·ProjectSettings 변경과 `Assets/Plugins/CoreKeeper`는 Unity 검증을 위해 공식 작업 폴더의 기존 환경을 복사하거나 Unity가 생성한 로컬 파일이다. 해당 환경은 커밋에 포함되지 않는다. 공식 작업 폴더의 기존 dirty 파일은 수정하지 않았다. 처음 로컬 커밋에 포함된 새 테스트의 bin/obj를 확인하여 파일 추적을 해제하고 전용 .gitignore를 추가한 뒤 현재 커밋으로 정정했다.
