# 기존 선택 트리와 255개 초과 요청 독립 감사

2026-11-08. 대상 `2a0112d`와 현재 생산 코드. 코드 수정 없이 정본 합의, 실제 호출 경로, 258개 요청의 전체 decisions 로그, 452개 요청의 SEND 로그를 대조했다.

## 결론

기존 생활·가방·채집이동 트리는 모두 구현돼 있다. 특히 채집이동 트리는 현재 오류에 직접 관련된다. 그러나 첫 요청에서 트리가 닫혀 있으면 모든 직접 행동 후보를 그대로 보내고 그 끝에 트리 열기 하나를 추가한다. 255개를 넘은 이 요청이 실패하면 모델이 트리 열기를 선택할 기회 자체가 없다.

258개와 452개 요청에서 생활·가방·채집이동의 각 트리 진입 항목은 하나씩이었다. 초과분의 대부분은 파들어가기·기억 광석·개별 벽 캐기다. 생활의 다섯 항목 페이지를 없앤 변경만으로 이번 초과를 설명할 수 없다. 기존 트리를 실제 전송 선택면에 연결하는 방식과 한 갈래 안의 전체 leaf 노출이 핵심 결함이다.

## 합의와 범위

- 생활 트리 합의는 농사, 제작, 요리, 가방·상자 정리 등 생활 행동의 필요한 수준을 탐색하고 이미 구체화한 실행은 바로 선택하는 계약이다. 첫 명세는 제작·요리·농사·보관/꺼내기 네 갈래를 연결했다. 일반 수리·단일 레벨 업그레이드·회수는 같은 생활 트리에 추가됐다. [생활 합의](../2026-11-07-생활트리구현/00-agreement.md), [첫 명세](../2026-11-07-생활트리구현/03-spec.md), [정비 합의](../../장비정비-트리/00-agreement.md)
- 가방 트리 합의는 현재 노드의 실제 항목을 모두 제공하고 분류로 선택 범위를 나누도록 정했다. 임의 숫자 잘림과 페이지 분할을 철회했다. 당시 가방 작업 범위에서는 채굴·전투·시설 전체의 다단계 재설계를 제외했다. [가방 트리 합의](../2026-11-07-가방장비구현/tree-agreement.md)
- 후속 채집·이동·귀환 합의는 눈앞의 채집 묶음, 현재 이동 계속, 이미 정해진 목적지의 직접 실행과 다른 대상·장소를 찾는 얕은 트리를 병행하도록 승인했다. 그러므로 생활 트리의 범위가 좁다는 설명만으로 현재 상태를 설명하면 이 후속 구현을 빠뜨리게 된다. [확정 합의](../2026-11-07-채집이동귀환-확정합의.md), [역할과 트리 검토](../2026-11-07-채집이동귀환-트리검토.md)
- 제약 해제 합의는 생활 분류 기능을 유지하면서 당시 설명된 5항목 페이지 제한을 제거한다고 명시했다. 후보를 임의로 삭제하는 상한과 분류를 통한 단계 탐색은 다른 계약이다. [제약 해제 합의](../2026-11-07-제약해제/00-agreement.md), [해제 대응표](../2026-11-07-제약해제/coverage.md)

## 다섯 항목 페이지 제거의 해석

`c3a02ef`의 AILife 변경은 `Page * 5`와 `start + 5`, prev/next를 없애고 현재 깊이를 끝까지 보여준다. 이 부분은 저장된 제약 해제 합의와 맞는다. 같은 변경에서 열린 생활 화면의 `actual.FindAll(continue/eat/doorclose)`도 `new List(actual)`로 바뀌었다. 그 결과 생활 트리를 열어도 다른 일반 행동의 전체 목록을 계속 합친다. 이 추가 효과는 단순 페이지 크기 제거보다 넓고, 트리로 선택 범위를 줄이는 효과를 약화시킨다.

다만 확인한 258·452 요청은 생활 트리가 닫혀 있었으므로 열린 생활 화면의 변경을 두 오류의 직접 원인으로 단정할 수 없다. 이번 오류의 직접 경로는 전체 직접 후보를 먼저 보내야만 트리를 열 수 있는 초기 선택면과, 마지막에 제한 없이 단일 choices 배열을 만드는 연결이다.

## 후속 검수에 넘기는 판단

기존 트리 누락 여부를 따지면 코드 자체는 존재하고 정상 응답 처리에도 연결돼 있다. 실기에서 그 탐색을 시작할 수 있는 요청이 성립하지 않았다. 또한 채집이동의 kind 단위 분류 뒤에도 350개 dig가 한 말단에 남을 수 있다. 기존 합의의 직접 실행·얕은 탐색·모든 후보 접근 가능성·현재 행동 보존을 함께 만족하도록 이 연결을 수정하고 검증해야 한다. 임의 255개 잘림이나 옛 5개 페이지 복원은 이번 감사에서 제안하지 않았다.

조회 중이던 경로 검색 최적화와 이 오류는 함께 추적한다. 기존 생산 흐름은 트리의 현재 노드를 정하기 전에 모든 후보의 경로와 위험을 만든다. 따라서 트리 연결을 다루면서 실제 필요한 경로 평가 범위도 검증해야 하며, 분류 선택 전 필요한 알려진 위험 정보를 누락해서는 안 된다.

탐험 후보의 두 경로는 구별해야 한다. `lExplore`의 화면 안 걷기 후보는 `ReachableInView`의 BFS 거리 `_reachDist`를 재사용하며 PlanC를 호출하지 않는다. 별도 언급된 553개 화면 안 후보를 553회 터널 경로 검색으로 해석할 수 없다. 이번 긴 준비의 `fr` 7,526개는 기억한 탐험 끝을 순회해 `PreparePlan → PlanC → lDigExplore`로 가는 `kind=dig` 경로다. 이 경로가 목적지별 터널 검색을 반복했다.
