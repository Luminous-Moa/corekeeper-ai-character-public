# 개발 지식그래프 개편 기준

사용자 요청: 코어키퍼 AI 작업 세션에 연결하고 플러그인에 포함된 지식그래프 제작 방법에 따라 개편한다. 사용자가 대상을 개발용 지식그래프로 확인했다.

## 결과

기존 개발 그래프를 사용자 활동 → 실제 화면/출력 → 기능 → 코드 → 데이터/외부 연결로 탐색하고 원문으로 돌아갈 수 있는 제품 그래프로 개편한다. 기존 정책·후보·미결·게임 코드 참조와 근거의 역할을 보존한다. 게임 아이템·레시피 데이터 그래프는 개편 대상이 아니다.

## 기준과 보존 조건

- 제작 지침: C:/Dev/_ref/head-agent-core/graph/build/02a-graph-definitions.md 및 02b-graph-workflow.md. 조회 참고 구현: 같은 graph/head-context-0.9.5/의 hc_graph.py, LLM.md.
- 기존 개발 그래프: C:/Dev/.head/sessions/코어키퍼-AI-캐릭터/work/지식그래프/. 기존 기획 문서와 그 인용 원문이 의도의 기준이다. 추정·관측·결정·투영을 섞지 않는다.
- 코드 기준: C:/Dev/CoreKeeperModSDK HEAD e82eb87f25641cc7c31e6216f64e20a34e58d0c0 (착수 시점). 진행 중인 전투-단계2의 코드·실행 결과는 기준판과 구별한다. 실행 환경이 다르면 버전 차이를 기록한다.
- 제품 코드·게임 월드·캐릭터 저장·실행 중인 전투 시험과 세션 context.md는 변경하지 않는다. 기존 Unity 생성 변경 및 ai-bridge 실행 데이터도 보존한다. 격리된 시험 환경으로 관측 가능한 출력과 읽기 전용 실제 상태를 확인한다. 실게임 조작이 필요하고 다른 작업과 충돌할 때는 그 필요와 차이를 HEAD에 보고한다.
- 새 구조는 원본으로 재생성한다. 코드 신원은 기계 추출, 문서 ID는 문서에 둔다. 기존 ID와 사용자 결정 근거를 추적 가능하게 유지한다. 실제로 확인하지 못한 상태는 미확인으로 표시한다.
- A(실제 사용)와 B(코드)는 서로 결과를 입력으로 받지 않는다. A-3, B-7, C, C-3, D 및 독립 검수는 제작 지침에 맞는 별도 컨텍스트에서 한다. 판단에 필요한 세부를 각 담당자에게 주고 HEAD는 전체 결과와 보존 조건을 판단한다.
- 파일은 이 폴더에 작업별로 두고 최종 사용 경로는 기존 개발 그래프 README에서 안내한다. 기존 도구의 유용한 조회·근거·낡음 검사는 살리거나 대응 경로를 제공한다.

## 완료 의미

대표 활동 하나를 실제 실행부터 원문 조회까지 연결한 다음 기존 개발 그래프 범위로 확대한다. 재생성 일치·깨진 참조 검사·기록한 씨앗의 비대표 표본 원문 대조·실제 질문 탐색·독립 검수의 중요 지적 해결로 판단한다. 검사 개수나 노드 수만으로 완료 처리하지 않는다. 실행 불가능한 부분이나 추출 경계는 최종 안내에 명시한다.

## 사용자 범위 조정

실제 화면 확인 관련은 사용자의 요청으로 후속 작업으로 미룬다. 컴퓨터 유즈에 의존하는 실제 게임 화면 탐색·화면 원본/위치 매칭·게임 화면 기반 처음 온 사용자 검증은 이번 완료 조건에서 유예한다. 나머지 코드 추출·기존 의도 통합·조회 도구·정합성·독립 검수는 먼저 완료한다. 이미 확보했거나 격리 실행으로 확인 가능한 실제 HTTP 출력은 근거로 사용하되 실제 게임 화면 확인 완료로 표현하지 않는다.
