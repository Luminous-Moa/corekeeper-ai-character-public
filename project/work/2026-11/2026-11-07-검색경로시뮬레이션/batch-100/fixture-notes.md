# Fixture와 조회 경계

세 장면 모두 새 부탁은 구리 광석 4개 확보이다. 위치·조건·이력은 합성 장면이며 현재 게임 월드의 사실이 아니다. 도구 등급 2 필요 및 등급 2 준비에 재료 1개가 든다는 설정은 시험 전제다. 장면 3은 memory.json의 옛 좌표와 이후 고갈 관측이 상충하는 경우다.

기존 memgraph.mjs의 context/runQueries를 그대로 사용한다. resource_history는 goal 조회와 같은 events.jsonl 원본 사건의 관측 cause·당시 조건을 함께 반환한다. 기존 goal 요약은 상세 cause를 생략하므로 이 보충 없이 정확한 필요 도구 등급과 고갈 관측을 평가할 수 없다. resource_sites는 near 조회에 같은 memory.json의 정확한 oreXY/oreId 좌표와 fixture 관측시각을 보충한다. 기존 near는 광석 개수만 반환하므로 이 두 보충은 시험용 API 제안이며 현행 제품 API의 성능이라고 하지 않는다. 두 경로 모두 같은 조회 도구를 사용한다.

모델에 주는 초기 목차는 동일한 두 조회 항목의 설명이다. 원래 memoryIndex가 아니라 새 API 비교를 위한 최소 목차다. 세 장면 기대 답과 이름은 판정 파일에만 있고 모델 입력에는 없다. 원래 제품 brief 대신 역할·출력 형식만 적은 시험 프롬프트를 사용하므로 실제 제품의 전체 입력량과 동일한 지연 실험은 아니다.
