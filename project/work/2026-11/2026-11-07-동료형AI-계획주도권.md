# 동료형 AI의 판단과 기억 관리 방향

2026-11-07 합의 정리. AI가 사용자의 부탁을 이해하고, 자기 상태와 주변 상황을 보며 목표에 도달하는 방법을 직접 정하는 게임 동료를 지향한다. LLM이 기억과 관찰을 바탕으로 계획을 세우고 수정하며, 코드는 실제 행동을 수행한다. 기억은 자동 기록을 유지하면서 LLM의 판단으로 신뢰도를 낮출 수 있게 하고, 기준 미달 정보는 복구 가능한 비활성 상태로 남긴다.

## 판단 주체와 실행 단위

LLM이 목적지, 작업 대상과 수량, 필요한 준비, 작업 순서와 대안을 정한다. 코드는 지정된 작업의 길 찾기, 이동 입력, 채굴·타격, 제작 요청과 결과 확인을 담당한다. 계획 단위는 어느 광맥에서 얼마를 캐고 어느 제작대로 갈지처럼 의미 있는 작업이다.

기억을 읽는 기술적 주체보다 읽은 정보로 작업 방법을 결정하는 주체가 중요하다. 코드는 기억 조회를 수행하고 실행 가능성을 검사할 수 있지만, 최종 목표만 받은 뒤 준비·조달 과정을 미리 결정하여 후보로 한정하는 방식에서 LLM이 조회와 계획을 주도하는 방식으로 옮긴다. 한 칸 이동이나 타격마다 LLM을 호출하는 구조는 필요하지 않다.

## 판단에 필요한 정보와 도구

충분한 행동 도구와 함께, LLM이 선택을 비교할 수 있는 정보를 제공하는 것이 핵심이다.

- 현재 관찰: 주변 대상, 가방, 체력·배고픔, 장비 상태와 작업 진행.
- 공간 기억: 기억한 자원·제작대·상자의 위치와 마지막 관측 정보.
- 경험 기억: 과거 목표 결과, 막힌 이유, 관련 장소·적·동료와 당시 조건.
- 게임 지식: 캐릭터에게 열린 제작법과 행동 조건.
- 실행 결과: 완료 여부, 실제 확보량, 진행하지 못한 이유, 새 발견과 상태 변화.

LLM은 필요한 정보를 조회하고, 대상과 장소를 지정해 작업을 실행하며, 결과에 따라 계속·중단·순서 변경을 결정할 수 있어야 한다. 도구의 세부 API는 아직 정하지 않았다.

## 현장에서 계획을 바꾸는 흐름

원래 부탁과 현재 계획을 유지하면서 현장에서 발견한 기회도 판단한다. 파밍 도중 다른 자원이나 음식이 보이면 추가 채집, 잠깐 조사, 위치만 기억, 귀환 중 무엇이 나은지 정할 수 있다. 추가 작업의 가치와 원래 부탁을 늦추는 비용을 함께 고려한다.

목표 수량 충족은 코드가 확인할 수 있는 사실이다. 파밍 종료와 귀환은 주변 상황을 본 LLM의 결정이다. 매 순간 호출하기보다 의미 있는 작업 결과나 상황 변화에서 계획을 다시 판단하는 방향이며, 정확한 호출 조건과 빈도는 후속 설계 사항이다.

예를 들어 철검 제작을 부탁받으면 제작 조건과 현재 자원을 확인하고, 기억에서 재료 조달 위치를 조회하여 작업 순서를 정한다. 현장에서 유용한 자원을 발견하면 가방·체력·시간을 고려해 추가 작업 여부를 판단한다. 예상과 다른 결과가 나오면 계획을 수정하고 제작 완료까지 이어 간다. 이는 목표로 하는 흐름이며 현재 철광석 채집 등 행동 연결의 공백은 별도로 보완해야 한다.

## 기억의 신뢰도와 비활성화

공간 기억과 경험 기록의 자동 저장은 유지한다. 이번 기억 편집 범위는 LLM이 실제 경험과 대조해 특정 기억의 신뢰도를 낮추도록 요청하는 것이다. 자유로운 교훈 작성이나 관계 편집 체계까지 확장하지 않는다.

1. LLM이 특정 기억과 실제 확인 결과가 다르다고 판단한다.
2. 해당 기억을 지정해 신뢰도 하락을 요청하고, 코드는 기존 값을 갱신한다.
3. 신뢰도가 기준 아래로 내려가면 정보를 비활성화한다.
4. 비활성 정보는 일반 검색·목차·판단과 행동 후보의 근거에서 제외한다. 필요할 때 확인하거나 복구할 수 있도록 남긴다.

비활성 표시만 붙여 평소 입력에 계속 노출하는 것은 이 방향과 다르다. 정보가 쌓이는 것과 LLM에게 보여주는 정보가 늘어나는 것을 구분한다. 감점 때마다 새 해석 문서나 기억 사본을 누적할 필요는 없다.

다음 조건을 지킨다.

- 같은 확인 결과를 반복해서 감점하지 않는다. 같은 기억을 여러 번 읽거나 같은 주장을 반복한 것은 새 근거가 아니다.
- 확인하지 못한 것과 실제로 틀린 것을 구분한다. 상자에 도달하지 못했다면 상자 내용이 틀렸다는 근거가 되지 않는다.
- 비활성 상태는 재접속이나 원본에서 그래프를 재구성할 때도 유지되어야 한다.
- 새 관측으로 상태가 달라졌다면 기억을 갱신하거나 복구할 수 있어야 한다. 한 번 무효였던 위치를 영구 차단하지 않는다.
- 현재 상태의 무효화와 과거 사건의 진위를 구분한다. 지금 상자가 비었다는 사실은 예전에 재료가 있었다는 경험을 부정하지 않는다.

기본은 완전 삭제보다 비활성화다. 다만 이미 캐버린 광석 위치처럼 관측으로 역할이 끝난 현재 공간 상태 항목은 기존처럼 삭제할 수 있다. LLM의 의심에 따른 비활성화와 확정된 현재 상태 갱신을 구분한다.

## 완전 삭제보다 비활성화를 택한 근거

완전 삭제는 LLM의 오판을 되돌리기 어렵게 하고, 무효 판정 사실을 잃어 같은 잘못된 내용을 다시 사용할 수 있게 만든다. 현재 기억 그래프는 사건 원본에서 다시 만들므로 그래프 항목만 지우면 다시 나타날 수도 있다.

기존 자료의 실제 약 2시간 관측 밀도를 100시간으로 환산하면 캐릭터당 사건 약 2만 1천 개와 원본 약 11MB다. 같은 사건 수를 사용한 합성 시험 파일은 약 7.9MB다. 네 캐릭터가 각각 100시간 활동한다고 계산하면 사건 원본은 약 32~44MB로, 현 규모에서는 용량 절감만을 위해 복구 가능성을 포기할 필요가 크지 않다.

이 수치는 사건 로그 기준이며 공간 기억·목표 집계·백업·개발 로그를 포함한 전체 용량이 아니다. 공간 기억의 100시간 크기는 탐험 범위에 따라 달라 현재 자료로 확정하지 않는다. 실제 100시간 플레이를 관측한 수치도 아니다.

## 구현 전에 정할 사항

- 신뢰도 초기값, 감점 크기, 비활성화 기준과 새 관측에 따른 복구 규칙.
- 감점 대상 기억의 식별 방법과 같은 확인 결과의 중복 반영 방지.
- 조회·계획·작업 실행 인터페이스와 계획 재판단 조건.
- 개인 목표·성격·사용자 요청을 미루거나 거절할 수 있는 범위와 호출 비용 한도.

이번 합의는 방향과 요구사항 정리다. 제품 코드 변경이나 게임·모델 호출 재개를 승인한 것은 아니다.
