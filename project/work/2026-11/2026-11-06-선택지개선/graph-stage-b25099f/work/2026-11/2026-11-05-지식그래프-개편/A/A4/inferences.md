# A-4 실제 출력 기반 부분 추정

이 문서는 **실제 HTTP/시작 출력만 보고 쓴 부분 추정**이다. 입력은 A1-exploration.md, A2/screens.md, A3/A3-first-user-report.md와 관측 원문뿐이다. 제품 소스·B 결과·기존 기획은 읽지 않았다. 아래 네 문서 절의 ID는 추정 노드 ID다. 기존 A2 화면·화면요소는 참조만 한다.

A1의 별도 포트 18331·빈 데이터·members 빈 설정과 preflight 비활성 조건에서 나온 값이다. found/login/subscriptionOk:false를 실제 사용자 설치·계정·구독 장애로 단정하지 않는다. 실제 게임 화면은 사용자 지시로 후속 유예되었고 정상 AI 플레이·유료 호출·로그인/구독은 미관측이다. 제품 전체 정체성·전체 저니를 확정하는 자료가 아니다.

## ACT-A-01 연결 준비 여부 확인

문서 ID: `ACT-A-01` / 타입: 유저 활동 / 근거: A3의 실제 GET 두 번과 판단, 대응하는 A2 출력 요소.

- 무엇을 하는가: 처음 온 운영자가 현재 AI 동료 연결을 사용할 준비가 되었는지 확인한다.
- 문제: 서비스 주소는 받았지만 사용 가능한 상태인지 모른다. 목표: 응답을 읽고 준비 완료를 판단할 근거를 얻는다.
- 언제: 첫 사용을 앞두고 health 주소를 받은 때. 제품을 알게 된 외부 경로와 실제 계정·월드 상태는 모른다.

| 차례 | 실제 행동·판단과 분기 | A2 화면요소 ID |
|---|---|---|
| 시작 | 받은 /v1/health 주소에 GET을 보내 HTTP 200을 확인한다. 이는 응답 도달의 근거다. | `BRG-02#1` |
| 상태 읽기 | 최상위 ok:false, 네 members 항목, busy:[]를 읽는다. busy의 정확한 뜻과 검사의 범위는 응답만으로 확정하지 않는다. | `BRG-02#2`, `BRG-02#3`, `BRG-02#4` |
| 차이 해석 | claude와 나머지 세 항목의 skip 차이와 usage unknown ()를 보고 무엇을 준비할지 판단하려 하지만 실패한다. 항목에 포함된 found·login·subscriptionOk·ok 값도 실제 계정 사실로 확정하지 않는다. | `BRG-02#3-1`, `BRG-02#3-2`, `BRG-02#3-3`, `BRG-02#3-4` |
| 안내 탐색 분기 | health 응답에서 다음 행동·도움말 링크를 얻지 못해 같은 서버 /에 GET을 보낸다. 화면 링크를 따른 이동이 아니라 A3 운영자가 떠올린 탐색이다. HTTP 404와 ok:false, not found를 읽는다. | `BRG-02#3`, `BRG-03#1`, `BRG-03#2`, `BRG-03#3` |
| 끝 | 전체·구성원 ok:false와 루트의 not found 때문에 준비 완료의 근거와 복구 안내를 얻지 못한 상태로 멈춘다. 준비 완료 분기는 미관측이다. | `BRG-02#2`, `BRG-02#3`, `BRG-03#3` |

얻는 것: 로컬 HTTP 서비스가 응답하며 현재 응답은 준비 완료를 보고하지 않는다는 판단. 얻지 못한 것: 어떤 도구·계정·설정을 먼저 확인할지, 재검사 방법, 게임 내 사용 가능 여부. skip:false와 ok:false의 조합, 빈 괄호가 붙은 usage unknown ()가 설명 없이 노출되어 다음 조치를 정하기 어렵다.

다음 활동: 확인된 다음 활동 없음. 별도 도움을 구하거나 환경을 확인한 뒤 재조회할 가능성은 **미확인 예상**이며 활동 노드·연결로 만들지 않는다. 루트 안내 탐색은 같은 문제와 목표의 중간 단계이므로 별도 활동으로 나누지 않았다. A3의 첫 PowerShell 매개변수 오류는 HTTP 이전 도구 실패이며 제품 흐름으로 만들지 않는다.

## JOURNEY-A-01 첫 사용 준비의 부분 저니

문서 ID: `JOURNEY-A-01` / 타입: 유저저니 / 대상: AI 동료 연결 준비를 확인하려는 처음 온 운영자라는 A3 상황.

| 단계 | 원하는 것·관측 결과 | 대응 활동·출력 |
|---|---|---|
| 진입 | health 주소를 받은 뒤 응답 유무를 확인한다. 제품 인지·설치·주소를 얻은 과정은 미확인이다. | `ACT-A-01`, `BRG-02#1` |
| 사용 준비 판단 | 연결을 사용할 수 있는지 알고 싶지만 전체 및 구성원의 준비 완료 근거가 없다. | `ACT-A-01`, `BRG-02#2`, `BRG-02#3`, `BRG-02#4` |
| 안내 탐색 | 다음 조치를 원하지만 스스로 시도한 루트에서도 안내를 얻지 못한다. | `ACT-A-01`, `BRG-03#1`, `BRG-03#2`, `BRG-03#3` |
| 관측 종료 | 준비 완료를 판단하지 못해 실제 사용 검증에 이르지 못했다. 관측 중단 지점이며 실제 서비스 이탈·해지를 뜻하지 않는다. | `ACT-A-01`, `BRG-02#2`, `BRG-03#3` |

재방문 계기는 미확인이다. 도움이나 환경 변화 뒤 다시 상태를 확인할 수 있다는 예상만 있으며 관측 저니 단계로 추가하지 않는다. 정상 게임 이용·지속 사용·이탈·복귀의 전체 저니는 미확인이다.

## IA-A-01 관측 출력의 목록과 묶음

문서 ID: `IA-A-01` / 타입: IA. 아래는 HTTP·콘솔 출력을 찾기 위한 부분 IA이며 게임 메뉴 구조를 추정하지 않는다. 각 기존 화면에 IA 묶음을 하나씩 부여한 문서 속성이다. A2 노드의 재정의나 화면 간 이동 연결이 아니다.

| 기존 화면 ID | 출력 | IA 묶음 |
|---|---|---|
| `BRG-01` | 격리 브리지 시작: 그래프 경고와 listening | 시작·상태 확인 |
| `BRG-02` | health: 격리 환경의 준비되지 않은 값 | 시작·상태 확인 |
| `BRG-03` | 루트 요청의 not found | 요청 오류 확인 |
| `BRG-04` | plan 요청의 unknown member | 요청 오류 확인 |
| `BRG-05` | plan 요청의 JSON 구문 오류 | 요청 오류 확인 |

관측 진입은 A1의 시작 콘솔 BRG-01과 A3에게 주어진 health BRG-02로 서로 다르다. 전체 제품의 기본 진입 화면은 미확인이다. 전역 메뉴·공통 영역·클릭 가능한 이동은 관측되지 않았다. BRG-03은 홈 화면이 아니며, BRG-04·BRG-05는 A1 오류 입력 탐색에서만 확인되어 정상 이용 활동을 만들어 연결하지 않는다. ENV-01·ENV-02는 A2의 환경·설치 관측으로 제품 IA 화면 목록에서 제외한다.

## CORE-A-01 제품코어의 확인 가능한 단서

문서 ID: `CORE-A-01` / 타입: 제품코어. 제품당 하나의 부분 추정이며 운영 출력만으로 제품 전체를 정의하지 않는다.

- 정체성 단서: 시작 출력의 ai-bridge, game graph 안내(`BRG-01#1`)와 listening 주소(`BRG-01#2`), health의 네 구성원 상태(`BRG-02#3`)를 제공하는 로컬 브리지 측면이 보인다. 실제 AI 동료 게임 제품의 전체 정체성과 성공 경험은 미확인이다.
- 타겟 유저 단서: 이번에 확인한 사람은 연결 준비를 확인하는 운영자다. 전체 제품이 운영자만을 대상으로 한다는 뜻은 아니다.
- 제공 가치 단서: HTTP 도달 여부와 구성원 상태를 한 응답에서 볼 수 있다. A3에서는 준비 완료 판단이나 복구 행동 결정까지 이어지지 못했다.
- 브랜딩 단서: 시작 출력의 ai-bridge 명칭만 확인했다. 게임 내 표시·시각 정체성·공식 제품명은 미확인이다.

추정 그래프에는 위 네 문서만 생성한다. 제품코어·유저저니·IA의 직접 연결은 없으며, 활동 연결은 본문 단계에 인용한 기존 A2 화면요소로만 향한다. 기능·정책·코드 노드를 새로 만들지 않는다.
