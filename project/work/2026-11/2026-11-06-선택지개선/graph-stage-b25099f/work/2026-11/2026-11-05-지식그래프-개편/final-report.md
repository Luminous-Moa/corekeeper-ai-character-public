# 개발 지식그래프 개편 결과

사용자가 확정한 개발용 지식그래프를 제작 지침의 A(실사용)·B(코드)·C(기획)·D(통합) 방식으로 개편했다. 새 실게임 화면 확인은 사용자 지시에 따라 후속으로 남겼다. 나머지 합의 범위는 독립 검수에서 통과했고 중요한 미해결 지적은 없다.

## 사용자 진입점과 변경

- [기존 개발 지식그래프 README](../../지식그래프/README.md)에 새 시작 경로를 연결했다.
- [제품 그래프 사용법](../../지식그래프/제품그래프-사용법.md)에 조회, 재생성, 기준판과 한계를 정리했다.
- 새 조회: `node tools/product.mjs overview`, `user ACT-A-01`, `feature "ai-bridge:GET /v1/health"`, `source <ID>`, `policy <ID>`, `find <낱말>`, `check`.
- 통합 재생성: `node tools/product-build.mjs`. 이미 생성된 A/B/C 입력을 합치는 명령이며 제품 소스의 최신판을 재추출하지 않는다.
- 원본 도구 `tools/build.mjs`·`query.mjs`, 기존 기획 네 문서와 graph/graph.json은 그대로 유지했다. 기존 능력 36개, 정책 60개, 후보 19개, 문서 미결 60개 및 게임 참조를 보존하고 [C 대응표](C/legacy-capability-map.json)로 새 활동·입구·코드와 관계를 설명한다.
- 제품 코드, 게임 설치본·월드·저장, 운영 프로세스, 세션 context.md는 변경하지 않았다. 추가·수정은 세션 작업 파일 및 기존 개발 그래프의 README·새 사용법·새 wrapper 두 개에 한정된다.

## 구현과 검수 완료 범위

1. A는 소스 구현을 읽지 않고 격리된 실제 bridge를 실행했다. health 200, 없는 경로 404, 잘못된 멤버 400, 잘못된 JSON 500 응답 원문을 수집했다. 출력 기획자·처음 온 사용자·추정 작성자 컨텍스트를 분리했다. 외부 LLM이나 구독 CLI 호출은 하지 않았다.
2. B는 커밋 `e82eb87f25641cc7c31e6216f64e20a34e58d0c0`의 고정 스냅샷에서 Roslyn/Acorn으로 코드·입구·데이터·외부 연결을 추출했다. 코드 층 재추출 2회, 최종 병합 2회가 동일했다. 기능 뜻은 별도 파일에 두고 새 코드 컨텍스트의 추정을 분리했다.
3. C는 기존 의도를 기준으로 정책의 대체·예외·잠정 상태를 보존했다. 사용자 결정과 추정은 구별하고, B7 추정 91노드를 정본에 조용히 승격하지 않고 대응/별도 보존했다. 개발 작업용 모델·추론 지정 철회와 제품 자체 모델 정책을 구별했다.
4. D는 별도 컨텍스트에서 실제 요청의 메서드·경로를 기계 추출 입구에 맞추고 사용자 활동→출력→입구→코드→데이터/원문 조회를 구현했다. 읽기 출력은 `기능→화면요소` 관계의 역조회라고 표시한다. 404는 없는 기능을 만들어 채우지 않고 미매칭으로 남긴다.
5. 독립 검수자는 별도 seed의 비대표 원문 표본, 고정 커밋 blob, 보존 인용, 정책 원문, 실제 HTTP GET 및 신규 CLI를 대조했다. 상태 조회, 호스트 목표/자율 목표 차이, 기억 검색 결과 생성의 세 질문에 대해 실제 코드 경로와 원문을 확인했다.

최종 통합 결과는 3,516노드·13,198간선이며 원문 254파일을 가리킨다. 최종 그래프 SHA-256은 `3aa0e230f2752207b42f859cf4c83022bf9fa4b3c2819ce4b5771dcd4e693196`이다. 노드 수 자체를 완료 근거로 삼지 않았다.

독립 검수 최종 실행은 CLI 16개 모두 종료코드 0, 재생성 바이트 일치, 구조 오류 0, 고정 입력 낡음 0이었다. 정책 43개의 원문 절·규칙 전수 확인, 별도 코드 경로 7개 확인도 통과했다. 검수 중 발견한 정책 ID의 본문 조기 매칭은 정확한 Markdown 헤딩 매칭으로 고쳤고, 목표 질문의 활동 ID도 UA-02/UA-04로 바로잡았다.

## 추출·실행 한계

- **코드는 e82eb87 기준이다.** 이후 전투 단계2 등 다른 판의 동작을 이 그래프의 구현 사실로 보지 않는다.
- 새 `check`는 고정 스냅샷·통합 입력 문서 해시와 현재 Git HEAD를 검사한다. 미커밋 작업트리 편집이나 이후 세션 원문 기록 전체를 실시간 감지하지 않는다. 이 범위는 기존 README와 새 사용법에 명시했다. 기존 등록 원본의 변화는 기존 `tools/query.mjs check`로 별도 확인한다.
- Unity/게임 메타데이터가 없는 의미 분석 진단, 미해결·가능 호출, 동적 외부 연결은 경계로 남는다. 미도달 코드는 곧 죽은 코드라는 뜻이 아니다. 정적 도달은 실제 실행 trace가 아니다.
- 새 HTTP 실행은 사전 점검을 비운 격리 환경이다. `ok:false`는 운영 계정의 로그인 실패를 뜻하지 않는다. 정상 외부 모델 계획 성공이나 게임 내 AI 성공 동작을 이번 실행으로 주장하지 않는다.
- A 실행 파일은 초기 archive의 Windows EOL 형식이었다. 53개 파일의 LF 정규화 내용과 줄 수는 기준 커밋과 같음을 확인했다. 해시 채집은 실행 후이므로 동시점 로드 증명은 아니다. 외부 ai-chatroom 모듈은 SDK 커밋 밖의 별도 의존성 기준으로 남겼다.

## 사용자 지시로 유예한 범위

실제 게임 화면 탐색, 화면 원본·위치 매칭, 실제 게임에서 처음 온 사용자가 동료 상태·명령·목표·기억 흐름을 끝까지 쓰는 확인을 유예했다. 게임 사용자 활동의 출력 연결은 미관측 gap으로 표시한다. 기존 실게임 기록은 날짜·버전이 있는 과거 근거로 보존하며 새 화면 검증과 구별한다. 이 유예는 이번 허용 범위의 합격을 막지 않는다.

## 실행 프로세스 정리

A가 만든 격리 bridge는 종료 전 PID 60784의 실행 명령과 `127.0.0.1:18331` 단독 소유를 확인한 뒤 해당 프로세스만 종료했다. 종료 후 프로세스·리스너 없음이 확인됐다. 운영 게임·8331·다른 Node 프로세스는 건드리지 않았다. [정리 증거](A/runtime-cleanup.json).
