- 시험용 `/ai bridge`(게임 안에서 health GET).

## 5. 시험 중 고친 것

1. 보고 JSON이 깨짐: C# 보간 `{값:F0}}}`가 형식 문자열로 읽혀 `"distance":F3`이 됨 → 숫자를 먼저 계산(브리지가 500으로 거절했고 모드는 다시 시도함).
2. LLM 답을 버림: `JsonUtility`가 모드 컴파일 코드에서 중첩 클래스(`for`, `goal`)를 채우지 않음(기존 U.json-fallback과 같은 꼴) → 직접 읽음.
3. **정보 누출 + 판단 되풀이:** 기억한 주석 (-111,62)는 예전에 캤는데, 화면 밖이라 기억에는 남아 있었다. 판단 응답의 유효성 검사가 그 칸의 실제 상태를 서버에서 읽어 "대상 벽이 이미 없음"으로 답을 버리고, 같은 후보를 다시 내 115번 되풀이했다. → 화면 안의 대상만 실제 상태로 검사하고, 굴 기술은 도착해서 보이면 판정(보니 없으면 "기억이 옛것"으로 실패, 기억도 지워짐). 같은 대상의 답이 거듭 버려지면 실패처럼 30초 뺀다.
4. LLM 목표로 쓰러지고도 같은 목표를 계속함 → LLM이 정한 목표 중 쓰러지면 다시 일어날 때 보고(목표는 그동안 계속). 이것으로 LLM이 "따라가기"로 바꿨다.
5. "따라가기"는 끝이 없어 다음 보고가 안 옴 → LLM이 정한 따라가기는 3분이면 완료로 보고(호스트가 정한 것은 그대로). 초안의 `recheck`(2차 조각) 전까지의 임시.
6. 보고에 최근 쓰러진 곳(월드별 `deaths.log` 끝 3줄의 위치·원인)을 넣고 안내문에 설명.

## 7. 사용자가 정할 것

1. 단톡방과 같은 인물로 할지(초안 3.7 A/B/C). 지금은 A.
2. 사용량 나누기: 지금 문턱은 주간 85%(지시대로). 단톡방과 게임 중 무엇이 먼저인지.
3. 구독 CLI를 자동 반복 호출에 쓰는 약관 위험을 알고 계속할지(초안 5장). 이번 시험은 약 20분에 11번.
4. 브리지가 단톡방 코드를 import하는 것(읽기 전용, 시작 때 health 확인)으로 계속할지, 복사로 바꿀지.
5. LLM이 기억한 주석(사막 신전 쪽)을 거듭 고른다. "위험한 곳에서 두 번 쓰러지면 그곳 기억 광석은 보고에서 빼기" 같은 규칙을 둘지, LLM 판단에 맡길지(지금은 보고에 최근 쓰러진 곳만 넣음).

## 8. 남은 것

- 브리지는 지금 수동으로 켠다(시작 스크립트 없음). 게임 중에 꺼지면 모드는 자동을 끄고 알림.
- 정보 누출 수정(5장 3)은 위쪽 LLM과 별개로 아래쪽 판단에도 적용됨.

## 9. 시험 뒤 상태

자동 모드 끔(`/ai stop`, 브리지 끔 시험에서 다시 꺼짐), 목표 없음. 게임은 월드 ai2 안에 켜 둔 채, 호스트는 코어 (0,-1), Claude는 코어 근처. 브리지 프로세스는 꺼 둠. 커밋 없음.
