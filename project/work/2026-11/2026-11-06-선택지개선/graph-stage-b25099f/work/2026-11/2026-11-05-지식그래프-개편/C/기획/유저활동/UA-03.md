# 필요한 물건 제작을 맡기기

> 통합 기획: 기존 의도와 기준 코드 e82eb87, 격리 HTTP 관측을 구별한다. 게임 화면 확인은 사용자 지시로 후속 유예했다. 새 사용자 결정은 없다.

ID: UA-03
class: 기존 기획 전환 해석
legacyIds: F.craft, F.goal-cmd

## 무엇을 하는가

호스트 — 품목과 수량의 제작 목표를 주고 결과를 확인한다.

## 언제 하게 되나

문제: 원하는 물건이 없어 재료·제작대 준비부터 맡기고 싶다.

상황: AI에게 제작할 물건을 지정할 때.

## 차례

1. 시작: 제작할 ObjectID와 수량을 정한다. 화면요소 ID: **미확정**(게임 화면/정상 AI 출력은 이번에 관측하지 않음).
2. 기존 기록의 `/ai goal 만들기 <ObjectID> [N]`으로 목표를 준다. 화면요소 ID: **미확정**(게임 화면/정상 AI 출력은 이번에 관측하지 않음).
3. 분기: 재료 모으기→만들기→놓기→계속의 준비 경로가 필요할 수 있다. 이는 기존 구현 설명이며 실제 순서는 A/B 확인 전이다. 화면요소 ID: **미확정**(게임 화면/정상 AI 출력은 이번에 관측하지 않음).
4. 끝: 가방 변화 또는 막힘 이유로 결과를 확인한다. 화면요소 ID: **미확정**(게임 화면/정상 AI 출력은 이번에 관측하지 않음).

출력 문서 예약: OUT-02, GAME-01. 이 참조는 화면요소 연결이 아니다.

## 얻는 것

제작한 물건 또는 준비가 막힌 이유.
