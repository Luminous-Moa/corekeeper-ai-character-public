# 빠짐·차이·후속 판정 목록

이 목록은 C-1 전환의 빠짐과 기존 자료 내부의 차이를 드러낸다. 새 결정을 내리거나 기존 미결을 닫지 않는다.

## 문서 형식으로 옮기며 아직 없는 내용

1. 실제 화면×상태, 그림 또는 출력 원문, 보이는 문구와 화면요소 ID. 화면출력 7개는 **예약 수집 문서**여서 표준 화면 노드가 아니다. 한 문서에 여러 수집 대상 상태를 적었으므로 A 후 분리한다.
2. 활동 단계→화면요소, 화면요소↔기능, 화면→코드, 정책→기능. C-1에는 이 연결을 만들 근거가 없다.
3. 발견 경로·처음 진입 화면의 실제 사용 경험·전역 메뉴·이탈 지점·재방문 동기. 문서가 없다는 것이 제품에 없다는 뜻은 아니다.
4. 브랜딩과 말풍선 실현 방식. U.speech-bubble가 남아 있다.
5. 내부 능력의 세부 알고리즘·숫자·함수선·확인한 선 서명은 사용자 활동 본문에 복사하지 않았다. `legacy-capability-map.json` 및 preserved/legacy/기획/기능.md의 절로 돌아갈 수 있다.
6. 게임 특수 참조와 기존 자동 미결은 새 표준 문서 타입에 맞추려 삭제하지 않고 별도 보존했다. 게임 참조의 실제 최신성은 이 작업에서 재확인하지 않았다.
7. C-3 실제 게임 화면 검증은 사용자 지시로 후속 유예. HTTP 흐름 검증은 가능하나 이 결과로 게임 화면을 확인했다고 하지 않는다.

## 사용자 판단과 사실 확인의 구분

기존 미결의 `종류`와 `닫는 법`을 그대로 사용한다. 예: 관리자 참여 권한·말풍선 형태·월드 이동 저장 정책은 제품 판단이 필요하고, 미관측 갈래·코드 경로·CLI 응답 형식은 해당 출처의 관측으로 확인한다. 이미 사용자 결정이 있는 일을 새 승인 질문으로 되돌리지 않는다. 현재 C-1 단계는 이 목록을 보고만 하며 사용자에게 새 질문을 보내지 않는다.
