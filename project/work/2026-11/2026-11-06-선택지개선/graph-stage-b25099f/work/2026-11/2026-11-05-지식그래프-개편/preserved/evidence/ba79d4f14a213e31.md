작성일: 2026-11-04. 시험 월드: 버림용 `ai2`. 설계: [jev-행동설계-v2](2026-11-03-jev-행동설계-v2.md) §3("준비하면 실행 가능")–5. 앞 작업자(같은 작업)가 맥락이 다해 멈춘 뒤 이어 씀. 아래쪽 행동은 OpenAI Decisions가 고르고, 위쪽 LLM은 목표만 정한다. Claude는 사람 화면만큼만 본다.

## 2. 게임이 제작을 처리하는 방식 (디컴파일 `C:\Dev\_ref\corekeeper-decomp`)

1. 클라이언트 제작 UI: `Pug.Other\InventoryHandler.cs:211-223` `CraftItem` → `QueueInputAction(new UIInputActionData { action = UIInputAction.Craft, craftActionData = Create.Craft(objectID, amount, additionalFreeAmount, playerController.entity, craftingEntity) })`. 손 제작이면 `craftingEntity`가 플레이어 자신(`activeCraftingHandler?.craftingEntity ?? playerController.entity`). `Create.Craft`는 `Pug.Other\Inventory\Create.cs:350-362`(mainInventoryEntity = 플레이어).
2. 보내기: `Pug.Other\SendClientInputSystem.cs:219-235` — 서버 틱 + 1로 `UIInputActionDataRPC { tick, actionData }` RPC를 보내고 자기 쪽 `UIActionBuffer`에도 넣음.
3. 서버 받기: `Pug.Other\ReceiveUIInputActionsRPCSystem.cs:136-147` — 보낸 연결의 CommandTarget(그 플레이어)의 `UIActionBuffer`에 추가.
4. `Pug.Other\TriggerUIActionsSystem.cs:199-222` — 틱이 된 가장 오래된 행동을 꺼내 `UIInputAction.Craft`면 `CraftBuffer`에 `{ playerEntity, craftActionData }` 추가(`InventoryChange`면 `InventoryChangeBuffer`).
5. `Pug.Other\Inventory\InventoryUpdateSystem.cs:409-444` — 주 인벤토리 + 제작대 근처 상자(`GetNearbyChestsForCraftingByDistance`)를 모아 `InventoryUtility.Craft`(`Pug.Other\Inventory\InventoryUtility.cs:1709`) 호출. 검사는 `CanCraft`(:1605-1660): 재료 수, 그리고 **출력 칸이 비었거나 같은 쌓이는 물건일 것**. 거리·제작대 목록 검사는 서버에 없다(클라이언트 UI 몫).
6. 결과: 만든 물건은 주 인벤토리의 `CraftingCD.outputSlotIndex` 칸(플레이어는 50번, 화면에서 "커서에 든 물건")에 들어간다(:1715-1760).

모드가 하는 것(`AICraft.QueueCraft`): 3번이 서버에서 하는 것과 같은 `UIActionBuffer` 항목(틱 = 서버 틱 + 1, `Create.Craft(item, n, 0, AI, 제작대 또는 AI)`)을 AI 플레이어에 넣는다. 얇은 클라이언트는 고스트가 없어 RPC 안에 엔티티(플레이어·제작대)를 담을 수 없어서다. 그 전에 클라이언트 UI가 하는 검사를 한다: 제작대 목록(`CanCraftObjectsBuffer`)에 있음, 가방 재료 충분, 제작대 2칸 안(먼저 걸어감). 결과는 가방 수 변화로 판정하고, 커서 칸의 물건은 클라이언트의 `Create.MoveOrDropItem`(같은 UI 행동 경로)으로 가방에 넣는다. 로그: `SKILL 만들기: craft request Torch x1 at 손 (via UIActionBuffer, like a client's UIInputAction.Craft)`.

놓기(`PlaceSkill`): `Pug.Other\PlaceObjectSlot.cs:22-46` — 놓을 수 있는 물건을 손에 들고 보조 사용(`secondInteractHeld`)이면 `PlaceItem`(:48-100)이 `PlacementCD.bestPositionToPlaceAt`에 놓는다. 위치는 `PlacementHandler.cs:198-225`가 정함(조준이 없으면 바라보는 방향, `FindPlaceablePositionFromOwnerDirection`). 모드는 물건을 손 칸으로 옮기고(무기 바꾸기와 같은 방식) 네 방향을 차례로 바라보며 보조 버튼을 누른다. 놓였는지는 가방 수 감소 + 3칸 안에 그 제작대가 보이는지로 판정.

## 3. 부수기가 물체에 안 맞던 까닭 — 커서 칸의 횃불

- 앞 작업자는 곡괭이로, 다음엔 칼로 나무 상자를 쳤지만 `30초 안에 못 부숨(체력 2→2)`. 서버 진단 로그: 대상 `mineable=True destructible=True indestructible=False immuneTile=False`, 서버 물리 세계에 대상 몸체 있음, 바라보는 방향 맞음, 그러나 `routine=Inactive attackEq=None` — **휘두르기가 한 번도 일어나지 않았다.** 버섯도, 곡괭이로 흙벽도 같았다(`6초 동안 변화 없음(타일 체력 -1→-1)`).
- 까닭: Claude 인벤토리 50번(커서 칸)에 Torch 1개가 남아 있었다(`AIPlayers\…\Claude.json` inventory[50] objectID 110). 게임은 커서에 물건이 있으면 장비를 쓰지 않는다(`Pug.Other\PlayerEquipment\EquipmentUpdateSystem.cs:143-147` hasItemInMouse → 각 Slot.UpdateEquipment, 예 `PlaceObjectSlot.cs:39-42`). 이전 작업에서 횃불을 만든 흔적으로 보인다(제작 결과가 커서 칸에 들어가는데 그때는 꺼내지 않았음).
- 고침: 사람처럼 커서 물건을 가방에 넣는다(2초마다 점검, 제작 기술은 끝낼 때 직접). 로그: `BODY: item on the cursor (crafting output slot): Torch x1; moving it into the bag (client MoveOrDropItem)` → 다음 부수기 `SKILL 부수기 DONE after 1.4s: reason='WoodenDestructible 부숨 · 가방 ScrapPart +4, Wood +1'`.
- 덧붙여: 나무 곡괭이 `amount 0`은 부서진 것이 아니었다(이 곡괭이로 바로 흙벽을 캠). 부서짐 판정은 게임의 `PlayerController.ItemIsBroken`(내구도가 있는 물건이 0일 때, `PlayerController.cs:7211-7235`)을 쓰도록 했다.

## 4. 만든 것 (모드)

- `AICraft.cs`
  - `AICraft`: 보이는 제작대(`StationsInView`), 손 제작 목록, 재료 대비(가진 것/필요한 것), `QueueCraft`(UIActionBuffer), `QueueInventoryChange`, `CursorItem`·`StowCursorItem`, `StationFor`(손 제작·나무 작업대 목록 안에서 그 물건을 만드는 제작대), `HotbarSlotFor`, `KnownRecipe`(LLM 목표 검사), 시험용 `Diagnose`(`/ai craftinfo`).
  - `CraftSkill`(만들기): 제작대 2칸 안으로 걸어감 → 요청 → 가방 증가로 판정 → 커서 물건 가방에 넣고 끝. 커서에 다른 물건이 있으면 먼저 치움.
  - `PlaceSkill`(놓기), `RootSkill`(뿌리 캐기: 큰 뿌리 타일 `bigRoot`을 곡괭이로, 나무가 나옴), `BreakSkill`(부수기: 칼로 누르고 떼기 반복, 5초 동안 체력이 그대로면 이번 접속 동안 그 물체를 후보에서 뺌, 나온 것은 종류별로 모두 기억 `Wood +1 / ScrapPart +4` 식).
- `AIDecisions.cs`(준비 경로 `WantedItems`): 목표 품목 → (손 제작 | 보이는 제작대 | 만들 수 있는 제작대) → 모자란 재료. 모을 수 있는 재료(흙·구리·주석·나무)는 모을 품목으로, 만드는 재료(구리 주괴)는 따로 한 단계로, 제작대가 가방에 있으면 "놓기" 후보, 없으면 제작대 자체를 한 단계로. 결과 메모 예: `BRAIN: preparation: Furnace(목표 품목): WoodenWorkBench에서 만듦 — 보이는 WoodenWorkBench 없음, 먼저 WoodenWorkBench를 만들어 놓아야 함(재료 WallDirtBlock 227/20) / WoodenWorkBench(Furnace을(를) 만들 제작대): 손에서(제작대 없이)에서 만들 수 있으나 Wood 7개 더 필요`. 곡괭이 없음/부서짐이면 WoodMiningPick, "도구 부족" 벽이 막으면 CopperMiningPick을 준비 대상으로. 후보: 만들기·놓기·부수기·뿌리 캐기, 벽에 갇힌 부술 물체는 옆 칸까지 "파 들어가기". 놓인 제작대는 나무 물체로 치지 않음. 목표 완료는 기술이 끝나면 바로 확인(같은 물건을 한 번 더 만들던 것 고침).
- `AIBodySkills.cs`: `BodyInput.aim`(게임패드 조준처럼 `wasAiming`), 커서 칸 정리, 곡괭이 고를 때 부서진 것은 뒤로, 시험용 `/ai breaktest <ObjectID>`·`/ai craft <ObjectID> [N]`·`/ai place <ObjectID>`.
- `AIPlanner.cs`: 보고에 `can_do.craft`(손 제작·보이는 제작대 목록, 재료 가진 것/필요한 것), `stations_in_view`, **`craft_needed`**(지금 목표의 준비 메모), `cannot_yet`에서 "제작" 뺌. craft 목표 검사: 아는 품목, `KnownRecipe`(손·보이는 제작대·만들 수 있는 제작대), 개수 1~10.
- 브리지 `Tools\ai-bridge\brief.md`: craft_needed 설명, 목록 밖이라도 작업대 사슬로 만들 수 있으면 craft 가능하다는 안내. `bridge.mjs`는 앞 작업자가 이미 craft를 받게 해 둠(바꾸지 않음).

### 5.3 도구 준비 사슬 (`/ai goal 만들기 CopperMiningPick 1`)
첫 시도(빌드 craft17): `SKILL 놓기 DONE after 0.3s: reason='Furnace 놓음 (-19,38) 1.0칸'`, `CopperBar 2개 만듦`, `CopperBar 4개 만듦` 뒤 `SKILL 만들기 FAILED after 1.0s: reason='제작대로 가지 못함: 길 없음(게임 길찾기: 타일·물체 고려)'`(제작대 옆 칸 하나를 골라 가던 방식) → 적을 피해 멀어진 뒤 제작대가 안 보여 목표가 멈춤. 제작대 자체를 대상으로 다가가도록 고친 뒤(craft18):
```
GOAL set rev=1 source=host: CopperMiningPick(CopperMiningPick) 1개 만들기 (start count 0)
SKILL 만들기 DONE after 0.2s: reason='CopperWorkbench 1개 만듦 · 가방 CopperWorkbench +1, Wood -8, CopperBar -6'
SKILL 놓기 DONE after 0.3s: reason='CopperWorkbench 놓음 (-18,37) 1.1칸'
SKILL 놓기 DONE after 1.3s: reason='Furnace 놓음 (-18,38) 0.9칸'

(뿌리 캐기 3번)
SKILL 만들기 DONE after 0.3s: reason='CopperMiningPick 1개 만듦 · 가방 CopperMiningPick +1, CopperBar -2, Wood -4'
GOAL done rev=1: CopperMiningPick(CopperMiningPick) 1개 만들기 (1/1) after 27.3s, calls this session 15
```
중간에 버섯 적과 싸우고(`MushroomEnemy 처치`) 먹기도 함. 이 시험 중 두 가지 결함이 보여 고쳤다: 놓아 둔 나무 작업대를 "나무 물체"로 보고 부수기 후보로 냄(`부수기 — WoodenWorkBench (-20,39)`, 5초 뒤 실패) → 제작대(`CanCraftObjectsBuffer`)는 빼고 게임이 부서지는 물체로 표시한 것(`DestructibleObjectCD`)만. 그리고 앞 접속에서 놓은 용광로가 게임 강제 종료(저장 전)로 가방에 돌아와 `제작대가 없음` 1번.

### 5.4 LLM이 정한 제작 (브리지 켬, `/ai goal 알아서`, 호출 4번)
```
PLANNER: report #2 APPLY decision=set goal=craft CopperBar 4 why='구리 광석 8개와 용광로가 보임. 적이 근처라 멀리 가지 말고 제작으로 장비 기반 마련' after 4.1s
[Claude] 구리 광석 녹여서 주괴 좀 만들어 둘게요!
SKILL 만들기 DONE after 2.1s: reason='CopperBar 4개 만듦 · 가방 CopperOre -4, CopperBar +4'
PLANNER: report #3 APPLY decision=set goal=craft JuteBag 1 why='CopperBar 8개와 Wood 10개로 JuteBag 재료가 충분하고 제작대도 가까움. 쓰러졌던 서쪽 위험 지역에 다시 가지 않고 할 수 있는 일.' after 6.1s
GOAL done rev=5: JuteBag(JuteBag) 1개 만들기 (1/1) after 0.5s, calls this session 14
PLANNER: report #4 APPLY decision=set goal=follow  -1 why='적 2마리가 보이고 최근 이 근처에서 세 번 쓰러짐. 무리하지 않고 호스트 곁으로 합류해 안전 확보' after 4.4s
```
보고의 can_do.craft 예: `"CopperMiningPick: Wood 10/4, CopperBar 8/2"`, `"JuteBag: Wood 10/5, CopperBar 8/2"`, `stations_in_view:["CopperWorkbench","Furnace","WoodenWorkBench"]`, `craft_needed:"CopperBar(목표 품목): 제작대 Furnace (-18,38) 1.9칸에서 만들 수 있으나 CopperOre 1개 더 필요"`. ## 7. 남은 것

1. **"도구 부족" 모으기 목표의 준비 경로는 실게임 미확인.** 코드상 `_blockNote`에 "도구 부족"이 있으면 CopperMiningPick을 준비 대상으로 넣고 이제 사슬(작업대·용광로·주괴)까지 메모가 나오지만, 도구 부족 벽이 막는 목표를 ai2에서 다시 만들지 못했다(Claude가 이제 구리 곡괭이를 가짐). 대신 도구 자체를 목표로 한 5.3을 확인.
2. **놓은 제작대 기억 없음.** 제작대가 화면 밖이면 없는 것으로 보고 다시 만들려 한다(5.3 첫 시도에서 목표가 멈춤). 탐색 기억(AIMemory)에 "놓은 제작대 위치"를 넣을지 정해야 함.
3. 가방 → 손 칸 옮기기(놓기·무기)는 서버 버퍼 직접 변경. 클라이언트 `Create.Swap` UI 행동으로 바꿀 수 있음.
4. 부수기 "나오는 것" 기억은 메모리에만 있고 게임을 다시 켜면 사라짐(뿌리도 같음).
5. 게임 강제 종료(빌드 때 `Stop-Process`)로 마지막 자동 저장 뒤 변화가 사라짐: 놓은 용광로가 가방으로 돌아온 일 있음. 시험 방법 문제.
6. 큰 뿌리 후보는 "닿을 수 있는" 것만(벽에 갇힌 뿌리로 파 들어가기는 없음).
7. 제작 결과가 커서 칸에 남는 동안(0.1초 안팎) 다른 판단이 오면 커서 정리가 늦을 수 있음(2초 점검으로 회복).
