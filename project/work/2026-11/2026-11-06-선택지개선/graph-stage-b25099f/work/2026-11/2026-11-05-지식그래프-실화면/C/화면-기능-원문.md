# 화면·기능·코드 원문 대응

화면·요소 정본은 A2/manifest.json과 화면별 Markdown, 구현 정본은 기존 e82eb87 소스이며 설치판 대응은 B/existing-node-mapping.json이다. HTTP/IPC/상태 코드/stream 요청 캡처는 없다. 기능 매칭은 제출한 문자열·응답 문구·소스 분기의 일치에 근거하며 실제 함수 실행 trace가 아니다.

## 직접 연결하는 한 요청

`CKAI-ACT-01 → CKAI-02#3 → slash:ai → code:Assets/AIPlayerSpike/Scripts/AIPlayerSpikeMod.cs#AIPlayerSpikeMod.TryHandleChatCommand(string)`

기존 기능→코드 간선은 그대로 재사용한다. 입력칸 연결은 `/ai`를 Return으로 제출한 경우로 한정하며 빈 입력이나 `/ai Claude` 초안 입력을 실행으로 세지 않는다. `/ai` 자체가 조회를 하는 입구이고 하위 status/help/inv/mem별 가짜 기능을 추가하지 않는다.

결과 간선은 `slash:ai → CKAI-02#2-7`이다. 결과에서 기능을 찾을 때는 역방향 조회한다. 결과 문구를 클릭해서 요청한 것처럼 반대 간선을 만들지 않는다. 게임 에코 CKAI-02#2-6은 게임 본체가 출력하는 별도 경계이며 모드의 Reply 결과로 연결하지 않는다.

## 실제 화면과 소스 차이

- A2 CKAI-02#2-7의 `Claude 켜짐/들어와 있음/없음`에서 마지막 필드는 StatusAll의 Walking 때 Goal.Text 출력 자리로 대응한다. 화면에는 필드명이 없어 처음 온 사용자가 의미를 알았다고 주장하지 않는다. 지속 목표 없음과 현재 기술·자기 방어 수행 없음은 다르다.
- A1의 짧은 안내 전사 `<개별>`은 A2 최종 확대 검수에서 철회되어 인자명 판독 불확실로 남았다. StatusAll 원문은 `<멤버>`다. 화면이 실제로 코드와 다르다고 확정하지 않고 픽셀 읽기 불확실성으로 구별한다. 코드 문구로 화면 전사를 대체하지 않는다.
- A1 ‘70→70’은 A2가 중간 기호를 확정하지 못했다. C는 확정 수치 원문으로 재인용하지 않는다.
- A1 ‘제자리에 쉽니다.’와 A3 ‘제자리에 섭니다.’는 서로 다른 시점의 관측이다. 하나의 고정 메시지로 합치거나 한쪽을 오기라고 정하지 않는다.
