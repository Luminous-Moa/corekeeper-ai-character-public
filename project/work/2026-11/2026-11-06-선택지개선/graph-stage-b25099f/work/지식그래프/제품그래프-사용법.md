# 제품 그래프 사용법

개발 작업에서 언제 그래프를 조회하고 기획·설계·검수에 반영하는지는 [공통 제작·활용 지침](C:/Dev/_ref/head-agent-core/graph/build/README.md), 특히 [기획](C:/Dev/_ref/head-agent-core/graph/build/03-planning.md)과 [개발기획](C:/Dev/_ref/head-agent-core/graph/build/05-dev-planning.md)을 읽는다. 아래는 코어키퍼 그래프의 구체적인 조회·갱신 방법이다.

개발할 때 사용자 활동과 출력에서 관련 입구·코드·데이터·정책을 찾는 색인이다. 그래프의 답으로 위치를 좁힌 뒤 `source`로 원문을 읽는다. 결정의 권위는 기존 세션 기록이며, 추출 JSON은 원본에서 다시 만드는 결과다.

## 시작과 조회

이 폴더에서 실행한다.

```powershell
node tools/product.mjs overview
node tools/product.mjs user CKAI-ACT-01
node tools/product.mjs show "CKAI-02#3"
node tools/product.mjs source "CKAI-02#2-7"
node tools/product.mjs feature "slash:ai"
node tools/product.mjs user ACT-A-01
node tools/product.mjs feature "ai-bridge:GET /v1/health"
node tools/product.mjs source "ai-bridge:GET /v1/health"
node tools/product.mjs find 목표
node tools/product.mjs find 기억
node tools/product.mjs policy pol.multi-ai
node tools/product.mjs check
```

정확한 정책 ID는 `find`·`overview`의 결과에서 고른다. `show <ID>`는 한 노드와 연결, `impact <ID>`는 영향 후보, `source <ID>`는 문서·코드 원문을 읽는다. 코드 트리는 가능한 호출 관계이며 특정 실행에서 모두 실행됐다는 뜻이 아니다. 경계·미해결·깊이/개수 제한 표시를 함께 읽는다.

기존 근거 그래프의 모든 ID와 조회는 유지한다.

```powershell
node tools/query.mjs why F.action-select
node tools/query.mjs code F.ai-char-load
node tools/query.mjs unresolved
node tools/product.mjs legacy show F.action-select
```

기존 F.* 36개는 관측 가능한 능력 단위다. API·hook·slash 명령 등 요청 입구 단위인 새 `기능`과 크기가 다르다. [대응표](../2026-11/2026-11-05-지식그래프-개편/C/legacy-capability-map.json)와 [전환 차이](../2026-11/2026-11-05-지식그래프-개편/C/빠짐-전환차이.md)를 확인한다.

1. 코드가 바뀌면 [B 작업 안내](../2026-11/2026-11-05-지식그래프-개편/B/README.md)의 고정 커밋 스냅샷·추출 절차로 코드 층을 다시 만든다. 기준 커밋과 경계·표본 검증을 갱신한다. 2026-11-05 fc8161b 재추출에서 쓴 순서: B `extractor/pin-snapshot.mjs`·`verify.mjs`·`build.mjs`의 커밋 상수를 바꾸고 `snapshot`·`runtime-package`를 지운 뒤 B 실행법 그대로(pin → Extract → build → verify → determinism), `validation-review.json` 표본 줄 번호 재확인 → 개편 `C/integrate-c.mjs` → `C/build-graph-C.mjs`(C가 B 해시를 입력으로 기록) → 실화면 `B/remap-base.mjs`(대응표 기준 커밋) → `C/overlay-source.json`의 `baseCommit` → `C/validate-C.mjs` → 아래 5.
2. 실제 출력이 바뀌면 [A 안내](../2026-11/2026-11-05-지식그래프-개편/A/README.md)의 새 요청 원문·출력 문서를 갱신하고 재생성한다. 과거 실행 원문을 덮어쓰지 않는다.
3. 사용자 결정은 먼저 세션 원문에 기록하고, [C 안내](../2026-11/2026-11-05-지식그래프-개편/C/README.md)에 따라 기획·대응을 갱신한다. 추정을 결정으로 바꾸지 않는다.
4. 이번 실화면 문서/좌표는 [A2 정본](../2026-11/2026-11-05-지식그래프-실화면/A2/index.md), 활동·대응은 [C 선언 원본](../2026-11/2026-11-05-지식그래프-실화면/C/overlay-source.json)에서 고친다. C 문서와 선언을 함께 맞추고 `C/validate-C.py`(Python이 없으면 같은 검사의 `C/validate-C.mjs`)로 참조를 검사한다.
