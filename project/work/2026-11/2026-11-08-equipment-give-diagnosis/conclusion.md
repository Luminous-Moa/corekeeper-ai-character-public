# 현재 장비 전달 실패 분석

2026-11-08 최신 aiui1106 사용자 플레이를 분석했다. 사용자는 나무 장비 풀세트를 요청했고 상위 Gemini는 투구·갑옷·바지 전달 단계를 만들었다. 시작 관측에는 각 장비가2개씩 있었다. 현재 설치 소스116개는43c3817과 일치하며 게임 시작은 최종 설치 뒤다.

## 확인된 두 흐름

투구 단계에서는 실제 건네기 실행 없이 하위 판단모델이 finish_goal을 선택했다. 코드가 현재 계획 단계를 종료하고 다음 갑옷 단계로 진행했다. 이후 관측의 투구2개는 유지됐다. got=-1은Give의실측수량을계산하지않는기본값이며수량실패값으로해석하지않는다.

갑옷 단계에서는t144.1에give행동을시작했다. t150.2에출발가방감소1/1과바닥Entity.Null이기록됐고,t153.5사용자는방어구가들어왔다고말했다. 그러나동작종료기록이없고139초이후에도같은give를계속했다. 최신보존로그t469.8에도같은수령미확인상태가보고됐고투구2개·바지2개는남았다. 새상자보관목표에서도이전give동작이유지된흐름이확인됐다.

## 코드 원인과 설계 구분

AIInventory의DropTick은바닥아이템엔터티를포착한경우에만수령자가방증가를확인하는분기로진입한다. _floor가Entity.Null인경우가방증가값은초기값0으로남으므로, 이0은실제수령자가받지않았다는측정증거가아니다. 빠른자동줍기등으로바닥엔터티추적을놓치면실제전달뒤에도수령확인이계속대기할수있다. 엔터티를놓친정확한순간과원인은현재로그만으로확정하지못했다.

[공통 실행 합의](../2026-11-07-공통실행-합의.md)와 [계약](../2026-11-07-공통실행자료/contract.md)은스크립트가실제행동과수량·도착등의사실을관측하고,AI가현재계획단계를finish_goal로끝내도록명시한다. 사용자원래부탁전체의완료는상위모델의order=done으로결정한다. 따라서모델이단계완료를선택할수있는것은기록된설계다. 투구의문제는실제전달근거없이완료를선택한판단이며, 이를허용하는설계자체를이번분석에서임의로변경하지않는다. 모델이왜그선택을했는지의내부이유는관측된선택만으로확정할수없다.

## 수정 방향

우선전달결과관측을바닥엔터티포착에만의존하지않도록개선해야한다. 시작시점의정확한품목·출발수량·받는사람과가방기준을보존하고,바닥추적과수령변화를함께검증해완료사실을모델에제공하는방향이다. 출발가방감소만으로성공을단정하지않으며, 미확인상태와확인된전달을구별한다.

판단모델에는현재단계의실제수량·실행이력·완료관측여부가분명히전달되는지확인해야한다. 완료선택을강제로막는정책변경은사용자판단영역이다. 이번요청은원인분석이며코드·게임·설정변경을수행하지않았다.
