# Jev 대체 판단 모델 조사

조사일: 2026-11-03. 요청: Jev 이후 나온 유사 모델 중 더 나은 대안 조사.

## 범위와 현재 맥락

Core Keeper 설계의 ‘LLM 큰 목표 → 판단 모델의 실행 후보 선택 → 프로그램의 몸 조작’에서 판단 모델을 비교한다. 공식 모델 문서·모델 카드와 공개 비교 실험의 원자료를 확인한다. 설치·모델 다운로드·게임 시험·유료 API 호출은 하지 않았다. 모델 채택이나 설계 변경은 이번 결과에 포함하지 않는다.

이전 설계의 미정 사항에 대해 다른 작업 브랜치에 새 기록이 있음을 확인했다(11/3 19:32): 응답이 늦는 동안 반사 행동 허용, 응답 도착 시 해제; 평상시 2~3초 간격 잠정; 월10만원 선 검토. 마감값·반사 종류·API·정체 문턱 등은 여전히 미정이다. 기존 ‘반사 금지’를 최신 결정으로 재사용하지 않는다. 몸 시험도 이후 STEP1~3 성공 기록이 생겼다. 조사에서는 이 진행을 변경하지 않는다.

로컬 적합성 판단을 위해 읽기만 수행: 현재 GPU NVIDIA GeForce RTX 5080, nvidia-smi 총16303MiB; 시스템 메모리33,450,819,584바이트(약32GB급). 모델 동시 실행 성능은 측정하지 않았다.

## 결론

Jev보다 특정 평가에서 높은 품질 또는 낮은 비용을 보인 대안은 존재한다. 현재 비교 우선 후보는 **Perplexity Decider v1.2 / Decider Flash v1.2와 Jev1.14**다. Microsoft-Decision-1, Mercury Decide, d1-ultra도 검토할 가치가 있다. 공개 모델을 로컬에서 돌려 네트워크 지연을 없애는 경로도 있으나, 작은 모델의 정확도·컨텍스트와 게임 GPU 경합 때문에 자동으로 더 유리해지지는 않는다.

최고 모델 하나를 확정할 근거는 없다. 일반 분류·문서 검증 평가의 우위는 Core Keeper의 목표 수행·전투·성격 반영 우위를 입증하지 않는다. 모드가 구조화 상태를 제공하는 현재 방향에서는 멀티모달 지원은 부가 기능이지 필수 선정 기준이 아니다.

## 같은 입력의 비교에서 확인한 우위

[system-one-bench](https://github.com/alilibx/system-one-bench) 최신 round10(11/2)의 텍스트 결과. 별도 조사자가 results.json 원자료를 읽고 지수·비용을 재계산했다. 상세 산식·데이터·원자료 링크는 [벤치마크 조사](2026-11-03-jev대안-벤치마크.md)에 있다.

지수는16데이터셋의 정확도를 동일 가중치로 평균한100점 척도다. 전체 문항 정답률과 다르다. 3250개 입력·4850개 판단이며, 모두 해당 실험의 OpenRouter alpha/decisions 호출 결과다. 한국에서 직접 공급자 API를 호출했을 때의 지연 보장이 아니다. 비용은 API가 보고한 usage이며 모델별 토큰 계산도 다르다. 기록 비용을 현재 공식 토큰 단가로 혼동하지 않는다. Mercury 무료경로는 실제 상용비용보다 유리하게 비교하지 않는다.

이 조건에서 Decider27B는 품질과 비용에서 유리했고 Jev는 속도에서 유리했다. Flash4B는 Jev보다 지수·p50·비용이 유리하지만 p95는 거의 같았다. 실행 조건·호스팅·모델 버전과 측정 시점 차이는 남는다. 원자료 검산은 모델을 다시 실행한 독립 재현과 다르다. 예컨대 Jev1.14와 Decider1.2는 실행일도10/15와10/25로 다르다.

## 공식 API 후보

### Jev1.14 — 비교 기준

[TypeSafe 모델 문서](https://docs.typesafe.ai/models): 최신 안정 버전은 `jev-1.14.0`, `jev-latest`가 이를 가리킨다. 입력$0.042/M토큰·출력무료. 기본64k/request·32k/question, 텍스트·JSON 상태를 읽는다. 영어가 주 학습 언어이며 한국어 등 CJK 품질은 자기 과제로 확인해야 한다. 과거 Jev1.13 비교 결과를 최신판 열세로 단정하지 않는다.

### Perplexity Decider v1.2 / Flash v1.2

[공식 API 문서](https://docs.perplexity.ai/docs/decisions/quickstart), [27B 모델 카드](https://huggingface.co/perplexity-ai/pplx-decider-v1.2), [Flash 모델 카드](https://huggingface.co/perplexity-ai/pplx-decider-flash-v1.2). 일반판은27B, Flash는4B급이며 공개 가중치 라이선스는 Apache2.0이다. 공식 호스팅 입력 단가는 각각$0.02/M·$0.01/M, 출력은 무료다.

과금 구조는 다르다. 일반판은 질문 묶음에서 공유 상태를 한 번 처리하지만 입력 한도 때문에 그룹이 나뉘면 그룹마다 다시 과금한다. 호스팅 Flash는 질문마다 공유 상태를 반복 처리·과금한다. 따라서 질문이 많은 호출에서 Flash가 항상 저렴한 것은 아니다. 공개 Flash의 공동 질문 추론과 호스팅의 질문별 추론도 구분해야 한다. 과거 v1.1 API 이름은 현재 v1.2로 연결되지만 응답은 요청 이름을 그대로 표시하므로, 응답의 이름만으로 실제 버전을 확인할 수 없다.

### Microsoft-Decision-1

[공식 출시 글](https://commandline.microsoft.com/microsoft-decision-1-model-foundry/), [사용 문서](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/how-to/use-foundry-models-microsoft-decision).

Qwen3.5-9B를 판단용으로 후학습한 서비스. Foundry와 OpenRouter에서 제공, 입력$0.042/M·출력무료로 발표했다. noul·choice·score 형식이다. 제작자는36개 벤치·약15만문항에서 우위와 선택지 변형 내성을 보고한다. 이는 제작자 평가이며 우리 게임 성능 증거가 아니다. 지역 가까운 배포를 선택할 수 있으나 문서도 지연 개선을 보장하지 않고 실측을 요구한다. 공식 배수 속도 주장을 게임 반응시간으로 환산하지 않는다.

### Mercury Decide

[공식 모델·요금 문서](https://docs.inceptionlabs.ai/get-started/models). `mercury-decide`를 `v1/decisions`로 호출한다. 텍스트·JSON·이미지, 이진판단·선택·점수 및 추출 기능을 문서화했다. 현재 입력$0.02/M은 정상$0.04의50%할인가, 출력무료다. 할인 지속을 가정하지 않는다. 일반 Mercury의 생성 tokens/s와 Decide의 완전 응답 지연은 다른 지표다.

### d1-ultra

[Liquid 공식 발표](https://www.liquid.ai/blog/d1-ultra). 10/15 발표, 텍스트·이미지와 noul/choice/score, 입력$0.042/M·출력무료. 각 질문은 공유 문맥·이미지를 포함한 별도 프롬프트로 과금되므로 Jev와 동일 단가라는 이유로 여러 질문 묶음 비용도 같다고 할 수 없다. 제작자는 Jev1.14 대비112평가 우위를 보고한다.

[Vals ClaimBench](https://www.vals.ai/benchmarks/claimbench)는 1960개의10-K문서 주장 판별에서 d1-ultra100%, Deciderv1.2 99.69%, Mercury99.08%, Jev1.14 98.06%를 게시했다. 표의 지연은 각각0.67/1.23/0.72/0.18초다. 이는 gateway 측정으로 sandbox에서 gateway까지의 구간을 제외하므로 위 OpenRouter 클라이언트 왕복 수치와 직접 비교하지 않는다. 이 한정된 문서 과제에서 품질 우위와 속도 교환관계가 보인다. 현장 게임 선택 성능으로 일반화하지 않는다.

### OpenAI Decisions

[공식 문서](https://developers.openai.com/api/docs/guides/decisions)를 OpenAI Docs 절차로 확인했다. 현재 `gpt-6-luna`를 `POST /v1/decisions`에서 사용하며 predicate·choice·score를 지원한다. 텍스트·이미지·JSON, 공유 입력 캐시, 최대400질문 기능이 있다. 비캐시 입력$0.10/M, 출력무료이고 캐시 쓰기·읽기 및 지역/장문 조건은 별도다. Jev와 요청·응답 스키마가 같지 않다. 문서의 Responses API 대비 약10배 속도 설명을 Jev보다 빠르다는 근거로 쓰지 않는다. 위 OpenRouter 결과 역시 OpenAI native endpoint의 전면 평가가 아니다.

### Drex Max / Instinct — 추가 발견

[Drex 공식 카탈로그](https://console.nace.ai/docs/drex/reference/models): `drex-max-v1.1`(10/28)과 `drex-max`는 별도 버전, 입력$0.03/M. 구 Max 결과를 v1.1 결과로 바꾸어 적지 않는다. 기본 alias는 최신Max가 아닌 `drex-v2.0`이어서 정확한ID 확인이 필요하다.

[Instinct 공식 페이지](https://instinct.zoowork.ai/), [자체 비교의 제한 설명](https://zoowork.ai/blog/instinct-customer-service-decision-models/): 27B·dual4B·tuned4B 계열이 있다. ‘Jev보다 빠르고 정확’하다는231공개문항 비교는 시점·지역·클라이언트가 다르고 2문항차이며 공개문항을 개발에 이용했다. 제작자도 전면 우위 증거로 삼지 말라고 명시한다. 이번 최우선 비교 후보로 선정하지 않았다.

## 공개 가중치와 로컬 경로

정확한 버전·라이선스·하드웨어 조건은 [공개 모델 조사](2026-11-03-jev대안-공개모델.md)에 정리한다. 모델 계열 이름과 실제 제공 checkpoint/API 버전을 구분한다. 특히 Perplexity Decider와 Mapika Decider는 별개다.

현재 PC의16GB급GPU에서 27B급 BF16 서비스 벤치 속도를 그대로 기대할 수 없다. 작은 모델 또는 양자화가 필요하며 게임과 함께 돌릴 때 메모리·연산 여유를 봐야 한다. 로컬은 외부 토큰 청구가 없어도 전력·GPU 자원·운영 비용이0은 아니다.

- **Kev1.0:** 0.8B·4B·9B·27B 공개 모델. [Kev-4B 공식 CUDA 구성](https://github.com/jaredpalmer/kev/blob/main/docs/model-cards/kev-4b.md)은 상주 메모리 약14.3GB로 현재GPU에서 게임과 함께 쓰기에는 여유가 적다. 양자화4B 또는0.8B는 검토할 수 있지만 품질과 게임 동시 실행 지연은 미측정이다. 다른GPU의 수십ms 결과를 RTX5080 실측처럼 쓰지 않는다.
- **Laya:** [421M 모델](https://huggingface.co/convaiinnovations/laya)과322M 다국어판이 있다. 작은 크기는 장점이나 공개 평가에서 제로샷 판단 품질이 낮은 과제가 있어 Jev의 동등한 대체재로 보기 어렵다. 높은 미세조정 점수와 제로샷 점수를 구분한다.
- **Decider Flash v1.2:** 공개 가중치가 있어 로컬 실험도 가능하지만 이PC의 VRAM 사용량·게임 동시 실행 p95는 확인하지 않았다. 호스팅 API 비교가 현재 더 직접적인 출발점이다.
- **Mapika Decider / Cloudflare Clef:** 별도 공개 계열도 확인했다. Mapika는 기본 확률 온도가 벤치 점수와 확률 보정에 주는 영향이 있고, Clef Flash는9B다. 세부 조건은 공개 모델 조사에 정리했으며 현재 우선 후보보다 좋다는 충분한 근거는 확보하지 못했다.

## 프로젝트에 대한 판단

1. 당장 모델을 교체 확정하기보다 **Jev1.14 / Perplexity Decider Flash v1.2**를 속도 중심 첫 비교 쌍으로, **Deciderv1.2 27B**를 품질 우선 대조 후보로 삼는 것이 합리적이다. 조사자의 제안이며 실행 승인은 아니다.
2. 품질 우선 후보로 d1-ultra, 그 다음 MS/Mercury를 추가할 수 있다. 모든 후보를 동시에 붙이는 구조는 현재 결과에 필요 없다.
3. 평상시2~3초 판단이라는 잠정 방향에서는 수십ms 차이만으로 선택하지 않는다. 전투는 p95와 관찰→행동 적용까지의 지연, 늦었을 때 반사 개입·복귀까지 함께 봐야 한다.
4. 같은 상태·목표·선택지·지식으로 지시준수/목표진전/반복/한국어·영어 차이/선택순서 내성을 비교하고, 대표 실제 플레이에서 판단지연·사망·복귀·비용을 확인한다. 벤치 정확도는 이 검증을 대신하지 않는다.
5. 모델을 바꿔도 행동 실행·기억·LLM보고 구조는 유지할 수 있으나, API어댑터와 선택지/문맥 한도·확률 의미·과금·alias변경을 확인해야 한다. ‘base URL만 바꾸면 전부 동일’로 가정하지 않는다.

## 검증 범위

공식 웹·GitHub·Hugging Face 자료 조사 및 공개 벤치 원자료 집계 확인. 실제 모델추론·한국 네트워크지연·게임GPU경합·CoreKeeper 성능·청구 재현은 수행하지 않았다. 조사일 이후 버전·단가는 바뀔 수 있다.
