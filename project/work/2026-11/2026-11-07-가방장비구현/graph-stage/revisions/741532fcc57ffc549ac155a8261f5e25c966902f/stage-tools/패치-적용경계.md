# 가방·장비 그래프 staging 적용 경계

이 폴더는 루트 HEAD가 판단할 격리 후보다. 공식 그래프와 제품 코드는 이 작업에서 수정하지 않았다. `source-patches/`는 검토용 원본 차이이며 생성 JSON을 직접 수정하는 패치가 아니다.

새 `tree-agreement.md`의 분류→정확한 보유 물품→조작 흐름, 뒤로·전체 선택 취소, 개수 상한/임의 페이지 분할 제거를741532f 실제 코드 심볼·생성 그래프에 연결했다. F.bag-navigation은 구현됨·미확인 상태이며, 생산자/독립 오프라인 검사와741 자체 Unity/source SDK export 근거를 각각 구별한다. 원래 부탁·몸 제어와 메뉴 취소, 실제 게임 소비자·외부 모델의 미관측 경계를 유지한다.

**최신 공식 c4a0f5e 생활 트리가 병렬 반영되어 직접 적용은 차단했다.** 741은 복구 당시 공식685 위의 격리 가방 후보이며 현재 c4의 생활 코드/앵커를 담지 않는다. official-drift.json과 latest-official-c4a0f5e/에 그 변경과 원문을 보존했다. 기록된685 기획 prefix 해시는 그대로 확인했다. 최신 생활 기획을 지우거나741에 없는 생활 코드를741 관측으로 승격하지 않는다. 두 제품 코드/기획을 합친 SHA를 HEAD가 정한 뒤 현재 공식 위에서 가방 델타를 재적용·재핀해야 한다.

- 원래 복구한 staging은 UI 흡수판 11eb461 기준이었다. `recovery-before/`에 당시 기준 목록과 개수를 보존했다.
- 현재 공식의 공통 실행 685dde4와 최상위 `P.release-goal`(Core Keeper 모드 제작·배포)을 다시 복사한 뒤 가방 관련 선언만 재적용했다. 최신 기준 목록은 `canonical-before.json`이다.
- 여섯 `F.bag-*`, 승인 정책 둘, `U.bag-live`, 기존 `F.plan-queue`/`F.action-select` 앵커, 제품 intent→능력→정적 코드·게임 규칙·검증 근거를 기존 도구 방식으로 확장했다. 새 통합 그래프 아키텍처는 만들지 않았다.
- 원문과 실행 로그는 최종 SHA와 SHA-256로 구별한다. UI11eb461·리팩토링902721e·화면76563bf의 실게임 증거는 역사적 sourceCommit을 유지하며 현재 코드의 관측으로 승격하지 않는다.
- `history.md`, `context.md`, 작업 세션의 다른 기록 및 통째 복사한 `work/`를 공식에 역복사하면 안 된다. `stage-audit.json`의 원본 패치와 새 근거만 좁게 검토한다.
- 적용을 판단할 때 공식 G/P/L의 최신 해시와 `baseSha256`를 다시 비교한다. 이후 공식 입력이 바뀌면 해당 변경을 보존하고 가방 델타만 다시 적용한다.
- 코드가 병합되어 기준 SHA가 달라지면 새 공식 SHA로 Git blob 스냅샷을 다시 고정하고 Roslyn/Acorn·strict/check·제품 재생성을 다시 한다. staging 절대 경로를 사용하는 개발 `tools/config.json`의 codeRoot도 공식 snapshot 위치에 맞춰 바꿔 재생성한다.
- 후보 상태는 `구현됨·미확인`이다. 컴파일·오프라인 검사·최소 World 상태 주입 검사는 실제 게임의 소비자·슬롯 교환·수령 타이밍·원래 부탁 계속하기를 실행한 근거가 아니다. 실게임 보류가 해제되고 설치/시험이 승인된 뒤 `U.bag-live`를 검증한다.

기계 생성 결과는 원본에서 다시 만든다. 출처 패치 적용 뒤 `run-graph.mjs`가 사용하는 기존 13단계와 `queries.mjs`를 따른다. 중간판 검증 성공은 최종 독립검수 수용을 뜻하지 않는다.
