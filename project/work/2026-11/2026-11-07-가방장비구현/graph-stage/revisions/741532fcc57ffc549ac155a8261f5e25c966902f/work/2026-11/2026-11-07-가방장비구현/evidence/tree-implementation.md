# 분류 기반 가방·장비 선택 트리 구현

기준은 [사용자 합의](tree-agreement.md)와 [상세 명세](tree-spec.md)이며, 격리 후보는 `C:/Dev/CoreKeeperModSDK-bag-common`의 `741532fcc57ffc549ac155a8261f5e25c966902f`다. 본 저장소 반영·설치·실게임은 HEAD 판단 전이며 이 작업에서 수행하지 않았다.

## 모델이 실제로 고르는 흐름

일반 선택 목록의 인벤토리 진입을 고르면 **실제 보유 분류 → 그 분류의 개별 물품 → 가능한 조작 → 필요한 슬롯·자기 상자·수령자·수량 → 실행 확인**으로 진행한다. 이는 현장 판단 모델의 선택 상태이며 새 플레이어 GUI 창을 만들었다는 뜻은 아니다. 각 판단에는 현재 노드의 실제 자식과 뒤로·선택 전체 취소, 현재 동작 계속·명시 중단·단계 완료·상위 재계획 및 기존 생존/긴급 대응을 제공한다.

가방·핫바·현재 착용 위치를 구별하고 같은 종류의 다른 슬롯·변형·상태도 보존한다. 현재 목표가 구리 흉갑이어도 다른 보유 검·재료를 숨기지 않는다. 분류는 실제 ObjectType에 대응하며 Eatable을 사람 음식으로 단정하지 않고, 모르는 분류·메타데이터와 고장난 상태 0 장비도 보유 목록에서 누락하지 않는다. 내부 aux/갱신값은 식별 토큰 안에서만 보존하고 모델 문구에는 실제 위치·종류·변형·상태·개수를 보여준다. 숨은 장비 스탯/DB 전체 공개는 추가하지 않았다.

분류·물품·조작·대상 목록에는 숫자 cut이나 페이지가 없다. 수량은 1개·실제 요청 잔량·현재 가능한 전량의 짧은 경로와 그 밖의 유효 정수를 자리별로 입력하는 경로를 제공한다. 장착·해제·핫바·보관 목적지는 유효 슬롯을 모두 펼치며 첫 fit을 모델의 최종 목적지 대신 확정하지 않는다.

자기 상자 꺼내기는 상자 선택·접근/열어보기 이후 실제 관측한 내용만 분류·물품 단계에 노출한다. 열기 전이나 화면 밖 기억을 현재 물품으로 추정하지 않는다. 상자 접근/검사 leaf 뒤에는 그 결과를 기다리는 선택 상태를 유지한다.

## 실행과 취소의 의미

메뉴 navigation은 기존 cN 선택 응답과 실제 Loop.Apply 입구를 사용하지만 몸의 새 skill을 시작하지 않는다. 진입·뒤로·전체 선택 취소는 현재 몸 동작·목표·원래 부탁을 유지한다. 새로운 메뉴 결정이므로 이전 미적용 in-flight/prefetch/held/queued/next-hit 선택 권한은 기존 CancelPendingChoices로 폐기한다. 이미 실행 중인 몸을 중단하는 명령과 메뉴 전체 취소는 구별된다.

메뉴 토큰은 노드·revision·원래 목표 참조·실제 물품 스냅샷에 묶는다. 물품이나 역할이 바뀌면 다른 물건에 선택을 재해석하지 않고 변경 사실과 유효한 부모 단계로 복구한다. `741532f`는 head40의 물건이 같아도 active head가60으로 바뀐 경우를 잡되, 가방 slot12를 고르는 중 무관한 head preset 변경은 그 선택을 무효화하지 않게 좁게 보완했다.

최종 leaf만 검수된 정상 Swap/MoveAmount/DropItem과 실제 결과 관측을 재사용한다. 선택한 조작이 현재 목표를 실제로 충족할 때만 그 목표에 receipt를 연결한다. 흉갑 목표 중 검을 보관/내려놓는 준비 행동이 흉갑 완료가 되지 않는다. 요청 접수나 시간 경과를 성공으로 세지 않고 재전송하지 않는다. 수령자의 실제 증가와 해당 바닥의 실제 감소가 같은 경우에만 전달 수량을 확인한다.

## 상한 제거와 유지한 경계

[cap 결과](tree-cap-result.md)와 [감사](inventory-category-cap-audit.md)에 따라 가방 8/12/20, 전체 비전투14, 양수 combat 후보 cap, closeFight goalSide ONE quota와 현장 채굴·줍기·이동 등 동일 목적의 숫자 shortlist를 제거했다. 기존 eligibility·긴급성·정렬·실행 가능성·시야·소유권은 유지한다. Core/AIBaseEdge의 상위 둘레 설계안4, 보고 요약, 실제 탐색 guard·행동 batch·기록 보관 제한은 다른 소비자/의미여서 유지했다. 호출/비용 cap은 증가시키지 않았다.

기존 base/craft/farm의 상자 준비·이동 로직과 실제 skill은 재사용한다. 외부 일반 선택 목록의 기존 per-item `inventory/store/take`를 제거하여 트리가 같은 평면 선택 옆에 추가되기만 하는 상태를 피했다. 기존 먹기는 회복·허기 대응이라는 별도 소비자로 유지했으며, 선택한 개별 물품의 새 eat 실행을 추가하지 않았다. 원거리 발사·조준, 제작·수리·강화, 자원 공유 정책, 영구 삭제는 이번에 넓히지 않았다.
