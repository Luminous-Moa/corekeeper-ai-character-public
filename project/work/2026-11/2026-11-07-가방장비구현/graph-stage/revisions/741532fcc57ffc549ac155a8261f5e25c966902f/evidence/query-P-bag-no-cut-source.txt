24: ## 선택지 상한 제거
25: 
26: - 기존 일반 가방 후보 8개와 전체 비전투 기본 후보 14개 제한을 제거한다.
27: - 분류·물품·조작·대상 목록을 임의 숫자로 자르거나 페이지로 분할하지 않는다. 현재 노드의 실제 항목을 모두 제공하며, 트리의 분류로 한 단계의 선택 범위를 나눈다.
28: - 현장 후보 생성·전달 경로의 개수 기반 잘라내기를 조사한다. 같은 목적으로 선택지를 누락시키는 상한은 제거하고, 실제 관측 범위·소유권·실행 가능성 조건이나 로그/기억 보관량 같은 다른 의미의 제한은 구별해 보존한다. 해상도가 다른 제한을 조용히 같은 것으로 취급하지 않는다.

30: ## 실행·모델 연결 조건
31: 
32: - 기존 AICandidate/선택 응답 경로를 가능한 만큼 재사용한다. 메뉴 선택은 AISkill 실행·완료와 구별하며, 공통 stop_action/finish_goal/request_plan을 중복 구현하지 않는다.
33: - 원래 부탁과 목표, 실행 가능한 기존 몸 동작을 유지한다. 선택 메뉴를 탐색하는 동안에도 매 판단에 현재 상황·위험·실행 사실을 전달하고 기존 공통 대응 경로를 유지한다.
34: - 물품·슬롯·수량·상자·목표가 탐색 중 바뀌면 실제 상태를 대조한다. 오래된 메뉴 응답이나 이전 노드의 선택을 다른 물품의 실행으로 적용하지 않는다. 변경 사실을 보고하고 유효한 선택 단계에서 다시 판단한다.
35: - 최종 실행은 검수된 기존 Swap/MoveAmount/DropItem 및 실제 결과 관측을 재사용한다. 요청을 중복 전송하지 않고, 양 슬롯 변화·드롭 실소비·지정 수령자의 실제 증가로 결과를 판단한다.
36: - 단계별 모델 호출은 생기지만 기존 호출·비용 상한을 늘리지 않는다. 예산 제한이나 응답 실패를 이유로 메뉴 선택을 실행으로 승격하거나 유효한 몸 동작을 강제 취소하지 않는다.
37: - 이번 변경은 가방·장비 선택 트리와 요청한 후보 상한 제거다. 채굴·전투·시설 전체를 별도 다단계 트리로 재설계하거나 숨겨진 장비 스탯·DB 전체를 새 공개 정책으로 노출하는 작업은 포함하지 않는다. 현재 후보에 성능 비교 정보가 적다는 한계는 기록한다.
