# 선택 트리 초기 설계 독립 검토

2026-11-07. 검토 근거는 `tree-agreement.md`, `tree-spec.md`, `inventory-category-cap-audit.md` 및 그8절 HEAD 적용 판정이다. 독립 검수 컨텍스트가 읽은 설계 검토이며, 미완성 코드 검수·실행 검증·최종 수용이 아니다. 기존 평면판 QA를 다시 수행하지 않았다.

**판정: 현재 세 문서 사이에서 진행을 막을 중대한 설계 모순은 발견하지 않았다.** 물품 중심 다단계 선택과 실행 부품 재사용, 상한 제거와 기존 관측·예산 경계의 구분이 합의에 맞는다. 최종 고정판에서는 다음 경계를 실제 소스·입구 재현으로 확인해야 한다.

1. **현재 노드의 자식만 메뉴 선택으로 전송.** 분류→현재 실제 물품→가능한 조작→필요 인자→실행의 한 단계씩 진행한다. 다른 깊이·비관련 평면 행동을 섞지 않는다. 단, 명시된 continue/stop_action/finish_goal/request_plan 및 실제 긴급 대응은 공통 제어·위험 대응으로 유지한다. 이를 메뉴 자식과 구별하는 설명과 전송을 확인한다. 전투에서 유효 무기를 고르거나 드는 승인 경로가 도달 가능하도록 기본 inventory 진입이 closeFight의 기존 goalSide/progress 필터나 GoalNone 자기방어 세트에서 누락되지 않아야 한다. 이미 탐색 중에는 메뉴 자식·뒤로/취소와 공통/긴급 world 제어가 모두 도달 가능해야 한다. 이는 명세의 실행·위험 대응 유지 경계를 확인하는 것이며 새 전투 계획 정책을 추가하는 요구가 아니다.
2. **뒤로/전체 선택 취소는 메뉴 상태 전이뿐.** 활성 몸 동작·goal·원래 부탁·인벤토리 큐에 부작용이 없어야 한다. stop_action이나 finish_goal의 별칭으로 구현하지 않는다. 메뉴 navigation은 ApplyOrHold/prefetch의 몸 전환 대기보다 먼저 처리하고, 미리 받은/보류한 이전 메뉴 선택도 새 노드에 재적용하지 않는다.
3. **실행 leaf만 한 번 요청.** 물품·조작·목적 슬롯·수량·상대가 정해지기 전에는 Swap/MoveAmount/DropItem이나 대체 몸 skill을 시작하지 않는다. 자기 상자 접근/열어보기는 명세가 구별한 **inspect 실행 leaf**이며, 단순 상자 메뉴 진입·대상 탐색과 구별한다. inspect 완료 후 같은 경로에서 실제 관측한 상자 내용을 선택하게 하는 연결도 확인한다.
4. **목록은 현재 보유 인스턴스.** goal 품목이나 DB catalogue가 원본이 아니다. 가방·핫바·활성 착용 슬롯을 실제 위치와 함께 읽고 동일 ID의 다른 슬롯/변형/aux/상태를 보존한다. 빈 분류는 없고 info 없음·미분류·파손 보유 물품도 접근 가능해야 한다. 상자 내용은 기존 자기 소유·접근/열어본 관측 범위만 사용한다. 조작의 가능 여부와 분류/물품 존재를 혼동하지 않는다.
5. **늦은 응답은 revision+노드+스냅샷으로 차단.** 뒤로/취소/다른 물품/새 목표·월드·캐릭터 전환을 거친 답을 새 선택으로 해석하지 않는다. 노드 구성 시점과 적용 직전, 최종 leaf 실행 직전의 재검증을 구별한다. 변경 사유를 남기고 유효한 부모 단계로 복구하되 몸 동작·원래 부탁을 강제 취소하지 않는다. 비목표 물품의 조작은 유효하지만 receipt는 실제로 일치하는 목표 조건에만 귀속한다. **메뉴 토큰뿐 아니라 메뉴 결정 이전의 일반 world 응답·prefetch·held·queued·next-hit의 적용 권한도 함께 다뤄야 한다.** 기준1fc89b9의 `AIBrain.Loop.cs:881` StaleReason은 goal Revision과 대상/run만 검사하며, held/queued/next-hit도 이를 사용한다. 그러므로 goal/target이 그대로라는 이유만으로 이전 world 답이 새 enter/back/cancel을 덮어서는 안 된다. 기존 `AIBrain.CancelPendingChoices`는 pending을 비우는 접점이며 몸/goal을 직접 바꾸지 않는다. 기존 공통 응답 권한과 메뉴 epoch를 연결하는 구현 경계로 owner/HEAD에 전달했다. 이는 미완성 코드의 실패 판정이나 별도 프레임워크 추가 요구가 아니다.
6. **상한·예산·긴급 제어를 구별.** 메뉴 분류/물품/인자와 현장 Decisions의8/14·유사 countcut·closeFight ONE 할당량은 제거하고 페이지로 대체하지 않는다. 상위 둘레 설계 제안의 CoreEdge.Options4, 보고/기억/로그 요약과 실제 탐색·물리/소유/실행 조건은 HEAD 판정대로 보존한다. 기존 호출·비용 상한은 늘리지 않는다. 한도·응답 실패는 navigation/leaf의 묵시 실행이나 유효 몸 동작 취소의 근거가 아니다.

최종 고정판 인수 증거는 실제 소스에 연결한 메뉴 노드 전이와 모델 전송 배열, 각 단계의 요청 큐/몸/목표/원래 부탁 전후, stale 응답 차단, 8/14 초과 전량 접근, 상자 inspect 이후 관측, 예산 차단 중 기존 실행 보존이다. 현재 설계의 정합성은 이 증거를 대신하지 않는다. Unity·설치·게임·외부 모델 호출·제품 수정·공식 그래프 쓰기는 수행하지 않았다.
