# 가방·장비 중간 flat판 구현 및 공통 실행 통합

이 문서는 이전 flat 선택지 방향의 **중간 구현**을 보존한다. 사용자가 인벤토리 물건 선택→가능 조작→뒤로/전체 선택 취소가 있는 트리 방향을 새로 요청해, 이 판의 최종 수용·패키징은 보류됐다. 아래 입력/조작 primitive와 검증은 새 방향에서 재사용할 근거이며 트리 구현 완료가 아니다.

기존 [구현 합의](agreement.md)와 [계획안](../2026-11-07-가방장비-계획안.md)에 따른 격리판이다. 본 저장소·설치본·게임을 변경한 결과가 아니다. 보존 후보는 `C:/Dev/CoreKeeperModSDK-bag-common`, Git `bag-equipment-common-20261107`, 전체 커밋 `1fc89b93edbee31a9001a174581e32568119efc1`이다. 공통 실행 공식 기준 `685dde4`를 포함한다.

## 구현된 흐름

- **장착·교체·해제:** 실제 활성 장비 프리셋과 출발/목적 슬롯을 대상으로 정상 Swap 요청을 한 번 보낸다. 양 슬롯의 실제 교환과 현재 활성 착용 상태로 성공을 확인한다. 반지·파우치의 목적 슬롯을 구별하며, 가방·파우치 축소로 물건이 자동으로 떨어질 조건을 확인한다.
- **명시한 손 장비:** 곡괭이와 근접무기 선택을 캐릭터별로 유지한다. 실제 손 슬롯·개별 물품이 준비되기 전에는 공격 입력을 보내지 않고, 공격·짧은 공격·채굴 중에도 같은 물품인지 확인한다. 사용 중 정상 내구도 감소는 허용하며, 같은 ID의 다른 variation/aux 교체·파손은 다른 장비로 몰래 대체하지 않고 사실로 보고한다. 보관·먹기·일반 단계 완료는 명시 선택을 초기화하지 않는다.
- **보관·꺼내기:** 기존 일반 가방 정리와 상자 준비/이동을 유지하고, 명시 품목·출발 슬롯·자기 상자·요청 개수·남길 개수를 연결했다. 정상 MoveAmount를 사용하며 파괴·오버플로 드롭 경로를 쓰지 않는다. 양쪽 실제 변화가 같은 수량일 때만 그 수량을 누적하고 잔량을 다음 판단에 전달한다. 비중첩 장비의 amount는 개수가 아닌 원래 상태값으로 보존한다.
- **내려놓기·전달:** 명시 목표에서만 자기 위치에 정상 DropItem을 요청한다. 다른 플레이어의 가방을 직접 쓰거나 강제 흡입 상태를 만들지 않는다. 내려놓기는 출발 감소와 이번 바닥 물건 생성, 전달은 해당 바닥 물건의 지정 수령 요청·실제 감소/소멸·수령자 가방 증가가 같은 수량인지를 확인한다. 부분 수령만 확인되면 확인된 수량만 기록한다. 타인 선점이나 귀속 미확인은 성공으로 처리하지 않고 재전송하지 않는다.
- **공통 실행:** 개별 성공 receipt는 같은 목표 객체에 한정한다. 관측 결과는 공통 목표 입력에 전달하며, 단계 완료는 AI의 `finish_goal`, 원래 부탁 완료는 상위 LLM의 `order=done`에 맡긴다. 요청 후 3/6초 또는 수령자 접근 30초 경과는 중복 없는 관측 사실로 올리고 유효한 요청을 강제 취소하거나 다시 보내지 않는다.

상위 계획의 `equip/unequip/hold/take/drop/give` 및 기존 `store`와 `item/count/where/keep/slot`을 목표·후보·몸 실행까지 전달한다. 새 실행·슬롯 관측은 `AIInventory`, 실행 중 손 장비 확인은 `AIHandLease`와 Core 규칙에 분리했다. 공개 가능한 자기 가방·착용 상태와 자기 상자 기억만 선택 입력에 쓰며 수령자 가방 전체를 모델에 공개하지 않는다.

## 검수 지적 반영

[단계1 검수](review-stage1.md)의 실행 중 손 장비 교체, 기존 품목 지정 Store 거부, 점유 핫바 목적칸 누락, 완료 후 역교체 후보 네 건을 후속판에서 수정했다. [feature 검수](review-feature.md)의 Give 거짓 성공과 slot-only Store 무상자 준비 누락은 `3095226`/통합 `b4cbef7`에서 수정했다. 최종 통합판의 독립 재검수 결과와 실제 검증 범위는 [검증 보고](validation.md)를 따른다. 과거 판의 통과/실패를 최종판의 실게임 성공으로 바꾸지 않는다.

추가 독립 검수에서 열린 상자의 모든 같은 품목 스택이 9,999개로 가득 찼는데도 기존 준비 경로가 자리가 있다고 세는 경계를 발견했다. `1fc89b9`는 보이는·열어본 상자의 준비/배치 판단을 새 물품 이동과 같은 실제 목적 슬롯 조건/남는 공간으로 묶었다. 화면 밖의 과거 기억은 현재 공간을 단정하지 않고 가서 확인하는 경로로 유지한다.

## 작업 경계

기존 호스트/다른 AI 상자 공유 정책, 원거리 발사·조준, 시설 제작·수리·강화, 영구 삭제(trash)는 변경하지 않았다. 자연 드롭·줍기 전달은 수령자 독점 거래를 보장하지 않는다. 슬롯/ID/variation/aux/상태는 관측 가능한 구별 근거이며 영구 물품 UUID가 아니다.

이전 상세 작업자의 대화 컨텍스트는 현재 실행에 보존되지 않았다. 이 결과는 저장된 커밋·명세·실제 재실행 로그를 읽어 새 상세 실행 컨텍스트가 이어서 확인한 것이며, 예전 컨텍스트 자체를 복원했다고 주장하지 않는다. 사용자 승인과 전체 작업 판단은 원래 HEAD가 유지한다.

설치·실게임·외부 모델 호출은 보류를 유지했다. 자연어 부탁부터 게임 소비자와 실제 몸 동작까지의 기존 실행안은 [실게임 준비](runtime-plan.md)에 보존하지만, 새 트리 합의에 따라 선택 단계와 증거 조건을 갱신해야 한다. 설치 없는 정상 SDK export 경로와 격리 Editor helper까지 준비했으며 실행하거나 후보 패키지를 생성하지 않았다.
