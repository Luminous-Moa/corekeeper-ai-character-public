# 인벤토리 실행 모듈 명세

범위는 AIInventory.cs와 새 독립 규칙/시험 파일이다. 기존 goal/planner/body 연결은 상위 실행 소유자가 담당한다. 승인된 계획의 입력과 실제 게임 소비자를 대조한 구체화이며 제품 정책을 새로 만들지 않는다.

입력: 현재 캐릭터의 실제 가방/활성 장비 슬롯, 목표와 현재 실행 키. 후보는 정확한 출발·도착 슬롯과 ContainedObjectsBuffer 스냅샷을 보존한다. 일반 장착 후보는 물품의 게임 ObjectType에 맞는 실제 활성 장비 슬롯마다 만들며 반지·파우치의 목적지는 AI가 구별해 고른다. 요청한 목표의 item/slot/where와 일치하는 후보를 먼저 제시한다. 명시 없는 버리기·전달·상자 내용 전수공개는 하지 않는다.

장착/교체/해제: UI 큐의 Inventory.Create.Swap 요청 하나를 사용한다. 실행 직전 양 슬롯을 EqualsExact로 대조하고 현재 활성 장비 목적지와 타입 요구조건을 확인한다. 해제는 빈 유효 가방 칸으로 옮긴다. 배낭·파우치 교환 전에는 바뀐 용량/태그 요구조건에 의해 물건이 자동으로 떨어질 슬롯이 없는지 검사한다. 결과는 양 슬롯이 정확히 교환된 실제 관측으로 확인한다. 게임의 장비 조건 재요약은 정상 소비자에 맡긴다.

손 선택: 가방 물품은 AI가 고른 구체 핫바칸으로 Swap하고, 기존 핫바 물품을 출발 슬롯으로 돌려보낸 것을 관측한다. 핫바 물품은 BodyInput.slot으로 선택하고 EquippedObjectCD.equippedSlotIndex/containedObject를 확인한다. 성공한 정상 곡괭이·근접무기는 각각 캐릭터별 명시 선택으로 보존한다. 이후 내구도 변화는 허용하되 slot/objectID/variation/auxData가 바뀌거나 파손되면 자동 대체하지 않고 이유를 반환한다.

공통 gate: 실제 player/inventory/UIActionBuffer, 살아 있는 상태, guest 권한, 커서 비어 있음을 확인한다. Swap은 game consumer가 요구조건을 확인하지 않는 저수준 API이므로 모듈이 유효 범위·타입·가방 요구조건을 먼저 확인한다. 요청 성공 자체를 실행 성공으로 세지 않는다. 미관측 상태에서 같은 요청을 재발송하지 않는다. 개별 요청 후 관측 불가/지연은 사실과 사유로 끝내며 원래 목표를 취소하거나 완료로 만들지 않는다.

상태: 캐릭터별 Dictionary<AIAgent,State>. 목표 receipt는 동일 AIGoal 인스턴스에 한정한다. 목표를 설정하면 receipt·누적이동량을 초기화하고 목표별 실제 완료 사실을 추적한다. 원래 부탁의 완료와 공통 stop_action/finish_goal/request_plan은 이 모듈에서 처리하지 않는다.

검증: compile-check, 슬롯 identity/이동량/공간/오래된 요청의 오프라인 규칙 시험, 실제 게임 검증을 위한 정확한 후보·결과 로그를 남긴다. Unity·설치·실게임은 이 소유자가 실행하지 않는다.

상자·Drop/Give의 구체 상태기는 단계1을 전달한 뒤 검수된 게임 소비 경로에 따라 추가한다. 미구현은 성공으로 반환하지 않는다.

## 후속 상자 조작

명시 품목/개수/keep/where가 있는 Store 및 모든 Take 목표를 이 모듈이 맡는다. 나머지 generic Store의 자동 정리 품목 범위는 기존 모듈이 유지한다. where는 자기 상자의 `chest:x,y` 식별자 또는 base/빈값이다. 상자 후보는 AIBase의 자기 소유 기억과 일치해야 한다. 내용은 상자 옆에서 열기/살펴보기 동작을 선택해 NoteOpened를 수행한 뒤 현재 화면에 공개한다. 기존 기억은 과거 값이라고 표시한다. 화면 밖 자기 상자는 기억된 위치로 가는 기존 이동 후보를 제공하고, 그 후보는 상자 수령 완료가 아니다.

Store 후보는 일반 가방의 한 물품 슬롯과 실제 유효 상자 목적 슬롯, 요청 잔량·남길 수량으로 계산한다. Take 후보는 열어 살펴본 자기 상자의 한 출발 슬롯과 유효 일반 가방 목적 슬롯을 지정한다. 빈칸 또는 같은 stackable 물품의 남는 stack 공간만 목적지로 사용한다. 요청은 Create.MoveAmount(...,destroyExisting:false) 한 번이며 오버플로 drop 경로를 쓰지 않는다. 비중첩 물품은 슬롯당 한 개이고 게임 amount는 전체 상태값으로 이동한다. 먼저 큐에 넣은 한 동작의 실제 source감소=destination증가를 확인한 뒤 누적 이동량과 잔량을 갱신한다. 일부 이동은 실제 수량만 기록하고 다음 선택을 다시 받는다. 원하는 수량에 못 미쳤다는 이유로 목표를 자동으로 완료하지 않는다.

## 후속 내려놓기·전달

Drop/Give는 명시된 목표에서만 후보를 만든다. 둘 다 자기 물품의 정상 Create.DropItem(player,slot,amount,selfPosition,player) 한 요청으로 실행한다. Give는 보이는 목표 수령자까지 기존 길찾기로 접근한 뒤 떨어뜨린다. 다른 플레이어 inventory에 직접 MoveAmount를 쓰지 않는다. 수령자에게 물건을 강제 흡입시키지 않는다.

큐 전후 바닥 entity 집합을 대조해 이 요청에서 생긴 일치 물품 하나를 추적하고 출발 슬롯의 감소량을 확인한다. Drop 완료는 출발 감소와 해당 바닥 물품 생성이다. Give 완료는 그 바닥 물품의 PickUpItemCD 대상이 목표 수령자로 관측된 뒤 사라지고, 목표 수령자의 일치 물품 슬롯 총량이 실제로 증가한 경우다. 우연한 같은 품목 증가만으로 전달을 완료하지 않는다. 다른 사람이 주웠거나 누구에게 갔는지 관측하지 못하면 사실을 보고하며 재전송하지 않는다. 수령자 가방 전체 내용을 모델 입력으로 공개하지 않고 이 전달의 수령 확인만 결과에 쓴다.
