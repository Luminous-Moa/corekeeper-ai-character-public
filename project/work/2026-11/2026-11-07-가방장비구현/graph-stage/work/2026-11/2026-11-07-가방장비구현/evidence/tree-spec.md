# 분류 기반 가방·장비 트리 상세 실행 명세

근거는 [사용자 트리 합의](tree-agreement.md)다. 중간 flat판 `1fc89b9`의 정상 조작/관측 primitive를 재사용하며, 선택 목록과 호출 흐름은 아래 방식으로 교체한다. 상한·페이지·목표 품목 필터를 보유 목록에 적용하지 않는다.

## 모듈과 선택 상태

`AIInventoryMenu`는 캐릭터별 메뉴 노드/부모 경로/선택한 실제 물품 스냅샷/추가 인자/메뉴 revision을 소유한다. 보유 목록은 현재 주 가방·핫바·현재 활성 착용 슬롯의 실제 물품으로 만들며 같은 물품 종류라도 슬롯·변형·상태가 다르면 별도 항목으로 둔다. 분류는 게임 유형에 대응하고 모르는 분류는 기타로 남긴다. 현재 목표의 item은 목록을 숨기는 필터가 아니라 요청·진척 맥락이다.

기본 판단에는 인벤토리 진입 하나를 제공한다. 진입 후에는 현재 노드 자식과 뒤로/전체 선택 취소를 기존 `AICandidate`/응답 `cN` 경로로 전달한다. 별도 선택 토큰은 메뉴 revision/현재 노드/실제 대상 스냅샷에 묶는다. 오래된 노드의 답이 뒤로 또는 다른 물품의 선택으로 재해석되지 않아야 한다.

노드는 인벤토리 출처(자기 가방·착용/자기 상자) → 비어 있지 않은 분류 → 실제 물품 → 가능한 조작 → 필요한 목적 슬롯·상자·수령자·수량 → 최종 실행이다. 가방 출처 진입이 분류로 바로 이어지도록 하고 자기 상자 꺼내기 진입은 별도 자식으로 둔다. 상자 선택 후 접근/열어보기는 정상 inspect leaf이며, 그 결과로 실제 관측한 내용만 분류·물품 노드에 제공한다.

수량은 현재 가능한 전량·1개·요청된 남은 수량과 직접 정수 입력을 제공한다. 직접 입력은 자리별 숫자 선택, 지우기/확정으로 모든 유효 정수에 도달하게 하며 수량 preset으로 가능한 요청을 누락하지 않는다. 물품 목록 페이지나 개수 cut을 만들지 않는다.

## Loop와 몸 동작의 경계

메뉴 navigation의 적용은 몸 동작 `ApplyOrHold`/prefetch 완료 대기보다 먼저 처리한다. 메뉴를 들어가거나 뒤로/취소했다는 이유로 `AIBody.Stop`, 새 skill 시작, goal 변경/완료를 호출하지 않는다. 기존 몸 동작은 유효한 한 이어 간다. 최종 leaf 선택만 기존 Skill 적용 경로를 이용하고, 명시적으로 선택한 새 실행에 대한 기존 전환 의미를 유지한다.

메뉴 진입/뒤로/취소는 새로운 AI 선택이므로 이전의 미적용 world in-flight/prefetch/held/queued/next-hit 선택 권한은 기존 `CancelPendingChoices`로 폐기한다. 그 입구는 pending 참조와 요청만 비우고 몸/목표를 직접 변경하지 않는 것을 소스로 확인했다. 기존 실행은 유지하되 이전 선택이 뒤늦게 새 메뉴 결정을 덮어쓰지 않게 한다.

활성 메뉴에서도 현재 상황·위험·실행 사실과 공통 stop_action/finish_goal/request_plan, 현재 동작 계속, 실제 전투 대응 경로를 유지한다. 비관련 평면 일반 행동 목록과 트리의 다른 깊이 노드는 현재 메뉴 자식에 섞지 않는다. 메뉴 탐색으로 모델 호출이 추가되지만 기존 call/cost 제한은 바꾸지 않는다. 한도/실패 시 navigation이나 leaf를 임의 실행하지 않는다.

새 목표/월드/캐릭터 교체는 이전 메뉴 토큰을 무효화한다. 물품 스냅샷이나 활성 프리셋·상자 관측 조건이 바뀌면 변경 사실을 알리고 유효한 부모 단계로 돌아간다. 해당 변경은 원래 부탁과 유효 몸 동작을 취소하는 의미가 아니다.

## Leaf와 목표 진척

Leaf의 물품·대상·수량을 모두 확정한 뒤 Stale을 다시 검사하고 기존 Swap/MoveAmount/DropItem을 한 번 요청한다. 조작 선택이 현재 목표를 실제로 충족하는 경우만 그 목표에 receipt를 묶는다. 가령 구리 흉갑 목표 중 선택한 예비 검 보관은 유효 준비 행동이지만 흉갑 완료로 만들지 않는다.

상자 열어보기 leaf 이후에는 같은 선택 경로에서 실제 내용을 확인하도록 대기 노드를 유지한다. 물품 이동/장착 등 최종 leaf 뒤에는 메뉴 선택을 닫고 정상 관측과 다음 판단으로 이어간다. 완료한 물품의 이전 출발 슬롯에 돌아온 장비를 같은 목표의 진행처럼 다시 선택하도록 유도하지 않는다.

## 상한과 검증

현재 가방 8/12/20과 전체 비전투 14를 제거하고 조사 보고서의 같은 목적 cut도 제거한다. 실제 관측 범위·소유권·게임 슬롯 수·실행 가능 조건·예산 cap·기록 보관 제한은 보존한다. 첫 fit을 자동 목적지로 확정하던 지점은 목적 슬롯 선택 단계에서 유효 대상을 모두 제공하도록 바꾼다.

실제 소스 연결 검사로 root→분류→물품→뒤로→다른 물품→조작→인자→leaf→몸 관측, 모든 단계 취소 무부작용, stale 응답/물품 변경/새 goal, 상자 inspect, 8/14 초과 접근, budget 제한을 확인한다. 대표 실제 모델 입력 문구와 각 호출 수를 기록한다. 오프라인 World/모델 응답 대체와 실게임/외부 모델의 한계는 구별한다. 최종 고정판 뒤 독립 검수·Unity·설치 없는 SDK export를 수행하며 공식 본/그래프 반영은 HEAD 판단이다.
