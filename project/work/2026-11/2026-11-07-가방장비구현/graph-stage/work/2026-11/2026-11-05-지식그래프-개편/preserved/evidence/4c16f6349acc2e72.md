# 행동 판단 연결 설계 (OpenAI Decisions)

작성일: 2026-11-03. 근거: [행동설계 v2](2026-11-03-jev-행동설계-v2.md)(Jev 자리 → OpenAI Decisions), [몸 기본 기술 구현](2026-11-03-몸-기본-기술-구현.md), 사용자 합의(11-03 "진행해": 후보 생성 → Decisions가 2~3초마다 하나 고름 → 몸 실행, 반사·호출 간격은 시험으로, 목표는 처음에 /ai 명령으로).

표시: **[확인]** 코드·문서·호출로 확인, **[추정]** 확인 전 판단.

## 1. Decisions 요청 형태

- `POST /v1/decisions`, `model: gpt-6-luna`(지원 모델은 이것뿐) **[확인: 공식 문서]**.
- 질문은 `choice` 하나: `{"type":"choice","name":"action","instructions":"...","choices":[{"value":"c1","description":"..."}, ...]}`. 응답 `answers[0].choice`(값 하나), `probabilities[]`, `confidence`. 답이 `type:"refusal"`일 수 있음 **[확인: 문서]**.
- 선택지 수 상한은 문서에 없음. 기본 15개 이하로 둔다. 문서 권장대로 "해당 없음"에 해당하는 선택(여기서는 `wait` 짧게 서 있기)을 항상 넣는다.
- 입력: 문자열 하나(상황 요약). 이미지·JSON 파트도 되지만 처음엔 문자열.
- 요금: 입력 100만 토큰당 $0.10, 출력 무료 **[확인: 문서]**. 한 번에 약 0.5~1천 토큰이면 호출당 약 $0.0001.
- 키: 환경 변수 `OPENAI_API_KEY`. 게임 프로세스에 없으면 사용자 환경 변수(레지스트리)에서 읽는다. 키는 로그·채팅·파일에 쓰지 않는다.

## 2. 모드에서 HTTP 호출이 되는가

- 이 모드는 `ModManifest.json`에 `skipSafetyChecks: true`, `accessesExtraAssemblies: true`로 이미 설치돼 있고 게임이 `safetyCheck=False`로 컴파일함 **[확인: Player.log, Loader.cs:365·450]**. 이 모드에서는 보안 검사 모드가 `EnsureLoad`라 API 제한이 없고, 시작 때 올라온 어셈블리 전부를 참조로 쓸 수 있다(Loader.cs:399-412).
- 게임 첫 화면에서 '확장 권한 모드' 안내가 뜰 수 있음(ModManager.cs:253). 따로 켤 옵션은 없다 **[추정]**.
- 호출은 `UnityWebRequest`(메인 스레드에서 만들고 `SendWebRequest` 후 매 틱 `isDone` 확인). 게임 스레드를 막지 않고 TLS는 Unity가 처리. 캐릭터당 요청 하나만 진행.

## 3. 목표 (호스트 채팅)

- `/ai goal <품목> <개수>`: 모으기. 품목 별칭: 흙→`WallDirtBlock`, 구리→`CopperOre`, 주석→`TinOre`, 나무→`Wood`, 또는 ObjectID 이름. 완료 = 목표 시작 뒤 가방 속 그 품목이 N개 늘어남(관찰로 판정).
- `/ai goal 탐험`: 아직 안 가 본 방향으로 이동·굴 파기. 끝 없음.
- `/ai goal 따라와`: 호스트 근처 유지.
- `/ai goal 없음` 또는 `/ai stop`: 목표 해제, 제자리. 호출 0.
- `/ai goal`: 현재 목표·진행·호출 수·비용 표시.
- 목표가 바뀔 때마다 수정 번호를 올린다.

## 4. 후보 만들기 (관찰 + 목표)

관찰은 `AIObservation.Take`(사람 화면 크기, 빛 미반영)만 쓴다. 숨은 정보 없음. 후보마다 `행동 id · 대상 · 지금 가능한 이유 · 아는 효과/모르는 것`을 설명에 적는다.

| 행동 | 대상 | 만드는 조건 | 실행 |
|---|---|---|---|
| mine | 보이는 벽 칸 | 옆에 설 칸이 있고 벽 데이터가 읽힘. 모으기 목표면 목표 품목이 나오는 벽 우선 4개 + 다른 벽 2개 | `MineSkill(칸)` |
| attack | 보이는 적 | 최대 3마리(가까운 순) | `AttackSkill(엔티티)` |
| pickup | 보이는 떨어진 아이템 | 최대 3개 | `GotoSkill(그 칸)` |
| explore | 시야 가장자리의 걸을 수 있는 칸 | 4방향 중 칸이 있는 것 | `GotoSkill` |
| follow | 호스트 | 목표가 따라와이고 4칸보다 멀 때 | `GotoSkill(호스트)` |
| wait | - | 항상 | 2초 서 있기 |
| continue | 진행 중 기술 | 기술이 진행 중일 때 | 그대로 둠 |

## 5. 언제 부르나

- 목표 없음 → 부르지 않음.
- 기술이 끝나거나(완료·실패·취소) 진행 중 기술이 없을 때 → 바로 부름.
- 기술 진행 중에는 정상 진행이면 부르지 않음. 판단 전제가 바뀌면 부름: 새 적이 시야에 들어옴, 내 체력이 직전 호출보다 15 이상 줄어듦. 이때도 직전 호출 뒤 최소 간격(기본 2.5초)을 지킨다.
- 분당 호출 상한(기본 30)을 넘지 않는다.

## 6. 늦은 응답·오래된 응답

- 응답 검사: 목표 수정 번호가 같은지, 고른 후보의 대상이 아직 유효한지(벽이 그대로 있음·적이 살아 있음·아이템이 있음), 응답 나이(요청 뒤 8초 이하). 하나라도 어긋나면 버리고 다시 부른다(로그 `DISCARD 이유`).
- 실패(HTTP 오류·시간 초과 10초·거절 답): 로그와 호스트에게 짧게 알리고 3초 뒤 다시 시도. 3번 연속 실패하면 목표를 멈추고 알린다.
- **반사**(사용자 결정: 응답이 늦을 때만, 응답이 오면 바로 끔): 요청 뒤 1.5초가 지나도 답이 없으면 반사 켬. 첫 반사는 최소한만: **진행 중 기술이 유효하면 계속, 없으면 제자리**. 응답이 도착하는 순간 끔(로그 `REFLEX on/off`).
- 전술 반사(체력 낮을 때 물러나기, 피하기, 먹기, 맞으면 반격)는 **사용자 결정 거리**로 남긴다.

## 7. 비용 지키기

- 호출마다 응답의 `usage.input_tokens`로 비용을 센다(캐시 할인 무시, 넉넉하게).
- 월 상한 기본 **$70**: 사용자 검토 상한 월 10만원을 1달러=1,430원 정도로 환산(가정, 환율에 따라 다름). 설정 파일 `AIPlayers/decisions-settings.json`의 `monthlyCapUsd`로 바꿈. 사용량은 `AIPlayers/decisions-usage.json`(월별 호출 수·토큰·추정 달러).
- 상한에 닿으면 호출을 멈추고 호스트에게 알리고 제자리.
- 크레딧 잔액은 API로 확인하지 않는다(별도).

## 8. 실행부와의 관계

- 판단부(`AIBrain`)는 기술을 시작·취소만 한다. 입력은 지금처럼 실행부(`AIBody.Tick`) 하나가 만든다.
- 시험 명령(`/ai mine` 등)을 손으로 쓰면 그 기술이 끝날 때까지 판단부는 기다린다(목표가 있으면 끝난 뒤 다시 판단).
- `/ai off`, 월드 나가기 → 진행 중 요청을 버리고 판단부 초기화.

## 9. 사용자 결정 거리 (구현은 최소안으로 진행)

1. 전술 반사의 내용(물러나기·피하기·먹기·반격)과 반사를 켜는 마감 시간(지금 1.5초).
2. 월 상한 금액(지금 $70 ≈ 10만원 가정).
3. 판단 결과를 호스트 채팅에 얼마나 보여 줄지(지금은 목표 시작·완료·실패와 기술 결과만).
