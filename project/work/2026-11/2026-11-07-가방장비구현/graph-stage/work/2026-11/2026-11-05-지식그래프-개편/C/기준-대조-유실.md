## 기준으로 쓰는 자료

| 자료 | 기준이 되는 범위 | 전환 | 권위 제한 |
|---|---|---|---|
| preserved/legacy/기획/제품코어.md | 정체성·유저·제공 가치·범위 | CORE-01 | 요약 사본. 결정 원문은 evidence에 보존한 context.md 및 후속 세션 기록 |
| 정책.md의 pol.* 60항목 | 사용자 결정·원칙·방향과 그 확정도 | 정책-기준.md에 절 본문 유지 | 확정/잠정/검토/대체 및 적용 시기 구별. 코드 확인으로 사용자 결정이 바뀌지 않음 |
| preserved/evidence + manifest.json | 인용의 실제 글·시점·주체 | evidence-index.json에 사본/줄/인용 | 해시가 같고 인용이 있다는 것이 현재 실행 확인은 아님 |
| agreement.md | 이번 작업 범위·기준 커밋·보존 조건 | 모든 C 문서의 전환 경계 | 제품 기획의 새로운 결정으로 쓰지 않음 |

## 대조만 하는 자료

| 자료 | 대조할 내용 | 새 문서 처리 |

| 미결.md | 미정 결정/사용자 확인/안 가본 출처/구현만 있음/가설 등의 종류와 닫는 법 | 미결-보존.md. 그 사유와 닫는 법을 보존 |
| 기존 graph.json | ID·class·옛 함수선·게임 특수 참조·자동 미결·근거 | 별도 legacy 조회 유지. 표준 간선으로 이름만 바꾸지 않음 |
| 과거 실게임 기록 | 그 빌드·월드·시각에서 실제 있었던 일 | 과거 관측으로만 인용. 기준 커밋 e82eb87 및 이번 관측과 다름 표시 |
| 진행 중 전투 단계2 기록 | 기준판 이후의 결정·실험·승인 상태 | 의도 기준/후속 시험의 별도 시점. e82eb87 구현 증거로 사용 금지 |

## 유실 위험과 방지

| 유실 위험 | 방지 방법 |
|---|---|
| F.*를 모두 표준 기능 또는 활동으로 바꿔 내부 능력이 유저 조작처럼 보임 | 36개 각각 classification·activityIds·contextActivityIds·빈 standardFunctionIds를 둠 |
| 선 밖 코드·자동 미결을 문서 미결로 덮음 | 전체 legacy ID 인벤토리와 기존 graph.json 보존. B의 도달 불가 검사를 새로 받아 별도 비교 |
| API/명령 하나와 사용자 능력 하나를 일대일로 가정 | 대응은 다대다 허용. 조작/입구 근거 없이 간선 생성 안 함 |
| 게임 참조 특수 간선의 뜻 상실 | 게임 노드/사건 간선 원형을 별도 보존. 표준 reference/read/write로 옮길 때는 B/D의 구체 근거 필요 |
| HEAD 판단을 사용자 정책으로 승격 | cand.*와 등급·class 유지. 후속 결정이 실제 있으면 그 인용과 시점을 별도 기록 |
| 대체·검토 정책을 활성 확정 정책으로 적재 | 본문 원형 보존 + 적용 차이 목록. `pol.single-ai-first`의 메타데이터 불일치도 숨기지 않음 |
| 실행 데이터·게임 데이터 그래프를 개발 그래프 재작성과 혼동 | 파일은 C/에만 작성. 게임 지식/경험 연결 ObjectID 의도만 유지 |
| 과거 확인한 선 서명 또는 로그를 현재 검증으로 오해 | 과거 상태/빌드 정보 유지. A/B 판본·이번 관측을 별도 필드로 추가 예정 |
| 존재하지 않는 화면·문구·요소를 그럴듯하게 만듦 | 화면/출력 예약 문서는 수집 계획만. 원문/그림·요소 번호 없음을 명시하고 적재 금지 |

| 새 문서 | 가져온 내용 | 원본에서 빠지거나 아직 채울 수 없는 것 |
|---|---|---|
