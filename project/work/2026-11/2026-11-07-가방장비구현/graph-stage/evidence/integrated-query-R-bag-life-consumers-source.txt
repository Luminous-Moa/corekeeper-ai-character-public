16: ## 서로 다른 탐색 계약에 대한 통합 판단
17: 
18: 생활의 [승인 명세](../2026-11-07-생활트리구현/03-spec.md)는 페이지를 오가며 모든 항목에 접근하는 커서와, 읽기 전용 탐색 중 held/queued 보존을 명시한다. 가방 트리 합의는 분류·보유 물품을 임의로 자르거나 페이지로 나누지 않고, 새 가방 선택보다 과거인 응답의 적용 권한을 만료하는 기준이다. 다음은 이 차이를 적용하는 HEAD의 통합 판단이며 새로운 사용자 원문 인용이 아니다.
19: 
20: - 가방 분류·물품·조작 목록은 무상한·무페이지로 유지한다. 전체 기본 후보14개 제한과 후보를 영구히 누락하던 생성 단계 숫자 자르기는 제거한다.
21: - 별도 승인된 생활 메뉴의 손실 없는 페이지 탐색은 보존한다. 이를 제거한 상한이라고 보고하지 않으며, 생활 항목도 결국 모두 접근 가능해야 한다.
22: - 생활의 읽기 전용 탐색 중 대기 선택 보존과 가방의 새 선택 권한 처리를 각 소비자에 맞게 보존한다. 어느 쪽도 유효한 현재 몸 동작·원래 부탁을 취소하지 않는다.
23: - 메뉴를 바꿀 때 다른 메뉴의 커서·토큰만 닫거나 무효화하고, 생활 진척·수량/Runs·현재 목표를 지우지 않는다. 이미 만료한 선택 응답을 복구하지 않는다.
24: - 일반 평면 가방 후보는 숨기되, 생활 트리에서 이미 대상·수량을 고른 명시 실행 binding은 보존한다. 두 승인된 흐름의 식별과 설명을 섞지 않는다.

9: ## 유지할 합의
10: 
11: - [가방·장비 트리 합의](tree-agreement.md): 인벤토리 → 실제 보유 분류 → 보유 물품 → 조작 → 필요한 인자 → 실행. 뒤로·전체 선택 취소, 임의 후보 개수 상한/페이지 제거, 원래 부탁과 유효 몸 동작 유지.
12: - [생활 트리 합의](../2026-11-07-생활트리구현/00-agreement.md): 작업 → 대상/재료 → 시설/구역 → 수량으로 필요한 수준만 탐색하고, AI가 정확한 대상·수량을 이미 알면 바로 실행할 수 있다. 탐색이 몸 동작을 취소하지 않고 작업 수량·조건·실제 결과를 구별한다.
13: - 두 트리는 서로 다른 승인된 소비자다. 생활의 완전히 지정된 실행을 무조건 인벤토리 루트부터 다시 고르게 하거나, 인벤토리의 분류·보유 물품 선택을 생활 준비 루틴으로 대신하지 않는다.
14: - 작업에 지정된 수량과 현장 후보 목록의 개수 상한은 서로 다르다. 요청 수량·권한·실행 가능성·실제 관측과 기존 호출 예산은 유지하면서, 현장 선택지 개수를 자르는 상한은 제거한다.
