# 가방·장비 대표 실게임 확인 준비

이 문서는 이전 flat판의 실행 준비를 보존한다. 사용자가 인벤토리의 물건부터 조작을 고르고 뒤로/전체 취소할 수 있는 트리 방향을 새로 요청했으므로, 아래 계획은 트리의 각 선택 단계와 추가 호출·지연 증거까지 갱신한 뒤 실행한다. 현재 flat판의 설치/패키징/추가 Unity는 보류다.

현재는 실행 계획이다. 설치·게임 실행·자동 조작과 외부 모델 호출을 수행하지 않았다. 기존 실게임 보류 해제와 설치 후보 확인 뒤 실행한다. 실제 사용 월드/캐릭터를 먼저 백업하고 다른 대화의 시험과 겹치지 않는다. user 직접플레이 중의 물품/슬롯 변경이나 게임 종료를 자동 수행하지 않는다.

## 실제 첫 흐름

1. 시험 캐릭터 가방에 새 CopperBreastArmor와 기존 흉갑, 곡괭이와 검이 존재하는 상태를 준비한다. 실제 슬롯/variation/aux/상태, 현재 활성 프리셋의 흉갑칸을 읽기 관측으로 기록한다. 기존 `/ai inv`는 현재 기술을 바꾸는 명령이므로 무부작용 조회로 사용하지 않는다. 자연스러운 게임 UI/로그와 새 inventory_actions 보고를 사용한다.
2. 사용자 자연어로 가진 새 흉갑을 입도록 부탁한다. 상위 응답의 equip/품목/slot/where → Decisions 후보 → 선택 → Swap 요청 → 양 슬롯 교환 → 현재 활성 착용칸의 실제 결과 → 다음 판단까지 같은 요청에서 잇는다.
3. 구 흉갑이 출발칸에 돌아왔는지, 물품 상태가 보존됐는지 확인한다. 완료 사실 뒤 후보가 구 흉갑을 다시 새 목표진척으로 착용하게 유도하지 않는지 본다. 단계 완료는 공통실행 finish_goal을 모델이 선택한다. 원래 부탁의 종료는 위쪽 LLM의 order=done이다.
4. 해제를 별도 선택하고 빈 일반칸으로 돌아오는지 본다. 가방 가득참과 활성 프리셋 전환은 첫 흐름 뒤의 실패시험으로 수행한다. 양 슬롯 교환만으로 현재 활성 착용을 증명하지 않는다.

고정 입력이 필요한 보조 시험 명령은 `/ai gemini goal equip CopperBreastArmor where=chest slot=<실제 출발칸>`과 `/ai gemini goal unequip none where=chest`다. 이는 자연어부터의 대표 흐름을 대신하지 않는다. 시험 명령을 쓰더라도 Decisions가 구체적 후보를 선택하고 몸이 정상 조작해야 한다.

## 이어지는 생활 흐름

- 명시 손선택: 검 두 자루 중 슬롯·variation을 구별해 하나를 hold하도록 한다. 다른 정상 검이 핫바 앞칸에 있어도 고른 검으로 공격·짧은공격이 실행되는지, 곡괭이 선택 뒤 그 곡괭이로 채굴되는지 실제 손물품과 타격입력을 확인한다. 선택 후 동일ID 다른variation/aux물품으로 해당칸이 바뀌면 다른 물품에 primary를 보내지 않는지 본다. 실제 EquippedObject가 늦게 갱신되는 동안에는 primary가 기다려야 한다.
- 부분 보관/보급: 자기 상자만 대상으로, 나무 총량을 관측한 뒤 keep=10 보관을 부탁하고 실제로10개가 남는지 본다. 이어 take Wood count=20을 계획해 출발 상자 감소·가방 증가·남은 요청량을 확인한다. 예비 검 보관/회수에서는 비중첩 amount를 개수로 잘못 읽거나 내구도를1로 바꾸지 않는지 확인한다. 지정상자 where는 보고에 나온 chest:x,y를 사용한다.
- 내려놓기: 명시한 물품/수량이 자기 현재 위치에 생성되고 출발칸에서 감소하는지 확인한다. 바닥 생성만으로 상대에게 전달됐다고 말하지 않는다.
- 전달: 보이는 수령자를 이름으로 지정한다. 실제 접근→자기 위치 DropItem→이번 바닥 엔티티→그 엔티티의 pickup.targetEntity→수령자의 같은 물품 증가를 연결한다. 타인 선점/가방 가득참/동시 같은품목 획득/귀속 불명은 성공으로 처리하지 않으며 자동 재전송하지 않는다. 드롭한 캐릭터 차단은 수령자 독점보장이 아니다.

최종 한 요청 흐름은 “자기 상자에서 필요한 물품·장비를 정한 만큼 꺼내기 → 선택한 장비로 교체 → 선택한 검으로 행동 → 남은 물품과 구 장비를 보관 → 원래 부탁 계속하기”다. 각 전환에 모델이 받은 후보와 선택, 몸의 요청·관측을 같은 실행 회차로 기록한다.

## 증거와 통과 조건

소스 전체커밋, 설치 산출물/입력 대응, 월드·캐릭터 백업, 실제 시작/종료 슬롯과 상태, 후보/선택/skill Facts/공통 완료 선택을 남긴다. source ID만 같은 물품이 모두 동일 개체라는 추정을 하지 않는다. 관측상 구별 가능한 variation/aux/slot/state를 대조하되 관측필드까지 완전히 같은 물품을 임의 UUID로 구별했다고 주장하지 않는다.

오프라인 helper/최소World 어댑터는 게임 소비자·실제 UI·드롭 타이밍을 실행하지 않는다. 이 문서의 실게임 확인이 끝나기 전 구현판을 실게임 완료로 기록하지 않는다.

## 설치 대상과 별도 시험 준비

실제 읽기 전용 사전 관측은 [runtime-preflight.json](runtime-preflight.json)에 남겼다. 설치 대상은 `C:/Program Files (x86)/Steam/steamapps/common/Core Keeper/CoreKeeper_Data/StreamingAssets/Mods/AIPlayerSpike`이며 관측 당시 파일 96개의 실제 해시를 보존했다. 정상 SDK BuildMod는 임의 exportPath에 manifest와 소스 스크립트를 내보낼 수 있으므로, 게임 Mods 경로를 쓰지 않는 세션 후보 폴더에 먼저 생성한 뒤 검토할 수 있다. 지금은 트리 전환 때문에 생성하지 않았다.

실게임 재개가 승인되면 최초 변경 직전에 현재 설치 폴더, LocalLow Core Keeper의 `AIPlayers`·`Steam` 저장 영역, Steam userdata의 이 게임 `1621690/remote` 저장 영역을 별도 시각의 `runtime-backup-before-<최종판>` 아래에 복사하고 해시를 확인한다. JSON에 탐지된 정확한 실제 경로를 기록했으며 아직 백업·설치·복원은 수행하지 않았다. 이미 존재하는 백업을 덮지 않는다.

기존 사용자 월드와 캐릭터는 시험 대상으로 삼지 않는다. 새 `BagEquipment-<최종판>` 월드와 `BagTest-<최종판>` 플레이어로 동일한 흉갑 두 개·검 두 개·곡괭이·나무·자기 상자를 준비한다. 이름의 `<최종판>`은 실제 승인된 트리 코드 커밋으로 정하며 이전 `1fc89b9`를 새 판으로 간주하지 않는다. 시험을 위해 사용자 월드/캐릭터를 삭제하거나 자동 종료하지 않는다. 설치 후보와 기존 설치 스냅샷이 달라지면 변경된 실제 대상을 먼저 다시 확인한다.
