# 가방·장비 구현 합의

최신 선택 방식은 [분류 기반 선택 트리 합의](tree-agreement.md)를 따른다. 아래 최초 합의의 평면 후보 방식은 변경됐으며, 기존 조작·관측·담당 경계는 유지한다.

2026-11-07. 사용자는 [계획안](../2026-11-07-가방장비-계획안.md)에 대해 “좋아. 그렇게 진행해.”라고 답해 구현 진행을 승인했다. 이 문서는 계획 수립 뒤의 구현 착수 합의이며 context.md를 변경하지 않는다.

- 결과: 가진 장비 장착·교체·해제 → 명시 선택한 도구·근접무기 유지 → 장비를 포함한 품목·상자·수량 지정 보관·꺼내기 → 실제 경로를 확인한 내려놓기·전달의 순서로 연결한다. 해제와 직접 전달은 실제 게임 소비 경로를 먼저 확인한다.
- 판단 주체: 위쪽 LLM이 목적·계획을, Decisions가 현재 구체적인 선택을 담당한다. 코드는 정상 게임 입력과 실제 결과 관측을 담당한다. 자동 최적 장비 정책을 추가하지 않는다.
- 공통 실행: [계약](../2026-11-07-공통실행자료/contract.md)의 제어 동작을 중복 구현하지 않고, 기존 요청·목표·진척과 선택을 보존한다.
- 경계: 자기 상자 접근 범위 유지. 원거리 공격·조준과 시설 제작·수리·강화는 다른 담당의 범위다. 삭제(trash), 자원 공유 정책 변경은 포함하지 않는다.
- 근거: [이번 사실 조사](../2026-11-07-가방장비-조사.md)의 최신 검수 그래프 및 현재 11eb461 구현을 출발점으로 한다. 검수된 정적 규칙과 실게임 성공을 구별한다.
- 작업 위치: 본 저장소의 기존 수정은 보존하고 C:/Dev/CoreKeeperModSDK-bag-equipment 격리 worktree / bag-equipment-20261107 Git 브랜치를 사용한다. 기존 동명의 경로·브랜치가 있으면 먼저 실제 상태를 확인한다.
- 검증: 영향받는 오프라인 회귀와 독립 검수, Unity 컴파일을 진행한다. 대표 실제 흐름은 가방 흉갑 선택→교체→착용·양 슬롯 관측→다음 판단, 이어 지정 무기/도구와 수량 이동, 마지막으로 자기 상자 보급→장비 교체→행동→보관→원래 부탁 계속하기다.
- 설치·실게임: 다른 작업 기록에 사용자 PC 사용을 위한 실게임 보류가 남아 있다. 해당 보류의 해제가 확인될 때까지 게임 실행·자동 조작·설치·기존 프로세스 종료는 하지 않는다. Unity 배치 컴파일은 허용된 기록이 있으므로 다른 Unity 작업과 겹치지 않게 조정한다. 검증 후보를 준비한 뒤 실제 설치/실게임 단계의 진행 가능 여부를 확인한다.

구현 결과, 독립 검수와 근거, 미확인 부분은 이 폴더에 남긴다. 정적 검증만으로 실게임 완료를 선언하지 않는다.
