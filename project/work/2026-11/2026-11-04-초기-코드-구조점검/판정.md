# 초기 코드 구조 점검 판정

2026-11-04. 사용자 요청은 현재 코드의 책임 집중과 얽힘을 확인하는 것이며, 이번에는 제품 코드를 수정하지 않았다.

## 결론

책임이 집중된 곳이 있다. 특히 행동 후보 생성과 실패 사유 표현의 결합은 앞으로 기능을 추가할 때 변경 부담을 키울 수 있다. 자연어 채팅을 추가하기 전에는 응답 파싱 경계도 보완할 가치가 있다. 전면 재작성보다는 아래 세 경계를 좁게 정리하는 편이 적절하다.

| 경계 | 관측과 영향 | 최소 정리 방향 | 시점 |
|---|---|---|---|
| 실패 결과와 표시 문구 | 사람이 읽는 실패 설명을 행동 재시도와 경험 분류에서 다시 해석한다. 설명을 고칠 때 학습·재시도 의미까지 함께 확인해야 한다. | 실패 종류와 필요한 조건을 명시적인 데이터로 전달하고, 설명 문장은 그 데이터에서 만든다. 기존 분류·재시도·기억 의미를 보존한다. | 다음 실패 처리·기억 정정 변경 전 우선 |
| 행동 후보 생성 | AIBrain.BuildCandidates에 제작 준비·탐험·전투·실패 제외·설명·정렬·재생성이 모인다. | 공통 상황 입력과 후보 결과를 정하고, 응집된 후보 생성 책임을 분리한다. 최종 선택지 조정과 정책 소유자는 분명히 유지한다. | 다음 큰 행동 종류 추가 전 |
| 브리지 응답 읽기 | 수동 문자열 파서가 JSON의 따옴표 이스케이프와 중첩 필드를 올바르게 처리하지 않는 사례가 격리 재현됐다. 자유로운 자연어가 들어가면 제약이 두드러진다. | JSON 디코딩·답 형식 검증과 목표 적용을 구분한다. 런타임에서 쓸 수 있는 파서를 확인하고 기존 응답 계약을 보존한다. | 채팅·자연어 지시 연결 전 |

위 방향은 구조 제안이며 구현 승인을 의미하지 않는다. 후보 순서·개수 제한·전투 전환·재시도 조건을 바꾸는 것은 별도의 동작 변경이다.

## 파일 길이와 상태 소유권

조사 시작 시 메인 a03192d의 C# 모드 소스는 14개, 15,258줄(주석·빈 줄 포함)이었다. AIDecisions 2,804줄, AIBodySkills 2,286줄, AIPlayerSpikeMod 2,084줄로 세 파일에 약 47%가 모였다. 조사 도중 메인에 039d8b5가 반영되어 앞 두 파일은 각각 2,992줄·2,480줄이 됐다. 숫자는 집중 위치를 찾는 보조 근거이며 분리 필요성 자체의 증거가 아니다.

캐릭터별 상태는 AIAgent.Cur와 Slots를 통해 선택된다. 진입 시 Enter 범위와 Tick 폴링으로 현재 소유자를 지정하고 있어, 이번 점검으로 캐릭터 간 상태 혼선이 발생한다고 결론내리지 않는다. 향후 비동기 채팅·콜백을 연결할 때는 캐릭터 소유자를 명시해서 전달할 경계가 필요하다. 현재 전역 접근 형태를 전부 바꾸는 작업은 우선순위가 낮다.

## 이미 분리된 부분

농사·요리·기지·전투·경험 기록은 별도 모듈이 있다. 기억 검색 작업은 memgraph, recall-loop, bridge, replay로 역할을 나눴다. 몸·접속 파일 안에 여러 형식과 기능이 함께 있는 것은 가독성 정리 후보이지만, 파일을 옮기는 것만으로 상태 소유권이나 변경 부담이 해소되지는 않는다.

기존 브리지의 연결 종료 시 전체 CLI 종료 문제는 recall 작업에서 멤버별 종료로 수정 중인 범위다. 이를 신규 미해결 구조 과제로 중복 권고하지 않는다. recallSummary의 단어 제거 코드가 수동 파서 때문에 반드시 필요하다는 주장은 독립 검증에서 근거가 부족해 결론에서 제외했다.
