# AI 전용 캐릭터 — 구현·실게임 확인 (2026-11-03)

합의: Claude는 호스트 캐릭터 복사본이 아니라 자기 캐릭터 정보로 들어온다. 시작 상태는 새 캐릭터와 같고, 외형은 호스트와 구분되며, 시험은 Claude 하나로 한다.

## 결과 요약

| 확인 | 결과 | 근거 |
|---|---|---|
| 1. 새 캐릭터 시작(호스트 아이템 아님) | 통과 | 첫 접속 때 `Claude.json` 새로 생성(역할 Explorer, 시작 스킬 Running lv3, 1번 칸 SmallLantern x1, 2번 칸 FoodRation x3). 서버가 받은 호스트 정보(guid 0812ee8d…)를 AI 정보(guid c1a0de…a001)로 바꿈. 3번 확인에서 Claude만 Wood를 가진 채 다시 들어와, 호스트 복사본이 아님을 확인 |
| 2. 외형이 호스트와 다름 | 통과 | 스크린샷: 호스트는 파란 머리, Claude는 적갈색 머리·분홍 눈 |
| 3. 저장·재접속 유지, 호스트 복제 없음 | 통과 | Claude 칸 3에 Wood x7 넣음(시험 전용) → 나갈 때 저장 → 다시 들어오니 Claude 서버 가방에 Wood x7 있음, 호스트 가방은 시작 아이템 2개 그대로 |

STEP 1~3(접속·이름·이동)도 세 번의 접속 모두 그대로 통과했다.

## 바꾼 것

파일: `C:\Dev\CoreKeeperModSDK\Assets\AIPlayerSpike\Scripts\AIPlayerSpikeMod.cs` (설치본: 게임 폴더 `CoreKeeper_Data\StreamingAssets\Mods\AIPlayerSpike\`, 헤드리스 `HeadlessSdk.BuildAndInstall`로 설치).

- **AI 캐릭터 파일:** `%USERPROFILE%\AppData\LocalLow\Pugstorm\Core Keeper\AIPlayers\Claude.json` (Application.persistentDataPath 아래). 게임의 캐릭터 슬롯(saves/*.json)은 건드리지 않는다. 형식은 게임과 같은 `CharacterData` JSON(JsonUtility).
- **불러오기:** thin 월드를 만들기 직전에 파일을 읽거나(없으면 새로 만듦) 준비한다. 준비 실패 시 접속하지 않는다(호스트 복사본으로 들어가지 않게). 서버의 `SaveManager.GetCharacterDataFromSerialized` 후처리에서, 창이 열려 있는 동안 한 번만, 결과를 AI 캐릭터 정보의 새 복사본으로 바꾼다. 바뀌지 않은 채 생성되면 오류 로그.
- **새 캐릭터 만들기:** `SaveManager._ClearCharacter` 기본값(version 16, maxHealth 100, 빈 목록들)과, 게임이 캐릭터 첫 접속 때 주는 것(역할 시작 스킬 lv3 — Nomad 제외, 역할 시작 아이템 1번 칸부터)을 그대로 따른다. 역할은 새 캐릭터 메뉴의 기본값인 역할표 0번 = **Explorer**. 비내구 아이템은 게임처럼 amount=initialAmount. DLC·앱 추가 시작 아이템과 이름 이스터에그는 주지 않는다. serverConnectCount=1(시작 아이템 지급 완료 표시).
- **외형:** 게임의 외형 표(`Manager.saves.playerCustomizationTable`)에서 몸·피부·머리·머리색·눈색·셔츠색·바지색을 각각 호스트 현재 선택에서 목록 절반만큼 떨어진 항목으로 고른다(결정적). 처음 만들 때만 정하고 파일에 남는다. 이름 Claude, 장비 외형 비움.
- **저장:** 서버의 AI 플레이어 엔티티에서 가방(물건·모드 아이템 이름·보조 데이터), 스킬, 상태효과, 잠금 칸, 코인, 체력/최대체력, 영혼을 읽어 파일에 쓴다. 60초마다, 그리고 thin 월드를 정리하기 직전(월드 나갈 때)에. lastActiveSession은 비워 두어 재접속 때 항상 파일에서 가방을 다시 읽게 한다. 탤런트 배분·발견 목록·바이옴·튜토리얼은 서버에 없어 파일 값을 유지.
- **로그:** `[AIPlayerSpike] AI character: …` (생성/불러오기/교체/서버 가방 요약/저장).
- **시험 전용 장치:** `AIPlayers\Claude.testgive`에 `ObjectID이름 수량`이 있으면 AI 첫 빈칸에 한 번 넣고 파일을 지운다(로그에 TEST-ONLY 표시). 일반 동작에는 영향 없음. 남겨 둘지 지울지는 다음 구현 때 결정.

컴파일: `C:\Dev\_scratch\AIPlayerSpikeCheck` 빠른 컴파일 오류 0, 게임 안 컴파일 `Successfully compiled AIPlayerSpike`.

## 지시와 다른 점·확인 못 한 것

- **새 월드 대신 기존 버릴 월드 "ai" 사용.** 오늘 앞선 STEP1~3 시험용으로 사용자가 만든 월드다. 처음 들어갈 때는 세계 목록에서 마우스 휠을 굴린 직후 이 월드가 로드됐다(명시적으로 고른 것이 아님). 기존 월드라 이전 시험의 AI 엔티티(호스트 복사본 가방)가 남아 있었지만, 이번 접속은 모두 파일 내용으로 가방이 다시 채워졌다.
- **확인 1 단독으로는 구분이 약함:** 호스트 캐릭터도 오늘 만든 새 Explorer라 시작 아이템이 같다. 그래서 "호스트 복사본이 아님"은 교체 로그와 확인 3(Claude만 Wood 보유)으로 판정했다.
- **아이템 넣기는 실제 줍기가 아니라 시험 전용 서버 삽입.** 실제 줍기·제작으로 바뀐 가방의 저장은 같은 저장 경로를 타지만 실게임으로는 보지 않았다.
- **체력:** 첫 저장 75/75, 이후 100/100. 원인은 확인하지 않았다(첫 저장 시점의 최대체력 계산으로 추정). 재접속 때 체력은 파일 값을 쓰지 않는다(lastActiveSession을 비웠기 때문).
- **화면 조작 중 사용자 창에 한 번 잘못 클릭:** 사용자가 PC를 쓰는 중이라 게임 창 위에 사용자의 터미널(Codex)이 올라와 있었고, 캐릭터 선택용 클릭 한 번이 그 터미널 창에 들어갔다(키 입력은 없음). 이후로는 게임이 맨 앞일 때만 클릭하도록 바꿨다.

## 남은 문제

- **재접속마다 서버에 새 AI 플레이어 엔티티가 생김:** thin 월드 이름이 접속마다 바뀌어(playerGuid …1d → …2d → …3d) 게임이 매번 다른 플레이어로 본다. 가방은 파일로 이어지지만, 월드 저장에 꺼진 AI 엔티티가 쌓이고 위치가 이어지지 않는다. playerGuid를 고정하는 방법이 필요하다.
- **교체 조건:** "창이 열린 동안 첫 번째 캐릭터 정보"만 바꾼다. 그 짧은 순간(약 0.5초)에 실제 다른 사람이 접속하면 그 사람이 바뀔 수 있다. 여러 AI·멀티플레이로 넓힐 때 guid 기준으로 좁혀야 한다.
- 모드는 여전히 게임 폴더에 설치돼 있어 모든 호스팅 월드에서 Claude가 들어온다(이제 호스트 아이템 복제는 없음). Claude의 가방은 월드와 상관없이 `Claude.json` 하나를 공유한다.
- 게임은 월드 "ai"에 들어간 채 켜 두었다. 게임 폴더에 임시 파일은 남기지 않았다(`steam_appid.txt` 없음 확인).
