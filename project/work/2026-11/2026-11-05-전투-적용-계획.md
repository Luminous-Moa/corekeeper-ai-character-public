# 전투 개선 계획 적용 방식과 사용자 결정

2026-11-05. 계획 문서이며 구현·실게임 착수가 아니다. 원 계획: [전투 개선 계획](2026-11-04-전투-개선-계획/2-개선계획.md)(단계 0~5, 독립 검토 통과). 리팩토링: [리팩토링 계획](2026-11-04-리팩토링/2-계획.md)(S0~S8).

## 사용자 결정 (2026-11-05)

1. **성공 기준에 결과 기준을 더한다.** 정상 장비로 버섯 야수를 1:1로 잡을 수 있어야 한다(사람에게도, 코드로 짜도 어렵지 않은 몬스터라는 판단). 판단 적합성·선택과 실행 일치 기준은 그대로 함께 본다. 원 계획과 `pol.combat-fit-criterion`의 "처치·쓰러짐은 참고만"을 이 범위에서 바꾼다.
2. **전조에 따라 코드가 스스로 피하는 동작은 넣지 않는다.** 무조건적 회피가 될 수 있는 코드(늘 켜진 회피 반사, 후보에 붙인 "전조 오면 피함" 반응 방식 모두)는 지양한다. 한때 정한 안 C(반응 방식은 모델, 타이밍은 코드)는 **취소**.
3. **대신 관측과 방향·거리별 이동 후보를 주고 모델이 직접 고른다.** 근거: 모델 응답 약 0.3초는 사람 반응 수준이라 충분히 반응할 수 있다고 본다. 도저히 안 되면 그때 방향을 다시 정한다(사용자 결정 사항).
4. **복합 행동 후보는 반드시 넣는다**(2026-11-05 사용자 결정으로 "단일 행동으로 안 될 때만" 조건을 없앰). 한 번 치기→이동, 접근→한 번 치기, 짧은 이동→한 번 치기 등 고정 순서. 이유: 공격과 이동 사이 판단 왕복 지연 — 사람은 치고 바로 움직인다. 순서 안에 "전조 오면 피함" 같은 분기는 넣지 않는다(결정 2). 모델의 새 선택은 언제든 끼어들 수 있다.

## 설계 (단계 2 구체화)

### 관측 — 판단마다
- 적(화면 안, 개체별): 상태(대기·이동·공격 준비(전조)·돌진 중·공격 뒤 회복·기절)와 그 상태 경과 시간, 바라보는/돌진 방향과 내가 돌진 선 위인지, 거리, 체력.
- 나: 체력, 무기 사거리, 지금 휘두를 수 있는지(남은 쿨다운), 지금 동작.
- 주변: 적 기준 각 방향 열린 칸 수, 내 뒤 벽까지 거리.
- 관측 시각. 오래된 정보는 오래됐다고 표시.

### 후보 — 강한 적 근접전일 때
| 후보 | 내용 |
|---|---|
| 짧은 이동 ×6 | 적 기준 다가가기·멀어지기·왼쪽·오른쪽·왼쪽 뒤·오른쪽 뒤, 1칸 |
| 긴 이동 ×3 | 멀어지기·왼쪽 뒤·오른쪽 뒤, 2~3칸 |
| 한 번 치기 | 사거리 안일 때만 |
| 사거리까지 접근 | |
| 제자리 유지 | |
| 먹기·이탈 | 기존·단계 3 |

- 방향은 적 기준이라 적이 움직여도 키가 안정된다. 갈 수 없는 칸·도착지가 같은 후보만 뺀다. 위험하다는 이유로 빼지 않는다.
- 이동 후보마다: 도착까지 시간, 각 적과 거리 변화, 돌진 선·공격 범위 통과 여부, 도착지 뒤 벽, 막다른 곳 여부.
- 칸 수(1, 2~3)는 단계 0의 이동 속도·돌진 거리로 정한다.

### 실행 약속
- 이동: 목적지 도착 또는 막힘에서 끝나고 즉시 다음 판단. 이동 중 새 선택은 바로 바꾼다.
- 한 번 치기: 휘두르기 1회로 끝. 휘두르기 중 전환은 게임이 취소를 허용하는 시점에서(단계 0 확인).
- 코드는 모델이 고른 것만 실행한다.

### 지연 경로 — 전조 시작→이동 시작을 사람 수준(약 0.3초대)으로
- 전조 시작을 긴급 계기로: 진행 중 요청을 끊고 새 관측으로 바로 다시 묻는다(캐릭터당 요청 하나 유지, 끊은 만큼 비용 조금 증가). 안 하면 전조를 못 본 답을 한 번 더 기다려 최악 두 배.
- 이동 선택은 동작 경계를 기다리지 않고 바로 적용.
- 전조 시작→이동 시작 p50/p95를 잰다. 크게 늦으면 그대로 보고하고 방향을 다시 정한다.

### 단계 0에서 잴 것
- 전조·돌진·기절 상태를 게임 데이터에서 읽을 수 있는지.
- 전조 길이, 돌진 속도·거리, 기절 시간과 어떤 벽에서 되는지(놓은 블록 포함). 돌진 기절은 사용자 제공 정보라 확인 전에는 모델에 확정 사실로 주지 않는다.
- 내 이동 속도(칸/초), 휘두르기 취소 가능 구간.
- 코드만으로 잡는 기준 실행: 지금 장비로 잡을 수 있는지(장비 부족과 컨트롤 부족 분리). 시험용이며 제품 동작으로 쓰지 않는다.

### 단계 2 시험
- 시험장, 1:1, 정상 목검, 같은 조건 반복.
- 처치 여부, 맞은 횟수, 전조 때 고른 방향·거리 분포, 전조→이동 지연, 기절 중 공격 여부.
- 돌진 기절 정보 있음/없음 비교(관측·후보 사실과 함께 줄 때).

### 다수 적 (사용자 동의 2026-11-05, 단계 5에서 넓힘)
1. 이동 방향 기준은 집중 대상: 모델이 마지막으로 치기·접근을 고른 적, 없으면 전조·돌진 중인 적, 그다음 가장 가까운 적(거리·상태 사실로만 정함, 코드가 위협도를 판단하지 않음). 이동 후보의 사실(거리 변화, 공격 범위·돌진 선 통과)은 보이는 적 전부에 대해 계산.
2. 관측은 같은 종류도 개체별. 전조·돌진 중·가까운 순으로 약 5마리 자세히, 나머지는 수 요약.
3. 한 번 치기·접근 후보를 적마다(대상 3마리까지). 대상 바꾸기도 모델 선택.
4. 긴급 계기: 어느 적이든 나를 향한 전조 시작, 또는 내가 돌진 선 위에 서게 됨.
5. 동료: 위치, 상대 중인 적, 이동 경로에 동료가 있는지를 사실로.
6. 단계 3 이탈 후보도 보이는 적 전부 기준.
- 다수 적이면 후보가 20개 안팎이라 위 상한 확대가 필요하다.
- 순서: 1:1 버섯 야수 통과 → 2마리 → 강한 적+약한 적 → 동료와 함께.

## 사전조사 반영 (2026-11-05)

- **후보 사실 두 가지를 더한다(모델 판단을 크게 바꿈):**

  - 예상 결과: 이동 후보마다 "예상(가정 명시): 돌진이 벽에 부딪혀 약 N초 취약 / 부딪힐 것 없음". 없으면 벽 유도 0/24·벽 등진 자리 1/12, 있으면 18/24·10/12. 예측이므로 가정을 문구에 드러내고, 단계 2에서 예측과 실제 결과를 대조해 기록한다.
- **기록 줄 표현:** "쓰러짐 2번", "받은 피해 54/번" 같은 줄이 근접전 판단을 물러나기로 쏠리게 했다(빼면 5/12 → 12/12). 단계 1에서 근접전 입력의 기록 줄 표현을 다시 본다(지우는 것이 아니라 지금 판단에 필요한 형태로).
- **지연:** 긴급(전조) 때는 진행 중 요청 끊기·즉시 적용에 더해 0.25초 호출 바닥도 우회한다. 개선 후 추정 p50 약 0.36~0.41초·p95 약 0.57~0.62초.
- **후보 순서:** 같은 값의 좌우 후보는 먼저 나온 쪽이 뽑힌다. 순서를 고정하고, 좌우를 가르는 사실(열린 칸, 예상 결과)이 있으면 그것이 결정하게 한다.

## 단계 0 결과 반영 (2026-11-05)

근거: [기준 기록](2026-11-05-전투-기준기록/1-기준기록.md)(지금 AI 6/6 쓰러짐), [측정](2026-11-05-전투-단계0/2-측정.md)(돌진 49번), [탐침](2026-11-05-전투-단계0/1-탐침.md)(combat-s0 브랜치, 합치지 않음).

- **벽은 한 번 쓰면 사라진다:** 벽 옆 충돌 15/15가 반경 약 1.5칸 벽을 부숨(타일 피해 166). 벽 등진 자리 후보의 사실에 "부딪히면 이 벽은 부서짐"을 넣고, 블록 놓기 후보(단계 4~5)의 의미가 커진다. 놓은 블록 충돌은 아직 미측정.
