## 7. brief 제안 문구 (고치지 않음 — 자연어-명령과 겹침)

`## 기억 찾아보기`의 game op 줄을 이렇게 바꾸면 목차 없이(noindex)도 알 수 있다:

```
- game op: how(얻는 법)·uses(쓰임)·station(제작대 목록)·find(이름), target → {{name}}가 본 범위의 게임 지식. op rule(게임 규칙: 적이 생기는 바닥·기지 안전·적의 길·벽 부수기·방어물 재료), target은 낱말(예: "스폰 바닥", "문") → 누구나 아는 게임 규칙과 그 확인 수준
```

그리고 그 절 끝의 "결과는 {{name}} 자신의 기록과 본 게임 지식뿐이다." 뒤에 "게임 규칙은 예외로 누구나 아는 지식이며, [추정]·[사용자] 줄은 확정 사실이 아니다."를 더하는 것을 제안한다. 실제 LLM 시험에서는 이 문구 없이도 rule 질의를 골랐다(목차 줄 덕분, 1회 시험).

## 8. 남은 것

- 코어 면역 구역 넓이, 어떤 블록이 물 위에 놓이는지 → 단계 1 실측 또는 kgdump에 `ImmunityZoneCD`·놓기 표시(`PlacementCD.canPlaceOnWater`) 뽑기 추가.
- 실측으로 확인되면 rules.json의 level을 올리고(예: user+game → game) 다시 만든다.
- 규칙 줄이 길어 질의 3개를 한꺼번에 하면 각 질의의 뒷줄이 잘린다. 문제가 되면 규칙 text를 줄이거나 rule 결과 수를 줄인다.
- `kg.mjs`를 `node -e`로 import하면 명령줄 판정(`pathToFileURL(process.argv[1])`)에서 오류가 난다(전부터 있던 것, 파일 스크립트로는 문제 없음).
