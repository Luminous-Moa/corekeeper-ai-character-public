## 2. 항목별 근거

### 2.1 로그 값
- **N:** `CHAT-UI: N = …` 줄이 판 내내 한 번도 없다. 설정을 읽을 때마다 `line scale 1.000, N not measured yet`이다. `N not measurable` 줄(카메라 없음)도 없다. 그래서 카메라는 찾았지만 측정값이 정수 ±0.02에 들지 못한 것으로 본다. 측정값 자체는 로그에 없다(정할 때만 찍힘).
- **고른 m/N:** 없음. 줄 배율은 1.000이다.
- **font metrics(t=68.1):**
  ```
  default thinSmall: pixel font FontKorean charDims 15x15 lineSpacing -2 ppu 16 -> 13 dots per line, latin Font8L 10 dots, …, '채팅 시험 Luminous' uses pixel font FontKorean;
  set thinTiny: pixel font FontKorean charDims 15x15 lineSpacing -2 ppu 16 -> 13 dots per line, latin Font5 10 dots, …, '채팅 시험 Luminous' uses pixel font FontKorean; ratio 1.000
  ```
  - thinTiny 줄 높이 비율은 **1.000**이다.
  - 한글은 **픽셀 글꼴(FontKorean)**로 그려진다. 동적 글꼴로 넘어가지 않는다.
- **line font:**
  - `thinTiny (pixel font FontKorean), line scale 1.000: 0.9375 units per text line (1 line(s), 'Luminous: /ai all on')`
  - `thinSmall (pixel font FontKorean), line scale 1.000: 0.8542 units per text line (3 line(s), …)`
  - N이 없어 'px on screen' 값은 찍히지 않았다.
- **first line dropped:** `at local y 10.25 (limit 10.00); messages kept now 4 incl. the new one (line scale 1.000)`
- **diag(t=74.9):** 1판과 달리 배율이 0이 아닐 때 찍혔다.
  - messageTextParent localScale·lossyScale (1,1,1)
  - `N not measured`, line scale 1.000, font thinTiny, outputMask none
  - inputField `under messageTextParent True lossyScale (1,1,1)`, inputFieldPrompt `lossyScale (1,1,1)`
  - 프리팹은 모두 scale 1.000, overrides 0, maxWidth 8.5, thinSmall, fadeOutTime 4(일부 12)
  - diag는 'N이 정해진 뒤(최대 약 600프레임)' 찍는데, 이번에는 N 없이 기다리는 시간이 끝나 찍혔다.

## 4. 의견 (사실 바탕)
- **읽기 좋음:** 셋 다 원래 글꼴과 원래 크기라 1판 전과 똑같이 또렷하다. 다만 나)는 §3 때문에 채운 줄이 보이지 않는 일이 두 번 있었다.

  - thinTiny는 한글 설정에서 효과가 없다(ratio 1.000, 영문 줄도 FontKorean).
  - 정수 배율은 이 화면(점 하나 약 5.85px)에서 N을 정하지 못해 켜지지 않는다.
- 그래서 이 2800×1752 화면에서 0.5배를 얻으려면 정수 N을 전제하지 않는 방법이 필요해 보인다. 하지만 1판에서 보았듯 비정수 배율(0.7)은 글자를 깨뜨렸다. 0.5배를 이 화면에서 어떻게 그릴지는 HEAD와 사용자가 정할 일이다. 해상도를 바꾸는 시험은 시스템 상태를 바꾸는 일이라 하지 않았다.
