# Xevn 실행 조건·코드 확인

확인일: 2026-11-03. 공개 문서와 작은 코드 파일만 읽었다. 가중치 다운로드·패키지 설치·추론·GPU 실측은 수행하지 않았다. 대상 환경은 부모 조사에서 확인한 Windows, RTX 5080 16303MiB, 시스템 RAM 약32GB다.

## 판정

**로컬 한국어 판단 모델의 실험 후보로 타당하다. 공식 CUDA/Transformers 및 CUDA/GGUF 경로가 있으므로 Apple 전용 모델은 아니다. 하지만 현재PC에서의 지연·최대 메모리·게임 동시 실행은 미검증이다.** 현재 채택된 OpenAI Decisions를 바로 교체할 근거는 아니며, 같은 게임 상태·후보에 대한 비교 대상으로 두는 것이 적절하다.

## 실행 경로와 메모리

- 실제 원본 모델은 [quevirus/Xevn-4B](https://huggingface.co/quevirus/Xevn-4B)다. 모델 카드는 PyTorch와 `transformers>=5.2.0`, 전용 `xevn_infer.py`를 사용하고 NVIDIA에는 `device="cuda"`를 지정한다. 카드의 Transformers 파일 크기는9.3GB이며 멀티모달 가중치 구성을 보존하지만 helper의 추론은 텍스트만 사용한다. 원래 Qwen3.5-4B 기반, 한국어 중심이고 `choice`·`noul`·`score`를 처리한다. HF 자동 생성 pipeline 예시보다 모델 제작자의 전용 helper가 이 모델의 판단 방식을 정확히 나타낸다.
- [GGUF 모델 카드](https://huggingface.co/quevirus/Xevn-4B-GGUF)는 `llama-cpp-python>=0.3.36`을 요구한다. CUDA로 빌드된 backend와 전용 `xevn_gguf.py`·`xevn_infer.py`·`temps.json`을 사용한다. 공식 기본 추천은Q8_0, 파일4.61GB. Q6_K3.56GB, Q5_K_M3.16GB, Q4_K_M2.78GB도 있다. 이는 저장 파일 크기이며 실행 VRAM은 캐시·작업 버퍼·CUDA 런타임 등을 더 고려해야 한다. Windows RTX5080의 실제 사용량은 공개되지 않았다.
- GGUF 카드의 양자화 확인은40문항에서16비트 모델과 최상위 답이 일치한 수다(Q8_0 38/40 등). 이는40문항 정답률이나 전체 한국어 벤치 재평가가 아니다. MLX 4~8비트의 품질 유지 결과를 GGUF에 그대로 적용할 수 없다.
- **Ollama는 명시적으로 미지원**이다. prompt logits을 읽는 전용 방식이 필요하기 때문이다. HF 화면의 자동 생성 Ollama/일반 chat 실행 안내와 제작자 본문이 충돌할 때 제작자 본문을 따른다. GGUF 파일 존재만으로 모든 OpenAI-compatible 서버에서 Decisions API가 제공된다는 뜻도 아니다.

## helper 코드가 실제 하는 일

[PyTorch helper](https://huggingface.co/quevirus/Xevn-4B/blob/main/xevn_infer.py)를 직접 읽었다.

- 상태·질문·후보를 텍스트로 이어 붙여 한 번 인코딩하고, 마지막 위치의 A~Z 후보 토큰 logits만 읽어 확률을 만든다. 자유로운 설명·행동 코드를 생성하지 않는다.
- `choice`는2~26선택지, `score`는2~10단계다. 최고 확률의 후보를 반환하는 결정적 선택이며, 반환 확률로 다양하게 행동하려면 호출자 쪽 샘플링 정책이 따로 필요하다.
- 여러 질문을 넣으면 comprehension으로 순차 처리한다. **요청 하나에 forward 한 번이 아니라 질문마다 한 번**이다. PyTorch 추론은 `use_cache=False`이고 상태를 질문마다 다시 읽는다.
- 타입별 온도 기본값은choice1.1, noul1.2, score1.2다. 특히 `noul`의 yes 확률이0.2~0.8 사이면0.5를 기준으로0.2 또는0.8로 강제 이동시킨다. 예컨대0.51은0.8이 된다. 따라서 반환된0.8을 실제 성공 가능성80%나 충분한 확신으로 곧바로 사용하면 안 된다. 이는 후보 선택과 별개로 안전 임계값·LLM 재판단 조건에 영향을 준다.

[GGUF helper](https://huggingface.co/quevirus/Xevn-4B-GGUF/blob/main/xevn_gguf.py)도 직접 읽었다. 기본은`n_ctx=8192`, `n_gpu_layers=-1`, `n_batch=n_ctx`, `n_ubatch=512`이고 마지막 logits을 직접 읽는다. 매 질문 `reset()`을 호출하므로 공유 상태 prefix cache를 사용하지 않는다. 질문별 반복 비용을 계산해야 한다. Python 클래스/CLI는 제공되지만 이 helper 자체가 HTTP API 서버인 것은 아니다.

## 입력 길이와 속도

[config.json](https://huggingface.co/quevirus/Xevn-4B/blob/main/config.json)의 `max_position_embeddings`는262144다. 그러나 이 설정값은 판단 학습/장문 정확도 보증이 아니며, PyTorch helper에는 별도의 안전한 입력 길이 검증·절단 정책이 없다. GGUF의 실제 기본 context는8192이므로 이를 구분한다.

제작자의 [속도 표](https://github.com/Nhahan/Xevn)는 Apple M4 Max, MLX, bf16, HTTP, 3000요청 조건이다. 원본 HF 카드에서 질문은요청당1개임을 명시한다.64토큰 이하 p50/p95 56/64ms,65~128토큰88/103ms,129~256토큰156/188ms다. 게임 상태·목표·기억·후보 설명을 넣어 수천토큰이 되거나 질문을 여러 개 넣으면 이 숫자를 그대로 쓸 수 없다. RTX5080의 GGUF/CUDA 성능과 게임 FPS 경합도 이 표로 예측할 수 없다.

## 라이선스와 재현성 경계

GitHub와 원본/양자화 모델 카드 모두 Apache2.0을 명시하며 원본 HF의 [LICENSE](https://huggingface.co/quevirus/Xevn-4B/blob/main/LICENSE)도 확인했다. 가중치는 공개돼 있지만 GitHub `main` 트리(확인SHA `6bddb66b4858f14e266714b12f00fb9892190929`)는 README·라이선스·시각자료·소개사이트로 구성된다. HF에는 추론 helper·가중치·설정이 있으나 검토 범위에서 전체 학습 과정과 자체 평가를 그대로 재현할 harness/원응답은 확인하지 못했다. 따라서 공개 가중치·추론 코드와 학습/평가 전체 공개를 구분한다.

자체 비교표의 **JevK5는 TypeSafe Jev1.14가 아니다.** [JevK5 공식 카드](https://github.com/allebee/jevk5/blob/main/MODEL_CARD.md)는 독립 Qwen 기반 대안이며 TypeSafe와 무관하다고 명시한다. Xevn 사이트의 비교 설명도4B이하 공개 모델이라고 되어 있다. 다른 열의 정확한 checkpoint/version까지 고정된 명세는 확인하지 못했으므로 `Decider`를 Perplexity 최신27B/Flash1.2로 임의 대응시키지 않는다.

## 프로젝트에 적용할 때의 판단

현재16GB급GPU에서는 Q8_0가 합리적인 첫 로컬 시험 후보지만 메모리 적합성과 응답속도는 실측 전 추정이다. 평가한다면 고정 상태에서 한국어 목표·성향·위험 판단과 후보순서 변형, 실제 game과 동시 실행한 p95·FPS·VRAM, 여러 질문 묶음 지연을 봐야 한다. `noul`의 후처리된 확률은 신뢰 임계값 설계에 그대로 쓰지 않는다. OpenAI 크레딧을 이미 쓸 수 있는 상황에서는 로컬 비용 절감만으로 이전을 정당화하기보다 한국어 선택 품질·네트워크 독립성의 실제 이득을 확인하는 것이 먼저다.
