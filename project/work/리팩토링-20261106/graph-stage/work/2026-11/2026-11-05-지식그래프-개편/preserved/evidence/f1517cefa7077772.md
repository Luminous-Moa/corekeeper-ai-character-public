## 바꾼 것

파일: `C:\Dev\CoreKeeperModSDK\Assets\AIPlayerSpike\Scripts\AIPlayerSpikeMod.cs`만(1431 → 1712줄, sha256 앞 12자 `553b3bf16b63`). 빠른 컴파일 오류 0, 게임 안 컴파일 성공("Successfully compiled AIPlayerSpike"), `HeadlessSdk.BuildAndInstall`로 설치, 설치본 해시 일치. 커밋 없음.

- **설정 파일:** `<persistentDataPath>\AIPlayers\<월드 ServerGuid>\settings.json` = `{"aiEnabled": true|false}`. 월드별 캐릭터 파일 옆. 없으면 꺼짐(기존 월드 포함 모든 월드의 기본값).
- **단계:** `Disabled`(이 월드에서 꺼짐, 명령 대기)를 더했다. 호스팅 월드에 들어가면 패치를 걸고(게임 실행당 한 번) 월드 ID를 읽어 설정이 켜짐이면 10초 뒤, 꺼짐이면 `Disabled`.
- **채팅 명령:** `NetworkCommSystem.SendChatMessage`에 prefix 패치(`AIPlayerSpikePatches.ChatSendPrefix`). 게임은 "<이름>: <글>"로 보낸다. 글이 `/ai`, `/ai on|off|status`(한글 `켜기|끄기|상태`도)면 처리하고 보내지 않는다. 호스팅 중이 아니면(남의 월드에 들어간 경우) 손대지 않고 그대로 보낸다.
  - `on`: 설정 저장 → 3초 뒤 들어옴. 이미 켜져 있으면 알려 준다.
  - `off`: 설정 저장 → 서버에서 AI 연결에 `NetworkStreamRequestDisconnect` → AI 저장 → thin 월드 정리 → `Disabled`. 서버 쪽 끊기는 게임이 사람이 나갈 때처럼 엔티티를 끄게 하려는 것(thin 월드만 없애면 서버가 연결 시간 초과까지 Claude를 남겨 둔다).
  - 상태·도움말.
- **답:** 다음 프레임에 `ChatWindow.RenderText`(비공개, 리플렉션)로 호스트 화면에만 보인다. 게임 언어가 한국어라 한글로 쓴다.
- **호스트만:** 명령은 호스트 자기 프로세스의 보내기 단계에서 잡으므로 다른 플레이어가 친 `/ai`는 이 모드에 닿지 않는다(그냥 채팅으로 간다). 관리자(admin) 권한 플레이어 허용은 넣지 않았다.
- STEP1~3, 걷기 무늬, 시험용 `.testgive` 넣기는 그대로 두었다.
- 머리 주석의 "단일 AIPlayers/<name>.json" 설명을 월드별·켜기끄기로 고쳤다.

## 어긋남·주의

- **STEP 3이 세 번 모두 "FAILED"로 찍혔다(이동 자체는 됨).** ai2에서 Claude는 매번 (1.15, -3.3)에서 다시 나타난다. 오른쪽 벽에 붙은 자리라 첫 무늬 "오른쪽 3초" 동안 움직이지 못한다. 2.8초 판정에서 route A가 실패로 보고 route B로 바꾼 뒤 무늬를 처음부터 다시 시작하니, 또 오른쪽에서 막혀 FAILED가 된다. 그 뒤 왼쪽·원 무늬에서는 route B로 정상 이동했다(t=3.2s부터 위치 변화, 최대 6.34칸). 그래서 이번 실행에서 route A는 확인되지 않았다. 월드별 작업 보고서의 "3번째 접속 STEP 3 FAILED, 오른쪽 벽"과 같은 현상이다. 걷기 무늬와 판정은 지시대로 고치지 않았다.
- `/ai off` 직후 단계 로그가 `Walking -> Stopped -> Disabled`로 두 번 바뀐다(DisposeThinWorld가 Stopped로 바꾼 뒤 Disabled로 옮김). 동작에는 영향 없음.
- 채팅에 친 명령 줄("Luminous: /ai on")은 호스트 화면에 남는다(게임이 보낸 글을 직접 그린다). 다른 사람에게는 보내지 않는다.
- 이번엔 월드 ai2만 썼다. 월드 ai(c48cf4bb…)는 설정 파일이 없어 꺼짐이 기본이다(직접 들어가 보지는 않음).

## 남은 문제

- 관리자 권한 플레이어의 `/ai`는 지원하지 않는다(호스트만). 필요하면 서버 쪽 채팅 수신(NetworkChatServerSystem)에서 잡고 `ConnectionAdminLevelCD`로 거르는 방식이 있다.
- 다른 플레이어가 있는 상태(명령 비공개, 동시 접속 판정)는 실게임으로 못 봤다.
- 다른 플레이어가 화면에서 보내는 `/ai`는 일반 채팅으로 모두에게 보인다.
- STEP 3 판정이 벽 붙은 스폰 자리에서 실패로 찍히는 문제(위).
