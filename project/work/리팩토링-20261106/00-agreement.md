## 목적과 승인 범위

비효율적으로 흩어진 같은 규칙을 모으고, 한곳에 섞인 서로 다른 책임을 분리하여 이후 개발과 유지보수를 쉽게 만든다. 승인된 방향은 [계획](../2026-11/2026-11-06-리팩토링-현황과-계획/plan.md)이며, 당시 '제안/구현 미시작/현재 요청은 실게임 없음' 표기는 이 승인 전의 상태다.

전체 단계 0~5를 순차 수행한다. 첫 구현 묶음은 목표 계약과 후보 의미(0~2), 다음은 공간·이동 공통화와 혼합 책임·상태 정리(3~4), 마지막은 실제 대표 경로 검증과 지식그래프 반영이다. 사용자가 승인한 동작 불변의 구조 개선 범위에서 구현·격리 시험·독립 검수·실게임 검증을 진행한다. 기존 병합·push 승인 조건은 유지한다.

## 보존할 것

- 시작점 ai-character a07166f. 본 저장소의 SDK 설정·미추적 로컬 자료는 보존한다.
- 모델·프롬프트·후보 순서/상한·종료 순서·경로 비용/캐시·저장/보고/경험 계약을 유지한다.
- 기지 범위 통일, 설 칸 조건 강화, 농사 캐시 변경, 우회 탐색 확대, 물체 분류 결과 변경, 저장소 통합, 멘션 큐 전환은 별도 동작 결정이다.
- 이미 통합한 문·칸·누름·피해·기억 판정을 재사용한다. 단일 몸 입력 실행기를 보존한다.
- 모든 변경 책임에 기존 동작과 확인 방법을 연결한다. 검증 근거를 확보할 수 없는 책임은 이유와 함께 HEAD로 돌린다.

## 실행 방식

HEAD는 승인된 방향과 전체 결과를 판단한다. 명세 작성·구현·상세 독립 검수·실게임 확인은 별도 컨텍스트가 맡는다. 상세 명세를 HEAD가 검토한 뒤 코더에게 준다. 각 묶음은 별도 커밋·검증 단위로 유지한다. 시험 환경은 운영 자료와 구분하며 게임 사용 일정/설치본/월드 보존을 확인한 뒤 실게임을 진행한다.

작업 트리 예정: C:/Dev/CoreKeeperModSDK-refactor-20261106, Git 브랜치 refactor-maint-20261106. 변경 전 오프라인 관문은 직전 소스 조사에서 전체 통과(core 973). 사용자가 승인한 작업을 불필요하게 다시 승인 요청하지 않고, 실제 동작 선택 또는 최종 병합 결정만 구체 결과와 함께 돌린다.

## 화면 확인 환경 보충

사용자는 연결된 모니터가 없어 Computer Use 화면이 보이지 않을 수 있다고 알렸다. 그 경우 ADB 연결 상태인 태블릿에서 FoldRemote로 PC에 원격 연결하여 진행하도록 승인했다. 먼저 현재 캡처가 가능한지 확인하고, 필요한 경우에만 이 경로를 사용한다. 다른 프로젝트의 코드·권한·계정 설정 변경까지 승인한 것으로 확대하지 않는다.

후속 확인: 태블릿 영상은 보이지 않아도 되며, 테스트에 문제가 없으면 그대로 진행한다. Windows 캡처 확보 뒤 태블릿 영상 표시 자체의 디버깅은 작업 대상이 아니다. 실제 테스트에 필요한 입력만 확인한다.

## 마무리 범위 조정

실게임 검증 뒤 시험 월드 삭제 입력에 시간이 걸리자 사용자는 '시험월드 삭제 오래 걸리면 따로 시킬게. 마무리해'라고 결정했다. 추가 삭제 시도는 중단한다. 이미 변경한 환경만 원복하고 리팩토링 결과를 마무리하며, 시험 월드 삭제/Cloud 반영 확인은 별도 요청 때 수행할 할 일로 남긴다.

## 최종 병합 승인

검증판902721e와 남은 시험 월드 정리의 분리를 보고한 뒤 사용자가 '합쳐줘'로 ai-character 병합을 승인했다. 기존 로컬 자료를 보존한 fast-forward 병합, 설치본과 공식 개발·제품 지식그래프 반영 및 관련 확인을 수행한다. 원격 push는 요청하지 않았으므로 수행하지 않는다.
